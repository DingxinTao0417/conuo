# 流式资料问答

Web 阅读器支持在生成尚未结束时显示已完成的回答段落。界面沿用现有阅读与问答布局；生成中标注“尚未保存”，只有完整结果确认后才进入正式对话。未包含个人笔记证据的回答可另存为笔记或知识页草稿；包含这类证据的回答目前不直接另存，避免丢失来源边界。

模型需配置在服务端，见 [MODEL_SETUP.md](MODEL_SETUP.md)。未配置模型时继续显示明确标注的原文检索结果。此时没有模型生成，不模拟逐字输出。

完整 JSON、流式回答和视觉调用共用可选的 `CONUO_MODEL_THINKING_MODE=enabled|disabled`：空值省略，非法非空值在联网前拒绝。模式纳入请求指纹，改变模式后需要新请求身份，不复用旧模式的缓存。当前 DeepSeek flash 联调使用 `disabled`，避免默认思考输出耗尽 4096 token 预算；没有提高输出预算或自动重试模型，思考内容也不作为可读回答发送。

## 从模型到浏览器

1. 浏览器通过 `POST /api/v1/ask` 发起问题，携带当前账号、`Accept: text/event-stream`，以及最多 6 条、经长度限制的同会话既往**用户问题**。鉴权、请求格式、当前工作区和范围的初始错误仍使用正常 HTTP 错误响应。
2. 服务端从当前允许范围检索真实原文；检索查询以本次问题为主，并只在 4,000 字符上限内补充近期用户问题。它按既有请求 ID 和包含这段上下文的输入指纹预占账本，再向配置的 Chat Completions 接口发送 `stream: true` 请求。仅在 `document-notes` 范围中，服务端才会额外选择可验证的个人笔记块：它们必须属于本次问答空间、未删除、已接受、明确标记 `aiGenerated: false`，并且所有引用都指向当前一份资料的当前版本；不能由浏览器指定任意笔记。
3. 上游返回的文本仍是原有结构化回答 JSON。增量读取器识别完整段落，使用正式答案相同的结构校验、出处绑定、答案格式转换和量化自评检查。原始资料证据使用 `e` 标识，个人笔记证据使用 `n` 标识；原文结论只能引用 `e`，个人笔记结论只能引用 `n`，混合两类依据必须标为推断。未闭合的字符串、原始 JSON、未知证据标识，以及用数字、分数或百分比评价本回答可信度、正确率或把握度的段落，都不会作为可读段落发给浏览器。
4. 每个累计段落预览发送前，服务端重新核对账号、资料、资料版本、原始问答空间、笔记 revision/块及 AI 权限。客户端接到预览时也检查当前会话与准确证据；缓存返回走同一套复核。
5. 开启 `CONUO_FEATURE_ANSWER_VERIFY=on` 时，上游正常结束后服务端再用 `fast` 档位逐段检查原文结论与其引用的片段；不直接被片段支持的段落会标为“**推断（原文未直接支持，请核对）：**”。核验失败或 15 秒超时会保留未加标签的原回答，不影响成功终态；该阶段不增加新的 SSE 事件，标签只出现在最终 `complete` 内容中。
6. 服务端重新校验完整回答及引用，确认账本保存，再次核对当前上下文，最后发送 `complete`。客户端只有收到并验证终态才将回答加入对话，之后由现有本机与云端保存队列处理。个人笔记依据以独立快照保存，包含空间、资料、资料版本、笔记版本和块，不会被伪装成原文引用。

首个段落可以在后续段落尚未生成时出现。为了先绑定完整证据，界面按完整段落更新，不把尚无依据的半句话标成已核验答案。原始资料引用与个人笔记依据分开呈现：前者确认资料和片段真实、版本正确、权限有效；后者还确认原始问答空间、同资料当前版本及笔记块快照。两者都不能证明模型观点一定被充分支持。

创建或保存对话会增加工作区 CAS revision，但没有改变原始资料时，不应据此中止问答。问答专用的检索复核要求 RPC 行的 revision 单一一致、不旧于初始快照；若高于初始值，则重新鉴权并读取最新工作区，确认最新 revision 至少达到 RPC 所观察值，且账号、固定范围和问答上下文仍一致。旧、未来或混合 revision、资料版本／片段失效及权限变化仍拒绝；普通搜索的严格 revision 合同保持不变。语义索引不可用时的关键词回退也执行同一复核，不额外调用 embedding。

知识页的“基于原始依据提问”将其引用的原始资料固定为问答范围，并锁定当前资料版本。知识页正文不会发送或作为证据；这项入口不代表知识页自身已进入 AI RAG 索引。

## 连续追问边界

既往用户问题仅通过用户 JSON 的 `priorUserQuestions` 字段发送，用来识别“它”“为什么”“再举个例子”等指代。同一会话最近 2 条已完成的助手回答由服务端从已保存会话读取，通过 `priorAssistantAnswers` 作为已讲解内容进入模型；该字段和资料正文一样是不可信输入，不能覆盖系统规则、不能成为事实依据，也不能获得 `e` / `n` 引用编号。浏览器不会自动发送历史助手回答，服务端会在当前资料版本和本次范围内重新校验其原引用后才允许再次引用；未完成回答、未经重新校验的旧引用和个人笔记不进入连续追问上下文。每次请求仍重新检索当前范围，并在输出、缓存和终态前复核当前资料版本、空间和权限。

## 传输合同

SSE 使用 UTF-8，单个事件为 `data: <JSON>` 后接空行。浏览器通过 Fetch 读取 POST 响应，不启用自动重连。格式参考 [MDN 的事件流说明](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events#event_stream_format)。

| 事件       | 含义                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| `progress` | 查找原文、深入思考、生成段落或最后核验阶段；不含已保存回答                       |
| `draft`    | 累计完整段落及其准确原始资料引用与个人笔记证据，仅供本次生成预览                 |
| `complete` | 完整、校验通过且账本已确认的模型回答，或无需模型的原文检索结果；这是唯一成功终态 |
| `error`    | 安全的错误码、状态与提示；结束当前预览                                           |

未声明 SSE 的既有调用保留完整 JSON 响应。客户端也能读取完整 JSON 响应以兼容既有服务。缓存命中或原文检索可直接完成，不额外调用模型或人为延迟显示。

## 富文本与公式

设置服务端 `CONUO_FEATURE_RICH_ANSWERS=on` 后，问答请求指纹会包含 `format: "rich"`，模型段落允许安全 Markdown 子集：粗体、斜体、行内代码、代码块、有序／无序列表、GFM 表格、行内公式和独立公式。标题、链接、图片、HTML、引用块、分隔线、脚注及方括号数字不在子集内。服务端先用 Markdown AST 检查每个段落；发现禁止节点时把该段落退回转义纯文本，不让一次格式错误中断整个回答。

模型写出的 `$x$` 会在服务端改写成 `$$x$$`，阅读器用 KaTeX 渲染；阅读器关闭单美元公式解析，因此旧回答中的 `价格是 $5 和 $10` 仍按文字显示。正文中的 `[n]` 会改写为全角括号，代码和公式中的 `[n]` 保留，避免被引用解析器误识别。开关关闭时沿用原有纯文本提示词和 Markdown 转义；渲染端仅保留 `$$…$$` 的兼容解析。回答另存为笔记或知识页时仍会按既有纯文本编辑器转换，公式暂显示为 `$$…$$` 原文；移动端暂显示原文。

## 停止、错误与保存

- 点击停止、切换资料版本或账号变化会中止当前操作；过期回调不能继续更新预览。
- 用户主动停止时，如界面已经显示过带当前引用的完整段落，会将这些段落保留为“未完成、未核验”的对话记录，供回顾和继续提问；它不作为成功账本结果，也不能另存或追加到知识页。没有可保留段落时，或发生超时、结构错误、引用失效和非用户触发的中断时，预览清除，原问题和可操作的错误提示保留。
- 每条成功、失败或停止的助手记录都保存一次回答尝试：新的请求身份、对应的原问题身份，以及当时的范围、资料、版本、选段和有限连续追问上下文。选段、当前资料及“此资料 + 我的笔记”保存当前一份资料的准确版本；显式选择多份资料时，实际发送范围只包含当时已允许 AI 且正文可用的选中资料，并保存一一对应的资料版本。点击“重试此回答”会基于该快照建立**新的**请求身份，保留失败历史且不复制用户问题；任一资料缺失、移出原空间、关闭 AI、正文不再可用、版本变化，或旧快照缺少精确版本映射时，阅读器会在写入会话或调用模型前停止自动重试并要求重新确认范围。
- 实时 API 对普通“指定资料”请求要求 `sourceIds` 与 `sourceVersions` 一一对应；对选段、当前资料及“此资料 + 我的笔记”要求与 `sourceId` 匹配的一项版本锁。缺少或伪造映射的旧客户端或手写请求会在读取工作区和调用模型前以 `400 INVALID_QUESTION` 拒绝；首个云端快照已有不同版本时返回 `409 SOURCE_VERSION_CHANGED`。单资料生成过程中的后续变化继续使用既有 `QUESTION_CONTEXT_CHANGED` 语义。持久化的旧回答尝试仍按兼容 schema 读取和恢复，界面只禁止将其无版本快照自动重放，不会猜填后来版本。
- 资料被彻底删除后，相关尝试保留为历史记录并标记为不可重试；界面明确说明原因并保留“重新编辑问题”入口。备份恢复会重新分配尝试、问题、空间和资料身份，避免恢复副本沿用旧账号的请求账本。
- 只有有效 `complete` 才形成可保存的完整回答；不含个人笔记证据的完整回答才可另存为笔记或知识页。
- 模型若返回“本回答可信度 95%”“Confidence: 9/10”一类量化自评，本次生成以 `INVALID_MODEL_ANSWER` 失败，不发送 `complete`，也不保存为成功答案。合法引用仍先按真实范围校验，因此量化自评不能掩盖越界引用；资料中的实验准确率、置信区间等有出处统计事实不按回答自评处理。这个规则只检查明确的中英文量化自评语法，不代表系统能够自动识别所有夸大、幻觉或不充分推断。
- 服务端在每次输出前复核权限，尤其包括等待读取及保存账本之后。其他设备改变资料、资料版本、笔记块、问答空间或 AI 权限时，先前已经显示的段落无法从用户记忆中撤回；后续输出与最终保存会按最新检查结果处理。
- 客户端取消会关闭读取并传播至上游请求，账本清理失败时保留不可重复执行的记录，沿用既有超期处理。SSE 会先发送原始失败事件，非流式请求会先返回原始 HTTP 错误；两者都不会等待账本清理完成。清理仍最多保留 2 秒的后台机会。没有自动重试；不承诺供应商立即停止计算或不计费。

## 容量与执行边界

| 层级             | 当前限制                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| 单次上游模型请求 | 默认 45 秒；输入最多 256 KiB，输出预算 4096 token，返回文本最多 32,000 字符                               |
| 上游流           | 总体最多 2 MiB、8192 个数据事件；只接受单一回答，要求正常 `stop` 与 `[DONE]`                              |
| 下游 SSE         | 单事件最多 512 KiB，总体最多 16 MiB；一次等待一个事件，发送前重新检查上下文                               |
| 服务端流生命周期 | 普通请求自 POST 入口计时 55 秒；深度请求最多 280 秒，Route Handler 上限 300 秒；失败账本清理最多再等 2 秒 |
| 浏览器读取       | 总体最多 310 秒（包括等待 HTTP 响应头），读取闲置最多 60 秒；最多 4096 个数据事件                         |

客户端、服务端与上游都限制响应大小；不依赖对方声明的长度完成校验。超限明确失败，不截断文本并伪装完整答案。初始鉴权、请求体或工作区读取卡住时，入口超时/取消竞争会及时结束当前请求。现有 Supabase 在途查询本身无法强制终止，但其迟到结果不能推进到模型调用；失败账本清理也有最多 2 秒的等待限制。当前已有有限真实供应商联调，网络代理、Vercel 部署和更完整的超时／取消矩阵仍待核对，不能据此承诺模型质量或线上首段延迟。
