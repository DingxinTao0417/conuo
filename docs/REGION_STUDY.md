# PDF 区域视觉学习

Conuo Web 首版允许用户在 PDF 当前页框选一个固定矩形区域，把该区域作为一次明确的多模态学习请求。用户可以让 AI 解读区域、围绕区域提出自己的问题，或基于区域生成一次性练习。该能力面向公式、图表、插图和扫描页局部内容，不等同于 OCR、整页解析或整库图片索引。

已确认采用“截图直接交给多模态模型”的路线，不增加前置 OCR 步骤。解读、问答和出题都不要求资料已有可提取文字，也不要求模型先返回文字转写；图像本身就是本次请求的输入。首版入口限定为 PDF 当前页框选，尚不包含操作系统截屏或任意网页区域截取。

## 使用流程

1. 在 PDF 原页进入区域框选，拖动选择当前物理页中的一个矩形区域。
2. 页面缩放只改变显示尺寸；区域使用相对页面宽高的归一化坐标保存，范围为 `0..1`。
3. 用户确认框选后，浏览器在本机生成临时截图预览；用户再选择“解读区域”“针对区域提问”或“生成练习”。
4. 只有用户明确点击发送后，浏览器才把这张临时截图传给已配置的多模态模型。
5. 返回结果绑定确切的资料、资料版本、物理页和归一化矩形；版本变化后不能把旧结果静默套到新版本。

页面图像与文字层分别确认：当前页图像绘制完成后即可框选，不等待文字提取或文字层呈现。文字层失败时提示“文字选取暂不可用”，不把它描述为整页预览失败；残缺文字层不得提供选字／原文位置凭证。图像绘制失败或页面、版本、缩放及布局改变时，截图仍须等待当前画面完成，不能复用旧画面的就绪状态。

区域身份至少包含：

```text
sourceId + versionId + page + rect{x, y, width, height}
```

`page` 是 PDF 的物理页序号。`rect` 相对于该页，不能使用浏览器窗口像素或当前缩放值作为跨会话锚点。生成练习是当前区域的一次性结果，不表示完整的练习作答、掌握判断或回顾队列已经实现。

## 传输与保存边界

- 拖动、调整和预览区域都在浏览器内完成，不会自动调用模型。
- 框选发起身份和本机截图状态都绑定当前账号、资料与版本；切换账号、资料或版本，关闭 AI 权限，或工作区失去云端确认状态时会立即退出框选并丢弃截图。旧编码回调不能把像素交给新上下文或中断后来框选，切回原上下文也不会恢复旧截图。
- 截图只在用户明确点击发送时，为当前请求临时传输。截图字节默认不写入 IndexedDB、Supabase、Storage、资料正文、全文索引、备份或应用日志。
- 请求结果可以保留区域身份和文字结果，但默认不把截图本身持久化。若以后增加“保存截图”，需提供独立、明确的保存动作和删除规则。
- 解读按摘要及观察、分析、学习要点小节展示；正文、区域问答和练习支持 Markdown 段落、列表、强调、表格及 TeX 公式。HTML 不执行，链接只显示文案，模型返回的图片不加载；公式渲染禁止受信任 HTML／网络命令。可选文字转写保持纯文本。
- 请求仍受全局 AI 开关、资料 AI 使用许可、当前资料版本、账号权限、请求账本和额度限制保护。资料换版、禁用 AI、删除或请求取消时，结果发布前必须重新核对。
- `store: false` 是发送给兼容模型接口的请求字段，不代表供应商绝不记录请求。供应商的数据保留、训练使用、地区和计费边界仍以实际条款为准。

## 与 OCR 和检索的区别

区域视觉学习把一次截图交给多模态模型，并只回答当前请求。模型可以在结果中附带 `visibleText`，作为用户核对当前回答时的可选区域文字转写；该字段不是独立 OCR 任务，也不会写入 `Source.text` 或 `ParsedBlock`、生成整页 OCR，或建立可供普通搜索、语义检索和整库问答使用的全文索引。

因此，扫描 PDF 仍可保存和按原页查看，也可以对用户主动发送的局部区域做视觉解读；但扫描页正文仍不能通过普通文内搜索或资料库全文检索命中。覆盖整份扫描 PDF 的问题也不能因为一次局部视觉请求而被描述为已有完整资料依据。

## 模型配置

区域请求需要所选模型明确支持图像输入，并在服务端设置：

```dotenv
CONUO_MODEL_VISION_ENABLED=true
```

该变量只是部署者的显式能力声明，不会让文本模型自动获得视觉能力。按 DeepSeek 2026-09-14 的[图像理解文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)，当前 `deepseek-flash` 已原生支持 `image_url` 图片输入；更换模型或供应商后仍需重新核对实际能力，不能只凭开关推断兼容。

2026-09-14 已通过正式适配器完成真实 PNG 输入冒烟测试。2026-09-15 补齐现有 Supabase 服务端账本密钥后，使用真实登录账号及自编 PDF 图形，完成框选、预览、发送、模型生成、区域身份绑定和账本完成的解读／提问／出题三条交互链路，数学答案人工核对通过。结果仍为一次性面板内容，没有刷新恢复入口；账本缓存不是永久学习档案。记录见[云端验收](CLOUD_E2E_ACCEPTANCE.md)，完整配置见[模型服务配置](MODEL_SETUP.md)。

三种任务的解读、问题、答案与解析默认简体中文；用户在自己提交的问题中明确指定其他语言时才覆盖。截图中的语言或嵌入指令不能改变该规则，公式与必要术语可保留原样；可选 `visibleText` 保持截图原文语言。当前结构化输出规则纳入 `vision-region-v3` 请求指纹，旧合同缓存不能冒充新生成结果。该提示约束不保证每次模型输出都遵循要求，仍需真实核对。

## 结构化解读与排版

新生成的解读严格返回 `summary` 与 `sections`；每节含类型、单行标题和正文。至少包含图中观察与学习要点，分析推导按材料需要提供，不为非数学材料捏造计算过程。摘要最多 1200 字符，2—8 个小节，每节标题最多 120、正文最多 4000 字符，含标题的完整可复制内容仍受 16000 字符上限约束。

摘要以浅色概览区显示，小节分开展示。正文由 React Markdown 与 GFM 渲染，公式使用 `$...$`／`$$...$$` 分隔符及本地 KaTeX 样式／字体。长公式、代码和表格在内容区域内横向滚动，公式语法错误保留可读表达式，不中断整个结果。原始 JSON 不作为用户阅读内容显示。

服务端从摘要与小节生成统一 Markdown；公共结果核对该内容与结构一致，“复制”包含全部小节和公式原文。旧版只有 `content` 的结果仍可显示，但不推测或补造小节，也不会因更换展示方式自动重发模型请求。

## 首版验收边界

- 只能截取当前显示的 PDF 物理页，区域不能跨页。
- 正向或反向拖动得到同一归一化区域；超出页面的坐标会限制在页面内，过小区域不会发送。
- 截图与结果始终绑定发送时的 `sourceId`、`versionId`、`page` 和 `rect`。
- 未点击发送、模型未启用视觉、原件不可用、资料版本失效或权限复核失败时，不得上传截图。
- 应分别用文本 PDF、扫描 PDF、公式、图表和高缩放页面核对；模型解释质量需人工检查，不能只验证接口返回成功。
