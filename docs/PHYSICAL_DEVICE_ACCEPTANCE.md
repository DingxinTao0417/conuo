# Conuo 物理双设备验收

更新日期：2026-09-20。本文用于独立 staging 的两台物理设备验收，不授权生产变更。自动化 Chrome／Edge 结果只能作为前置证据；本页要求设备、浏览器进程、网络生命周期和系统时钟相互独立。

## 前置条件

1. 两台设备均打开 `https://conuo-staging.vercel.app`，并使用同一个可丢弃 QA 账号登录。不要使用生产账号或用户真实资料。
2. 一台使用桌面 Chrome 或 Edge；另一台优先使用 iPhone／iPad Safari 或 Android Chrome。记录设备类型、系统版本、浏览器版本和网络类型，不记录账号、Cookie 或 token。
3. 访问 `/api/health`，记录完整 Git SHA；必须为 `branch=staging`。测试期间 SHA 变化时，本轮作废并从共同基线重新开始。
4. 等待两端都显示“已保存到云端”。长文本阅读使用现有自编资料 `qa-reading-position-conflict`；笔记冲突使用明确标记为 QA 的测试笔记。
5. 每个场景开始前记录云端 revision，结束后用全新页面复核权威终态。失败时先保留当前页面，不反复点击保存。

## 验收矩阵

| 场景           | 操作                                                                                                                 | 必须满足的结果                                                                                                                          |
| -------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 前台同步与延迟 | 设备 A 修改 QA 学习空间目标并等到云端确认；设备 B 保持前台可见。反向再做一次                                         | B 自动采用或明确提示新版本；内容一致。分别记录服务端确认到另一端显示的耗时，至少 10 个往返样本，用于计算 P50／P95                       |
| 同时保存       | 两端从同一文本基线开始，在倒计时后同时改学习目标并离开输入框                                                         | 只有一个版本直接保存；另一端快速进入冲突或重新连接后的权威复核。不得挂起几十秒、静默覆盖或自动重复提交                                  |
| 保存时断网     | 设备 B 开启飞行模式或关闭实际网络后编辑，确认页面显示未保存状态；设备 A 在线保存另一项修改；B 恢复网络并点击重新连接 | B 的当前输入在页面内保留；独立修改可安全重基，同一对象进入明确冲突。刷新后只出现已确认云端状态，不存在隐式离线副本                      |
| 提交后响应未知 | 设备 A 点击保存后立即切断实际网络，使请求可能已到达服务器；恢复网络后点击重新连接                                    | 客户端先权威回读；远端已精确提交时确认成功，未提交时才允许重新保存。revision 只推进一次，不生成重复对象                                 |
| 删除防复活     | 设备 B 离线打开 QA 资料详情并修改标题；设备 A 在线把同一资料移入回收站；B 恢复网络                                   | 删除状态胜出，资料不回到有效资料库、搜索或 AI 范围。B 的文字只保留在明确恢复/导出路径，不移除 tombstone                                 |
| 阅读位置冲突   | 两端打开 `qa-reading-position-conflict` 的同一版本，从相同位置开始，分别滚动到明显不同段落并等待保存                 | 失败端出现“选择阅读位置”；选择任一位置后云端保存，落选位置出现在“已保留阅读位置”。切换后原当前位置也保留，刷新位置一致                  |
| 笔记冲突       | 两端打开同一 QA 笔记，从共同正文开始分别输入不同段落并同时保存；在失败端选择手工合并                                 | 合并正文包含双方修改；两份冲突正文均进入历史。刷新和第三个新会话读取相同终态，撤销操作不能复活已放弃正文                                |
| 后台与账号边界 | 一端保持登录，另一端退出；随后对专用可丢弃账号执行注销验收                                                           | 普通本地退出不影响另一端；账号注销后另一端下一次身份/工作区请求被封锁，不能继续保存或恢复旧工作区。账号注销只在已准备清理的专用账号执行 |

## 记录格式

每个场景记录以下非敏感字段：

- UTC 开始／结束时间、完整 Git SHA、场景名称。
- 设备代号、操作系统、浏览器和网络类型。
- 起始／结束 revision、各请求状态码和用户可见结果。
- 是否出现静默覆盖、重复对象、长时间挂起、资料复活或跨账号内容。
- 失败时保留错误分类和页面提示；不得保存邮箱、密码、Cookie、token、完整 Storage 路径或用户正文。

## 通过与清理

全部场景必须使用已部署页面完成，不能用 API 会话或设备模拟器替代。409 属于预期冲突结果；未处理的 5xx、超过 10 秒仍无终态、静默覆盖、跨账号可见、删除复活或刷新后数据丢失均判定失败。

完成后恢复 QA 学习目标和测试笔记；阅读位置长 TXT 保留到生产候选冻结，供回归复用。软删除资料按场景需要恢复；需要彻底删除或注销账号时进入现有清理队列，不手工删除数据库行或 Storage 对象。结果回填到 [Staging 部署与验收](STAGING_DEPLOYMENT.md)和[生产发布手册](PRODUCTION_RELEASE.md)。
