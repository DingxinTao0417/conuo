# 批注原文位置

更新日期：2026-09-14。本文记录 P21 的 Web 批注位置合同。新建高亮和批注保存可核验的原文位置，重复句子可以分别标注，并在重新挂载阅读器后定位到各自原文。完整检查、响应式浏览器回归和本地迁移验证已通过，结果见[开发状态](IMPLEMENTATION_STATUS.md)；此处不代表真实云端或跨设备验收。

## 保存合同

`Annotation` 新增可选 `textAnchor: { start, end }`，与 `sourceId`、`versionId`、`quote` 一起确定原文身份。位置使用 JavaScript 字符串的 UTF-16 单位，是对应保留版本 `Source.text` 的半开范围，既不是 Unicode 字符数量，也不是页面像素坐标。

```ts
const text = "😀目标\n目标";
const textAnchor = { start: 5, end: 7 };
text.slice(textAnchor.start, textAnchor.end) === "目标";
```

这个范围指向第二处“目标”；前面的 emoji 占两个 UTF-16 单位。存在锚点时必须满足：

- `start`、`end` 为安全整数，`0 <= start < end <= text.length`，对象仅含这两个字段。
- 首尾不能切开同一个 emoji 等字符的代理对。
- `text.slice(start, end) === Annotation.quote`，原话不得通过去空格、替换换行或 Unicode 归一化后冒充准确切片。
- 当前版本或保留历史版本必须能唯一确定；工作区校验也核对回收站中仍保留的资料正文。

锚定原话保存时保留切片中的空白、CRLF 和 Markdown 格式；用户批注正文继续使用原有长度和格式规则。编辑只改变用户批注文字，删除和离线重基核对锚点是否仍为同一身份。不能给旧批注原地补上猜测的位置，也不能把批注改绑到另一处相同句子。

## 从原生选区到原文

选区首尾必须属于当前 source/version 的阅读正文。阅读器核对实际 DOM 的非空白文字与该范围的原文显示投影，再用原生 `Range` 前缀确定用户选中了第几处文字；仅在首尾和内容均能证明时保存连续原文切片。

| 正文类型 | 位置依据与边界                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------- |
| Markdown | 沿用 AST 的原始范围、显示投影和正文 DOM 身份；粗体等格式不会靠删除符号猜测位置，未知结构与实体切点保守拒绝     |
| 网页     | 对保留的 Markdown 正文使用同一合同，位置属于已保存快照，不是远端网页的任意 DOM                                 |
| TXT      | 核对解析正文 DOM 与 `Source.text`；相同段落按实际选区偏移区分                                                  |
| DOCX     | 核对软件中显示的解析正文，不保存 Word 版式坐标或推测原文件单元格位置                                           |
| PDF      | 核对实际文本层及保留的有序页块范围；页码、完整页文字和 source/version 必须相符，不能取第一条相似片段证明页身份 |

PDF 的 `renderedFrame` 在画布和文本层提交完成后记录 source/version、归一后的实际页码、缩放和布局宽度。只有这份帧仍与当前显示一致时，文本层才提供可信正文身份；正在换页、缩放或调整宽度时，旧文本层不能生成新批注位置。`textAnchor` 始终是解析正文位置，`page` 是页身份，二者都不是 zoom 下的屏幕坐标。

DOM 被改动、正文版本变化、页范围不能证明、显示与原文不一致或选区切开原子字符时，阅读器不会选择另一个相似位置来替代。高亮入口会提示重新选段或切到解析文本核对。没有文本层的扫描页也不能凭图片文字创建原文锚点；直接截图交给多模态模型的学习路线见[区域视觉学习](REGION_STUDY.md)。

## 高亮与点击定位

保存后的锚点重新映射到当前可证明的 DOM 范围。点击“我的标注”使用独立的批注 focus 和点击序号，不构造一条带位置字段的引用；滚走后再次点击同一批注也会重新定位。PDF 批注同时检查锚点属于记录的页范围，不允许把第一页的相同原话套到第二页。

引用合同保持：`Citation.quote` 仍是对应完整 `chunk.text`，source/version/chunk 身份继续核验，没有新增批注 offset 字段。批注位置准确不扩大普通引用点击在未知排版或重复文字中的定位保证。

旧无锚点批注继续读取和保留人工文字，不自动猜位置。只有原话在当前可证明原文范围内唯一时才尝试兼容定位；PDF 有页记录时以对应保留页范围为准。重复、缺失或 DOM 无法核对时保留批注并明确提示无法准确定位，不回退到第一处。历史阅读仍禁止新建、编辑和删除批注。

## 恢复、离线与备份

资料删除与离线批注编辑冲突生成的可恢复草稿保留锚点。草稿与原批注的原话、版本及位置必须一致；恢复资料、另存笔记或丢弃草稿前重新核对，不能让内容已变化的记录执行旧动作。离线重基也拒绝同一个版本 ID 下已变化的原文切片。

ZIP 恢复创建新的资料和版本身份时保留原始正文、原话与锚点数值，重新绑定身份后仍按同一切片核验。旧无锚点记录保持兼容，不在恢复过程中为重复原话生成位置。
