# 分层摘要

Conuo 的全书摘要按当前资料版本生成。执行器先按 PDF 书签或导入目录切分章节；没有可用目录时按正文顺序使用不超过 12,000 字符的窗口，再把过多章节合并到 60 章以内。章节摘要完成后，执行器用每章摘要和每章最多两段代表性原文生成全书摘要。

摘要写入 `source_version_summaries`，与资料版本绑定。资料版本被删除时，摘要通过外键级联删除；资料当前版本、AI 许可、工作区 AI 开关或账号状态改变时，租约写入会再次检查资格并停止旧任务。后台每个账号的章节调用受 `CONUO_SUMMARY_DAILY_SECTION_LIMIT` 限制，默认 60，允许范围为 1–500。

摘要是导航提示，不是证据。问答可以把章节摘要放进 `sectionSummaries` 帮助模型理解结构，但回答的 `e` 引用只绑定 `source_chunks` 的原文。全书问题最多使用 24 段原文，章节问题只使用该章节摘要所引用的切块并在有页码边界时补充章节内切块；摘要不存在时回到普通检索路径。

摘要处理器使用与 Embedding 相同的处理器鉴权和租约方式。`supabase/operations/staging-summary-cron.sql` 只用于部署评审，本地开发和默认测试不会访问外部模型或远程数据库。
