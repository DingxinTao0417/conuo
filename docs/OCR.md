# 扫描件 OCR

WP-20 为 PDF 阅读器提供浏览器驱动的逐页 OCR。PDF.js 在浏览器中渲染用户选择的页面，页面图片经 `/api/v1/vision/transcribe-page` 发送给视觉模型；服务端只在本次请求中校验图片、调用 `vision` 档位并返回 Markdown，不保存页面图片或识别结果。

## 识别边界

- 只允许当前用户、当前空间、当前 PDF 的当前版本；全局 AI 或资料级 AI 关闭时拒绝请求。
- 图片使用现有视觉图片校验：PNG、JPEG 或 WebP，解码后不超过 2 MiB，并限制尺寸与像素数。浏览器长边最多 1600 像素，超过限制会降低一次分辨率。
- 每个请求一次识别一页，浏览器并发为 1。`CONUO_OCR_DAILY_PAGE_LIMIT` 限制账号每日页数，默认 100，允许范围 1–2000；额度按 UTC 日期通过 `reserve_ocr_pages` 原子预占，重复 request ID 不重复扣除。
- 模型合同版本为 `ocr-vlm-v1`。结果必须是最多 20,000 字符的严格 JSON Markdown；服务端不接受模型返回的额外字段。

## 保存与版本

用户在浏览器预览并确认后，OCR 页面文本与原有可用页面文本组装为新的派生版本。原文件字节和旧版本保留不变；新版本的 `derivation` 为 `{ method: "ocr-vlm-v1", fromVersionId }`，内容哈希与原 PDF 相同。解析状态、页覆盖率和切块在保存前重新计算。

停止、取消或未确认时不保存派生版本。无法自动确定的页面范围可以手动输入页码；识别失败的页面不会被静默替换。

## 验证范围

本地测试覆盖图片与模型结果合同、路由鉴权和额度隔离、SQL 迁移、派生版本 CAS、页面组装及浏览器流程。真实视觉模型、真实 PDF 浏览器验收、staging 开关、远程迁移和部署仍按进度表人工事项处理。
