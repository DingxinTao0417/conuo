# Conuo 搜索与语义索引

更新日期：2026-09-15。本文记录已实现的 Web、数据库与 Python 索引链路。代码已进行本地验证；真实召回质量、Embeddings 供应商和云端调度仍待联调，完整 M0 仍未验收。

## 搜索入口与范围

资料库工具栏提供“关键词”和“用问题找资料”两个入口，共用类型、标签及时间筛选。“关键词”区分资料、笔记和知识页；“用问题找资料”只列出可核对的当前版本原文片段，并允许选择最多 5 份资料进入既有跨库问答。进入问答只预填问题与资料范围，不自动发送、不提前创建对话。

每个对象显示一个最佳命中块；结果保留对象类型、版本或正文 revision，打开前重新核对当前内容，不用旧结果替换已编辑的正文。问题检索的资料即使暂不允许 AI 使用也仍可阅读，但选择框会明确禁用并显示原因。进入问答前和实际发送时都会再次检查删除状态、当前版本、资料级 AI 许可、正文就绪状态与可用知识库归属。

登录且当前工作区已确认云端保存后，可使用云端搜索按钮调用 `POST /api/v1/search`。普通搜索读取规范化资料索引，并在账号工作区中检索笔记和知识页；后两者尚未拆分为独立数据库索引表。本机搜索不需要云端或模型配置。

普通搜索的单一类型下拉包含 PDF、DOCX、Markdown、TXT、网页、笔记和知识页。可以先选择笔记或知识页再输入关键词；关键词为空时浏览当前范围内该类型的已保存内容，清空关键词不重置类型。空关键词不会调用云端搜索接口。类型、最近 7 天／30 天／一年、关键词和范围写入资料库 URL；从搜索命中的笔记或知识页返回时保留这些条件。切换“用问题找资料”会明确重置不适用的笔记／知识页类型；浏览器前进后退恢复该类型时回到普通搜索。

| 模式           | 内容与权限                                                                                            | 范围与限制                                                                                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 普通关键词搜索 | 当前资料标题、标签、正文，以及笔记和已接受知识页；不要求 AI 开关开启                                  | 指定库、收件箱或显式全库；草稿默认排除，底层契约另支持显式包含草稿                                                                                              |
| 用问题找资料   | 本机确定性关键词基线返回原始资料片段；可选云端语义匹配只替换候选，不生成回答                          | 共用当前资料库筛选；检索结果与 AI 回答分开标注，只能选择当前版本且满足问答条件的 1–5 份资料，随后由跨库问答再次锁定范围                                         |
| 语义搜索       | 仅当前资料；需全局 AI、`semanticSearch` 和资料 `aiAllowed` 均允许，且存在匹配配置的已发布当前版本索引 | Web 入口要求选择具体知识库或收件箱；不把笔记、知识页或关系作为向量证据                                                                                          |
| 新问答         | 仅当前授权的原始资料；服务器绑定真实片段、版本和定位                                                  | 选段、资料、资料集合或空间；跨库入口只在全部资料库显式开启，要求选择 1–5 份可用资料，使用关键词检索且不启用任意全库语义范围；历史资料可阅读核对，不能用于新问答 |

收件箱只包含没有知识库归属的资料。指定库必须存在且未归档；普通“全库”可管理归档库中的未删除资料，AI 检索和索引则排除只有归档库归属的资料。软删除立即影响新的检索与索引发布。类型、标签和日期条件在数据库候选数量限制前确定允许的资料 ID，返回后再次核对，避免先取全库前若干项再由客户端筛掉越界结果。

日期契约使用 ISO 时间，起点包含、终点不包含；每个对象按自己的创建时间判断，笔记与知识页不继承所引用资料的日期。最近时间窗口在选择条件时固定，不因提示或保存状态刷新而重新计算、作废正在返回的云端结果。标签筛选要求所选标签全部匹配；笔记与知识页目前没有资料标签或收藏属性，标签、收藏和旧 `sourceKinds` 条件仅匹配资料。公共 `filters.starred` 对资料进行精确 true／false 匹配，服务端在 RPC 候选截断前筛选，避免非收藏资料遮挡低排名收藏。云端候选只代表当前返回窗口，不宣称全库精确总数。

## 关键词、混合检索与问答

数据库关键词检索使用 PostgreSQL `simple` 全文索引、精确短语，以及英文有效词和中文相邻双字匹配。中文双字是可解释的召回启发式，并非完整中文分词；真实中英文问题集的召回和排序质量仍需评估。英文问题按内容词 OR 召回，过滤常见问句词；中文问题如“学习率过高会怎样”可以命中正文中的“学习率”。

单个 PostgreSQL `tsvector` 有容量限制，因此派生全文索引只处理块前 100,000 个字符；关键词兜底仍检查完整原文，规范化正文没有截断。普通检索先为每份资料选择最佳块，再应用候选上限，避免一份长资料占满整个窗口。AI 检索允许同一资料的多个块，返回结果仍受范围与上下文容量约束。

显式语义搜索先检查当前范围是否存在已发布且配置指纹匹配的索引，再预占查询字符额度、生成查询向量，并通过 pgvector 余弦检索取得候选。关键词与向量排名使用 RRF 合并，不直接相加两种不同含义的原始分数。未就绪或配置不匹配时明确提示，不产生模拟向量。

“用问题找资料”始终先显示本机关键词结果，并明确标为“未生成回答”。云端语义检索尚未执行、正在请求或失败时，本机候选继续可见，错误不会被伪装成语义结果；云端成功后才改为“云端关键词与语义检索”。全库范围不伪造任意语义范围，用户仍可用本机结果选定具体资料。

云端问答已读取真实 `search_source_chunks` 候选。开启语义能力且当前版本、配置与已发布索引匹配时可使用混合召回；尚未就绪时保留关键词路径。总结类请求继续按服务端原文轮询采样构建上下文，不把高相关性片段误当成全文覆盖。回答输出前仍核对账号、范围、资料版本、AI 权限和原文引用；没有生成模型时返回标记为 `extractive` 的原文摘录。正式问答支持真实分段传输、临时预览与完整结果确认，见[流式问答](STREAMING_ANSWERS.md)；搜索列表本身不生成回答。

普通“全库”资料页不会自动成为 AI 范围。用户可以直接开启“跨库问 AI”，也可以先用问题找到并勾选资料；两条路径最终都进入同一个 1–5 份资料选择面板。问题和选择只作为一次性内存草稿预填，刷新不会自动恢复或发送。首次发送后才锁定 source/version 集合并创建会话；云端以该固定集合做关键词候选检索，不运行跨全部资料的语义搜索。每次请求、输出与终态写入前均重新核对资料、版本、AI 许可与可用学习空间，任何一份不满足即整体拒绝。

### DOCX 基础表格证据

新导入和文件替换预览中的 DOCX 使用 Mammoth 的原始文字提取及受限结构解析。结构与原文顺序能够准确对应的基础矩形表格，按完整行组成有界证据块；每块最多 1200 个字符，以 JavaScript 字符串长度计。长表分为多个行块，不把整张表无限扩成一个片段。块文字直接取保留原文中的连续范围，多段单元格也保留真实段落分隔，不把表头或其他行拼接进引用。

例如表格包含“参数／值”“学习率／0.001”“批量大小／64”时，检索“学习率是多少？”可取得同时包含“学习率”和“0.001”的原文块，避免只召回孤立的参数名称。每块定位元数据保留章节、表格序号、实际行范围、列数及有界的首行各列文字。首行文字按实际列顺序提供，过长内容明确截短；它不是推断出来的表头，也不宣称首行一定是列名称。后部行块仍携带这份列上下文，但单块不代表已经读取完整长表。

合并、嵌套、不规则或空单元格、超过单块容量的完整行，以及结构与原文位置无法可靠对应的表格，不生成声称完整行列关系的块。解析保留普通原文片段并标为 `partial`，说明相应表格的行列关系暂不保证；结构解析失败时也保留已提取文字并提示限制。这些情况不能当作“资料中没有答案”，也不能凭转换结果猜测原文位置。引用仍绑定真实 source/version/chunk，块文字必须属于保留原文。

已有当前版、历史版和备份中的片段不会因应用升级、搜索或重建向量索引而静默重新切块。重新解析入口仅适用于失败或已取消且原件可用的当前导入任务，沿用该任务的 source/version 身份；已完成任务即使资料为 `partial`，也没有通用重解析入口。已完成旧资料若需使用新规则，可明确导入为独立资料，或选择实际字节发生变化的文件保存成新版本；当前同 SHA-256 原件通常不能通过换版重复保存。文件版本与原件缺失例外见[文件版本记录](FILE_VERSIONS.md)。

## 数据库迁移与版本保护

迁移的权威目录为 `supabase/migrations/`。在独立开发环境备份后，按以下顺序应用：

1. `202609120001_workspace_foundation.sql`：工作区、revision 保存协议与私有原件桶。
2. `202609120002_ai_requests.sql`：生成式问答及整理的请求账本。
3. `202609120003_source_retrieval.sql`：规范化资料、保留版本、内容块、pgvector、索引任务和字符预算。
4. `202609120004_source_purge.sql`：资料彻底删除、tombstone 和 Storage cleanup outbox。
5. `202609120005_source_purge_cleanup.sql`：outbox 的 service-role 租约、心跳、退避和完成确认。
6. `202609120006_account_deletion.sql`：账号注销的 Storage/Auth 两阶段 outbox、访问封锁和迟到对象重开。
7. `202609120007_account_deletion_embedding_fence.sql`：注销时取消向量任务、清空模型结果，并封锁迟到的模型/向量任务写入。
8. `202609130001_document_notes_evidence.sql`：资料彻底删除时保留 document-notes 个人笔记证据的历史快照，移除原资料引用，并阻止它作为新的单资料提问范围。
9. `202609130002_answer_attempts.sql`：保留问答尝试的范围快照；资料彻底删除后将受影响尝试标记为 `source-purged`，防止自动重试已删除资料。
10. `202609130003_manual_excerpt_references.sql`：资料彻底删除时，从当前及历史笔记移除手工摘录引用中的资料标识。
11. `20260914000500_source_version_purge.sql`：清理单个历史版本的服务端影响预览、CAS 事务和复用的 Storage cleanup outbox；笔记/对话保留不可替代的历史引用，手工内容与进行中任务会阻止操作。
12. `20260914000600_fix_project_workspace_space_alias.sql`：修复资料库投影读取 JSON 数组元素时的值列访问。
13. `20260914000700_fix_project_workspace_space_alias_scope.sql`：为两个资料库 JSON 数组结果集显式声明 `sp(value)`，避免历史部署定义遗漏聚合子查询别名。

003 使用 `extensions` schema 下的 `vector` 扩展。托管 Supabase 的 `storage.objects` 属于平台角色 `supabase_storage_admin`，且 RLS 由平台启用；006 只维护其 Storage policy，不能对平台表执行 `ALTER TABLE` 或改动所有者。账号注销的 restrictive policy 仍会与其余 Storage policy 共同执行，保持对象访问封锁。应用前核对已有扩展和同名业务对象；不要重写已经应用的迁移，或把开发夹具写入真实用户数据库。每个迁移有自己的事务，失败会回滚本次新增对象、回填和函数替换，保留此前迁移及原有快照。旧数据不符合身份或原件路径约束时明确失败，不能通过跳过记录或复制当前正文掩盖历史问题。仓库没有破坏性降级脚本；已成功升级后的回退需要备份和单独评审的前向修复或恢复方案。

| 表                         | 责任                                                                    |
| -------------------------- | ----------------------------------------------------------------------- |
| `sources`                  | 可变资料身份：标题、标签、空间、AI 权限、删除状态和当前版本             |
| `source_versions`          | 每版正文与原件元数据的不可变 manifest、独立 digest 和保留状态           |
| `source_chunks`            | 精确绑定 owner／source／version／chunk 的原文、定位、顺序和文本 SHA-256 |
| `embedding_profiles`       | 当前 `embedding-v1` 的维度与首次绑定的配置指纹                          |
| `embedding_jobs`           | 持久待执行记录、租约、检查点、尝试次数、取消和发布状态                  |
| `chunk_embeddings`         | 按任务 generation 暂存的向量；发布前不参与语义检索                      |
| `embedding_usage`          | 按账号与 UTC 日预占的字符用量                                           |
| `account_deletions`        | 不依赖 Auth 外键的账号注销审计、Storage/Auth 阶段和租约状态             |
| `account_deletion_objects` | 账号首层 Storage 路径的服务端清理 outbox、退避和完成确认                |

`save_workspace(p_data, p_expected_revision)` 签名不变。它在一次数据库事务中比较 revision、保存兼容快照、同步资料及全部保留版本/块，并按权限创建或撤销索引任务。失败不会留下“快照成功、资料投影失败”的半次更新。迁移也会用同一规则回填已有工作区。

资料、版本、片段和库 ID 使用兼容旧数据的文本标识；只有账号 owner 是 Auth UUID。正文 digest 独立计算，不把旧资料的空 hash 或非 SHA 字符串当作安全证明。标题、标签、归属和阅读进度可更新；同一版本正文及定位不能覆盖。原件路径按 `owner/version/source.扩展名` 核对，允许从缺失补齐准确路径，不允许换绑已有路径。所有保留历史版都检查身份与路径，缺失历史不回退到当前正文。

快照中不再保留的资料/版本会标为 `retained=false`，不会自动成为当前可检索内容；此标记不是永久删除。资料与块虽然已规范化，客户端同步仍受 **3 MiB 工作区快照**限制。笔记、关系等结构的完全规范化、孤立内容清理和最终生命周期仍需后续实现。

## 语义模型与配置指纹

语义功能默认关闭。启用后，仅同时满足全局 AI、资料许可、当前版本可用及归属条件的资料才产生持久索引任务。服务没有默认供应商、默认模型或假向量；必须明确选择原生输出 **1536 维浮点向量**的模型。

在 Next.js 服务端配置：

```dotenv
CONUO_EMBEDDING_BASE_URL=
CONUO_EMBEDDING_API_KEY=
CONUO_EMBEDDING_MODEL=
CONUO_EMBEDDING_DAILY_CHAR_LIMIT=200000
CONUO_PROCESSOR_SECRET=
```

仍需 Supabase 公开连接配置和服务端 `SUPABASE_SECRET_KEY`，旧项目可二选一使用 `SUPABASE_SERVICE_ROLE_KEY`。所有 Embeddings、处理器秘密与 Supabase 特权密钥均不能使用 `NEXT_PUBLIC_` 前缀。公开示例见 [Web 环境变量](../apps/web/.env.example)，完整基础配置见 [CLOUD_SETUP.md](CLOUD_SETUP.md)。

配置指纹是规范化 Base URL、模型名和维度构成的 `SHA256(JSON.stringify(['embedding-v1', baseUrl, model, 1536]))`，不包含密钥。第一次领取任务会固定 `embedding-v1` 的指纹；此后不同配置无法继续领取或查询同一 profile。更换 API 密钥不会改变指纹；更换模型或地址需要迁移、重建并切换索引，不能只修改环境变量或清空指纹来混用向量空间。当前没有自助迁移模型的 UI。

Next.js 在向 worker 返回正文或生成查询向量前，调用 `reserve_embedding_usage` 预占字符额度。默认每账号每 UTC 日 200,000 个 Unicode 字符；失败也消耗预占，重复请求 ID 不允许再次实际调用。字符预算是输入准入限制，**不是货币费用上限**，也不保证崩溃或网络中断时供应商只计费一次。生成式问答的每日次数账本与此预算独立。

## 任务执行、取消与重试

`embedding_jobs` 同时作为持久 outbox 和可领取队列。本轮没有外部队列投递或云唤醒；已有 Python 3.12 处理器由操作者显式运行：

```sh
cd apps/processor
python -m conuo_processor --max-jobs 5 --max-seconds 40
```

它不自动读取 `.env`，运行前由环境注入配置，详见 [Processor README](../apps/processor/README.md)。默认最多 5 项、40 秒，参数只能调低；每次领取 1 项，租约 120 秒，每批最多读取 16 块。没有常驻循环、自动等待或隐式 HTTP 重试，也不持有 Supabase 服务角色密钥。

| 接口                          | 授权与行为                                                                        |
| ----------------------------- | --------------------------------------------------------------------------------- |
| `POST /api/v1/search`         | 用户会话、账号绑定与范围检查；关键词或显式语义搜索                                |
| `GET /api/v1/indexing`        | 当前账号各资料当前版本的 `embedding-v1` 任务状态、检查点和服务配置状态            |
| `POST /api/v1/indexing`       | 当前账号任务的 `cancel`／`retry`，不能控制其他账号任务                            |
| `POST /api/internal/indexing` | 独立 Bearer 服务秘密和配置指纹；仅 `claim/read/commit/finish/heartbeat/fail` 动作 |

规范化表和预算表不向浏览器或 worker 开放直接读写。用户检索/控制 RPC 使用账号身份；任务执行及预算 RPC 仅 service role 可调用，Next.js 内部入口代为调用。名称包含 `internal` 本身不提供保护，实际依赖验证过的秘密、动作 schema、请求大小、租约与配置指纹。

状态查询只返回仍保留资料的当前版本任务，每份资料最多一项，与当前最多 5000 份资料的边界一致。历史任务留在数据库中，不混入状态面板；当前快照大小不能限制多年累积的历史任务数量。历史任务的清理属于后续生命周期工作。

领取任务按 owner 锁序与行锁进行，过期租约会换发新 token。分批提交必须匹配真实 chunk ID、内容 hash、1536 维向量和连续 cursor；原文 `ordinal` 允许不连续。相同已提交批次可幂等确认，不同内容重放被拒绝。全部块提交后，再复核当前资料、版本、权限及取消状态，才能将整个 generation 原子标为 `succeeded` 并开放检索。保存新版本或撤销许可会使旧发布结果立即失效。

失败状态由数据库记录退避和下一次尝试时间，最多 5 次领取尝试；Python 不在本次进程中等待重试时间。后续显式运行处理器才能重新领取到期任务。用户取消不会被无关保存自动复活；显式重试会创建新 generation、清空旧检查点和暂存向量。权限恢复可重新排队符合条件的任务，但不会直接把未完成结果发布为可用。

处理器只向量化已经存在的切块，PDF/DOCX/OCR 等解析仍在浏览器。数据库任务能跨页面关闭持久保存，**不代表页面关闭后会自行运行**。可靠后台执行仍需要单独部署、受保护的调度/唤醒、跨机器并发及失败恢复验收。浏览器自动资料整理队列与这些向量任务是两条独立链路，前者仍受工作台页面生命周期限制。

账号注销记录创建后，`embedding_eligible` 会立即变为 false；已排队或租约中的任务会取消，已发布向量撤回，`read_embedding_batch`、提交、心跳和完成操作都无法通过账号访问栅栏。模型请求与向量字符预约也会拒绝，模型结果只能经 `finish_ai_request` 写入并在写入前复核同一栅栏。已经发送到外部模型供应商的调用无法被数据库撤回，但结果不会重新写回或向用户发布。账号清理执行器与真实云端验证见 [云端配置](CLOUD_SETUP.md)。
