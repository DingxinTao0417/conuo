## 数据与身份

- Web Cookie 路径保留；新增明确的原生 Bearer 路径。服务端验证 token 与请求账号，RLS 查询使用同一身份；无效显式 Authorization 不回退 Cookie。响应保持私有、不可缓存，并区分 Cookie/Authorization。
- 移动端配置只接收 HTTPS 根地址及公开 Supabase 配置。浏览器构建仅为示例预览，不做真实认证、不调用模型或保存云端，也没有为演示放开 CORS。
- 原生认证凭据分块写入 Keychain。退出先建立持久封锁，旧凭据清理失败也不能重新接受旧会话；只有新的成功登录及服务端身份验证才能解封。
- 业务内容与未保存草稿留在进程内存；会话退出不保留资料副本。暂时网络故障保留当前页面和草稿，明确失效或账号封锁停止访问。认证中断后的本人输入恢复与主动退出的清理规则，见本页后续增量；封存容器不是本地资料库或离线工作区。
- 新建笔记与网页资料保留 Web 侧未编辑字段，使用 revision CAS。响应未知先按固定笔记或资料／版本身份核对云端，失败不静默覆盖；迟到刷新不能回退已确认 revision。网页正文用于 AI 需显式授权；仅收藏链接不建立正文索引。
- 问答绑定当前资料版本和许可；身份、资料版本或范围失效时清除旧结果与引用弹层。引用只对可唯一匹配且不重叠的原文片段提供定位。

移动认证恢复已实际接入 `App.tsx`、`DraftRecoveryGate` 和 `WebImportSheet`，不是未使用的独立方案。`draft-recovery.ts` 只在进程内保留账号／generation 绑定的用户输入、创建身份和确定性保存摘要；不持久化，也不保留旧工作区、服务器正文、自动提取标题、答案、引用或凭据。流程为：

1. 401 或非主动 `SIGNED_OUT` 封存白名单输入并关闭旧工作区；主动退出、423、已在线确认的不同账号立即清空。另一账号验证成功后，即使会话封锁解除失败，也不再保留旧账号输入。
2. 新登录之后显示恢复提示；只有用户选择恢复，才依次检查当前会话封锁、线上 `getUser` 和实际工作区 GET。每个异步阶段复核身份及 generation，晚到结果不能打开旧账号或重建已放弃草稿。
3. 新建笔记保留用户文字和原创建 ID；保存未知先读回核对，一致才确认，不同／已删不覆盖或复活。网页仅保留摘要收据，未找到时由用户重新预览、重新授权 AI；沿用 source ID、使用新 version ID，并保留有限历史收据辨认迟到提交，继续使用最新 revision CAS。
4. 未发送和已提交但未获得回答的问题分别标识，只恢复用户文字；成功获得回答的问题不再当作待恢复输入。用户后续编辑、主动清空与明确放弃优先，恢复不自动提问、提取或保存。

请求身份适配由 App 与恢复门禁共用 `request-identity.ts`：空会话／明确失效要求重新验证；网络、429、503 等临时故障停止业务请求并保留当前草稿；只有确认异账号或旧 generation 才按账号变化处理。不能把暂时无法取得会话直接归为账号切换。

最终移动完整回归为 **88/88**、类型检查通过，包含两项后续身份／迟到回答边界；独立 Auth/API/fence/学习会话复核 **55/55** 是其中重叠的检查范围，不相加。Web 最终集成定向 **35文件282项**、最后冲突增量 **3文件14项**（重叠），类型、静态检查与生产构建通过。移动 Web 静态及 iOS Hermes 导出通过；没有生成 IPA 或执行 Xcode/真机。确切命令、限制与本地日志见[优化台账](UX_OPTIMIZATION_LOG.md)。
