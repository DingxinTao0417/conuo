# 从备份恢复

Web 的恢复目标始终是已登录的云端账号：工作区保存到 Supabase PostgreSQL，原件保存到该账号的私有 Storage。包内原件只在当前页面内存暂存并记录可信 owner，不写入本机资料库，也不会凭 ZIP 或工作区声明取得另一账号的缓存权限。刷新后只读取云端，当前政策见 [Web 存储政策](WEB_CLOUD_STORAGE.md)。

Web 设置中的“恢复备份”可读取 Conuo 的整个工作区或指定知识库 ZIP，检查内容后，将包内资料、历史版本、笔记、知识页、对话、批注和知识关系作为新增副本追加到当前账号的最新工作区。账号已有内容保留，不要求空账号。导出范围和格式见 [EXPORT_FORMAT.md](EXPORT_FORMAT.md)。

## 操作流程

1. 登录并等待当前账号云端资料加载完成，进入“设置 → 账号与保存 → 恢复备份”，选择 ZIP。
2. 等待目录、完整性和原件检查完成。读取与预览不写入工作区，不连接包内网址或旧账号存储路径，可以停止读取。
3. 检查恢复目标、对象数量、历史版本和缺失原件清单。包缺少原件时，须明确同意只恢复已包含的内容。
4. 点击“确认恢复为新增副本”，等待保存队列上传原件并提交云端工作区。
5. 云端确认后才显示恢复成功。失败时保留当前页面计划与修改供重试；未登录或云端尚未加载时不能恢复，不创建本机工作区。

同一次确认计划在保存失败后重试不会重复新增，也不会覆盖用户之后的编辑。重新选择同一 ZIP 并再次恢复，会创建另一套副本。当前没有跨永久删除的导入收据或全局去重账本。

## 导入旧匿名资料

设置中的“导入旧版资料”是兼容旧版的主动入口。只有用户明确发起，才只读当前来源的旧匿名 IndexedDB 工作区与可信归属原件，生成 ZIP，并通过同一严格读取器检查后进入恢复预览。账号非空也可确认恢复为新增云端副本，旧资料及原件保持原样。

普通登录、刷新、阅读、导出和保存不会自动读取旧工作区，也不再通过“资料副本存在差异”阻止正常使用。旧无归属原件不能被自动认领，须按缺失原件处理并由用户明确同意；原件和旧快照没有在本轮策略变更中自动删除。再次主动导入会新增另一套副本，不自动去重。格式与原件归属边界见 [原件与遗留缓存](LOCAL_ORIGINALS.md)，实际迁移验收见 [云端验收](CLOUD_E2E_ACCEPTANCE.md)。

## 指定知识库备份

指定知识库 ZIP 的 `workspace.json` 是所选范围的业务快照，并非完整工作区。`export-scope.json` 说明所选知识库、对象数量、额外引用资料、缺失引用、已知原件缺失和警示；它不替代业务快照、资料版本映射及原件校验。已有且没有该清单的旧 Conuo ZIP 仍按原校验流程读取。

恢复只复制包内的知识库和对象，不读取旧账号、不补入未导出的其他库当前笔记、对话或知识库正文。成员资料在包内的 `spaceIds` 只保留所选库，恢复后关联新建的知识库副本；为追踪引用而额外纳入的资料 `spaceIds: []`，恢复后进入收件箱，已删除者仍在回收站。所选知识库的归档状态、资料与笔记的删除状态均保留。

每份纳入资料仍包含当前版和全部保留历史版本，不仅是被引用的片段或旧版；该资料的全部批注、可恢复草稿和已解决草稿记录也在包内。恢复对资料、版本、片段、批注和草稿身份进行一致重映射，保留原文、原话及 `textAnchor` 的 UTF-16 位置数值，不能把历史批注改绑到当前版。被引用资料仍在回收站时，引用身份虽已重映射，也不因此重新成为可用于 AI 的资料；用户须通过明确恢复动作处理。

所选笔记的全部已保存历史保留，包括当时记录的其他 `spaceId`。恢复会隔离重映射这些历史身份；包内没有对应知识库时，它们仅作为历史记录，不能导航到原库，也不会碰巧关联当前账号的同 ID 知识库。已纳入的关系端点、整理审核快照和个人笔记依据可能含其他库当时的历史标题、正文或摘录；保留这些证据快照不等于恢复该库的当前笔记或整套历史。

缺失引用保持原话和独立的缺失身份，不用恢复后的当前版或相似片段修补；导出映射中不可建立的路径仍为 `null`。导出预览的“已知原件缺失”只来自原快照标记，原件在生成或恢复读取时仍可能出错；是否包含准确字节，以包内版本映射、逐项问题记录和恢复时的实际校验为准。

## 内容和身份

`workspace.json` 是业务数据来源，`source-mapping.json` 定位每份资料当前版及全部保留历史版的元数据、正文、片段和原件。读取器检查二者的一致性；缺失历史正文、映射错版或原件指纹不符会拒绝恢复，不从当前版补齐旧内容。

恢复时重新分配业务对象、版本和片段标识，并一致更新结构化引用、笔记历史、对话、批注及知识关系。双资料对照会话保存的左右资料与版本身份、以及每次回答尝试中的固定资料版本身份，也会一起重映射，不能在恢复后猜测当前版本。每条回答尝试会获得新的尝试身份，并重绑到恢复后的原问题、空间和资料范围；它不会沿用旧账号的模型请求账本。原始资料正文和引用原话保留；笔记中的受支持内部链接指向对应恢复副本。缺失对象的引用保持为独立的缺失身份，不能碰巧关联当前账号中同 ID 的其他内容。

所有旧 `storagePath` 移除，包内原件使用独立的会话暂存键，上传后取得当前账号的新私有路径。现有工作区的全局 AI 设置保留；新增资料的 `aiAllowed` 为 `false`，需用户逐份开启。备份中的排队/运行整理任务转为取消，已有结果和已保存审核记录保留。文件导入任务也不会自动续跑：原件存在的未完成导入会转为可重新解析的已取消任务；原件缺失时资料标为解析失败和 `originalMissing`，不会留下无法执行的任务。备份本身不授予新账号继续调用模型的许可。

恢复的整理任务带有 `restoredFromBackup` 标记，不能检查原工作区的请求账本。需要继续时，用户可在当前资料已同步且允许 AI 使用后明确重新生成；这会建立新的请求，不续用原任务的云端执行身份。

删除和归档状态保留；恢复副本中的回收站项目仍留在回收站。账号注销记录会持续封锁同一账号，恢复包不会移除该记录或让已清理内容重新上线。Web 注销确认会清理同账号的当前页面暂存，并由云端注销流程负责正式数据；不会自动读取或删除旧 IndexedDB 恢复副本。用户已下载或导出的 ZIP 仍由用户自行保管和删除。服务端灾难恢复、账号注销后的删除记录重放及真实云端备份演练仍需单独实现和验收。

## 缺失原件

当某个版本的原件没有包含在包内，可以在明确同意后恢复已有文字及引用。该版本保存 `originalMissing: true`，同时去除不可用的本机和云端路径，避免阻塞其他完整资料同步。阅读器显示原件缺失提示，再次导出时也会继续列为不完整。

重新选择准确原文件，可经现有文件替换流程保存成新版本。即便内容指纹与缺失原件的当前版相同，也允许修复为新版本；历史缺失状态保留，不假称旧版原件已经找回。其他正常资料仍拒绝创建与当前内容相同的重复版本。

包内原件核对字节数与 SHA-256。已有可靠指纹不匹配时拒绝；旧记录没有可靠 SHA-256 时，在通过 ZIP 完整性和大小检查后，为恢复副本计算新指纹并在预览中说明。ZIP 校验与指纹不能证明文件内容来自可信作者。

## 读取与保存边界

| 项目              | 当前上限或行为                                                                         |
| ----------------- | -------------------------------------------------------------------------------------- |
| ZIP 文件          | 128 MiB                                                                                |
| 总展开内容        | 256 MiB                                                                                |
| 单个条目          | 50 MiB                                                                                 |
| 工作区及映射 JSON | 每份 24 MiB                                                                            |
| ZIP 条目          | 50,000 项                                                                              |
| 合并后的工作区    | 沿用当前 3 MiB 快照及各类对象数量上限，原件字节独立保存                                |
| ZIP 类型          | 单卷 STORE/DEFLATE；不接受 ZIP64、加密或特殊文件；空条目须为本项目导出的零压缩数据形式 |

读取器先核对原始中央目录、本地文件头、路径、重复项和声明大小，再逐项有界展开并校验 CRC。超过上限、结构损坏、指纹不符或用户取消时明确停止，不截断对象来完成恢复。没有在文件系统中解压包内路径，也不会加载包内 HTML 阅读副本来执行代码。

保存流程先校验全部原件，再不可覆盖地在会话内存暂存并回读核对；最后针对当前最新工作区合并并重查容量，通过现有账号保存队列上传原件并等待云端快照确认。解析或暂存期间的其他编辑不会被早期预览快照覆盖。

等待云端保存后还会检查恢复对象是否仍在当前工作区。若期间加载了另一份云端副本，导致这些对象全部或部分移出，恢复操作不会返回成功，也不会自动把它们再次并入。用户后续编辑已恢复对象的内容不影响同一计划的重复提交保护。

发布副本前失败时，仅清理确认由本次创建且无任何工作区引用的会话暂存原件；无法安全确认时保留并提示。发布后保存失败保留当前页面原件及修改，可重试。刷新或关闭会释放暂存，未确认内容不会自动恢复。Storage 上传成功而工作区未提交可能留下云端孤立原件；上传预留与清理迁移、生产调度仍待完成，不能把会话清理视为云端物理删除。

账号变化会阻止旧恢复操作写入新账号；当前页面暂存按可信身份隔离，已发出的上传与保存仍须等待对应账号的云端结果确认。Web 不提供退出后保留本机恢复草稿的路径。真实 Supabase 双账号、跨设备竞争及 Vercel 场景以独立云端联调为准。
