# 网页导入

入口：资料库 → 导入资料 → 保存网页。本页说明当前 Web 实现，不代表原生内置浏览器或完整 M0 已交付。

## 预览与保存

1. 输入公开文章 URL。网址通过本地格式校验后，可点击「打开原站（新标签页）」；它使用隔离的新标签页打开原始网址，不触发提取、保存或 AI 调用。输入、打开导入窗口或打开原站都不会自动抓取网页。
2. 主动点击「提取预览」后，核对标题、原始网址、重定向后的最终网址、采集时间、应用内学习阅读版和提取说明。阅读版是只读纯文本，标题可以修改；它不加载原站脚本、图片或 Cookie。
3. 选择提取正文、连续原文选段或仅链接，再确认加入资料库。选段必须是本次预览中的连续文字，保存后明确标为「仅保存选段」；这是用户限定的资料范围，不等于原网页解析失败。改写文字使用独立的「手动粘贴」入口。
4. 工作台按既有保存队列写入 IndexedDB，已登录且配置完成时再同步工作区；以顶栏保存状态为准。预览接口本身不写资料，不调用模型。

只有正文被明确保存后，才按资料版本分块并进入现有检索范围。全局与资料级 AI 开关继续约束问答和整理；网页抓取本身不依赖模型或 AI 开关。仅链接资料没有正文和内容块，不进入正文问答。

取消、修改 URL、切换账号、切换目标库或关闭窗口会中断当前提取并丢弃过期响应。返回预览还需匹配最初请求的网址，不能将另一网址的内容保存成当前来源。

无法联网、登录/验证码、动态空页、非 HTML、文章过短或超限时提供明确原因，保留手动粘贴或仅收藏链接的入口；不会自动把失败结果存入资料库。站点兼容性取决于公开 HTML，不能保证任意网址都可提取。

## 来源与版本

每份新网页资料增加可选 `webSnapshot` 元数据，旧资料没有该字段仍可读取：

| 字段                       | 含义                                                                             |
| -------------------------- | -------------------------------------------------------------------------------- |
| `originalUrl` / `finalUrl` | 用户提交的网址与实际完成抓取的最终地址；网络请求不发送 fragment                  |
| `capturedAt`               | 服务端完成采集的时间；手动模式为保存内容时的时间，界面区分「采集于」和「保存于」 |
| `method`                   | `server` 表示服务端提取，`manual` 表示用户提供；不是经过签名的来源真实性证明     |
| `scope`                    | `article` 提取正文、`selection` 用户选段、`pasted` 手动文字、`link` 仅链接       |
| `siteName` / `byline`      | 页面提供的站点和署名，可缺省，不视为已核实的身份                                 |
| `warnings`                 | 提取覆盖范围或失败说明                                                           |

每个新资料版本还可带可选 `coverage` 元数据；旧备份和旧云端快照没有该字段时继续按 `webSnapshot.scope` 与原处理状态只读推导，不会在无关保存时回填或改写旧版本。

| 字段                    | 含义                                                                                                            |
| ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| `captureScope`          | `full` 为保存的文件或提取正文快照，`selection` 为用户选段，`manual` 为手动粘贴，`link` 为仅链接                 |
| `parseState`            | `complete`、`partial`、`failed`、`pending` 或 `not-requested`；它只说明已保存材料的解析结果，不扩大网页采集范围 |
| `unavailablePageRanges` | PDF 等有明确页码的真实解析缺失范围；仅用于 `full` 的 `partial` / `failed` 状态                                  |

用户选段为 `selection + complete`，可正常检索和提问，但界面和回答都会说明只依据该片段。只有实际解析缺页或结构缺失才是 `partial`；其提示与 PDF 页码范围会保留到历史版本、备份与恢复中。手动粘贴同样只依据已保存文字。`article` 表示已保存的提取正文快照，不声称包含原网页的脚本、图片、嵌入内容或动态区域。

正文存于现有 `Source.text`，切块继续绑定 `sourceId`、`versionId`、`chunkId` 和章节。不会执行网页脚本、加载外部图片或保存 Cookie。应用内学习阅读版只含提取文字和结构，不是原站 HTML 或包含所有资源的网页归档；需要查看原始页面时，可在有效网址下使用「打开原站（新标签页）」。

从导入入口重复保存同一 URL 仍会创建独立资料。更新已有网页时，在阅读器点击「刷新网页」，或从「网页版本记录」进入刷新页，预览并确认保存为新版本。刷新固定原始网址并保留资料名称、标签、收藏、AI 权限与知识库归属；其他网址通过导入入口另存。

确认刷新后，资料 ID 保持不变，正文和切块使用新的版本 ID。原正文、片段标识、来源元数据、`coverage` 与时间归档到 `Source.versions`，当前版另记 `versionCreatedAt`；旧格式未记录版本时间时使用原采集时间或资料创建时间。预览、关闭弹窗或抓取失败不会替换已保存内容；仅链接和用户选段作为新版本需由用户明确选择。

历史列表可打开指定旧版，地址为 `#source/<资料ID>/version/<版本ID>`，刷新页面后仍展示该版本。旧问答和笔记的引用跳到对应版本，找不到旧版时明确提示，不用新版正文补齐。历史阅读保留已有标注和问答查看、独立摘录保存；新问答、标注和阅读进度写入须回到当前版。当前问答、自动整理和新建议审核继续只使用当前版；旧引用可阅读不代表仍是当前有效的 AI 依据。

保存时再次核对当前版本，另一操作已更新或删除资料时拒绝旧预览写入。最多保留 200 个历史快照，新旧正文、切块和元数据共同计入工作区 3 MiB 上限；超限拒绝本次新增，不自动删减旧版本。历史版本可直接恢复为当前；登录且同步完成后，也可经服务端影响预览与明确确认单独清理一个历史版本。原文件替换与完整数据生命周期仍需继续实现。

## 跨设备解析协调（第 12 份迁移已应用）

资料入库后，对同一 `sourceId + versionId` 的文件解析会先尝试获取账号私有的服务器租约。只有持有精确令牌的设备会继续下载原件、解析并提交结果；其他设备等待持有者完成、释放或租约到期。完成同时核验令牌与工作区 revision，取消会使持有者的迟到结果失效，失败或取消后的重新解析也走受控的原子状态迁移。网络结果不确定时，本机保留暂存状态，重新连接仅在远端 revision 未变化时重放原专用操作。受控转换只改变解析输出，不能改写该版本的原件或网页来源身份。无关资料仍可按既有保存协议编辑，但普通保存不能改写正在解析的资料/导入任务对。

这套协调不参与网页 URL 预览：预览仍是独立的只读抓取，确认保存后才进入资料版本与后续解析流程。`20260913233000_import_parse_leases.sql` 已在连接的开发 Supabase 执行，并核验私有表 RLS、认领/完成 RPC 及 `save_workspace` 租约保护；真实两台设备的网页资料入库、断网、租约到期和迟到结果拒绝仍尚未联调。

## 服务端边界

`GET /api/v1/web/preview` 只返回当前提取能力；`POST` 接受 `{ "url": "https://…" }`，成功返回经过结构校验的正文预览。业务请求检查同源、JSON 类型、16 KiB 输入上限及会话身份。

生产环境必须配置 Supabase 并登录，服务端以 `getUser` 核验身份，前后复核 `X-Conuo-User`。未配置时保留手动保存。仅 `NODE_ENV=development`、请求地址为 loopback、未配置 Supabase 且不含账号标头时提供本机匿名提取；开发服务继续绑定 `127.0.0.1`，不是公网匿名代理。

| 约束         | 当前实现                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------- |
| 网址与协议   | URL 最长 8192 字符；只允许 HTTP 80 / HTTPS 443；拒绝凭据、控制字符及不支持的协议                                    |
| 地址校验     | 所有 DNS 结果须为允许的公网地址；拒绝本机、内网、保留地址、云元数据地址、映射与转换地址段                           |
| DNS 与连接   | 用 Node HTTP/HTTPS 的自定义 lookup 固定已校验 IP；保留 Host/SNI 和证书检查，不二次解析、不继承代理配置              |
| 重定向       | 每跳重新校验，最多 3 次；拒绝循环和 HTTPS 降级                                                                      |
| 时间与容量   | 抓取总时限 12 秒，含 DNS、跳转、传输、解压；响应头 16 KiB，传输及解压正文分别 2 MiB                                 |
| 解压与编码   | 有界流式 gzip/deflate/br；按 BOM、声明编码或 UTF-8 读取，无法完整解码时失败                                         |
| 正文抽取     | Readability + JSDOM；禁用脚本和资源加载；最多 20000 个 DOM 元素、120000 正文字符；有效文字不足 100 字符时降级仅链接 |
| 临时负载保护 | 单实例每身份 10 次/分钟、同时 2 次，实例总并发 4；不是跨 Vercel 实例的持久配额或费用上限                            |
| 保存容量     | 新增前核对目标库、5000 份资料及完整工作区 3 MiB JSON 容量；数据库仍单独核对 JSONB 实际大小                          |

身份和目标库变化不能把结果写入其他账号。网页中的文字均为不可信资料，不是服务器、工具或模型的操作指令。

解析方案依据 [Mozilla Readability](https://github.com/mozilla/readability#nodejs-usage)、[jsdom](https://github.com/jsdom/jsdom#executing-scripts) 和 [Node HTTP](https://nodejs.org/api/http.html)。当前返回纯文本，不直接展示 Readability 的原始 HTML。

## 导出与剩余验证

备份在 `sources/<资料ID>/web-snapshot.json` 保存来源、范围与版本信息，`extracted.txt` 保存实际纳入的正文；`source-mapping.json` 指向两者。资源清单为空，明确未抓取外部图片和原站 HTML。仅链接不声称包含正文，选段不包含未选择部分。详见 [导出格式](EXPORT_FORMAT.md)。

备份同时保留全部历史版本，旧引用链接到对应版本目录，不能指向当前正文冒充旧依据。真实 Supabase 双账号、多设备同时刷新、Vercel 运行环境、多实例限流和更多站点兼容性仍需联调；动态页面、登录后的客户端采集和原生内置浏览器不在本次实现中。具体测试数量、浏览器样本与运行终态见 [开发状态](IMPLEMENTATION_STATUS.md)。
