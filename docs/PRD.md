## 1. 产品定义与命名

### 1.1 名称

- **已确认名称：Conuo（可诺）。** 英文主名为 Conuo，中文名为可诺；项目目录与后续代码标识统一使用小写 `conuo`。
- **建议读音：按 `co + nuo` 拆分，近似“扣诺”。** `nuo` 按中文拼音读；`co` 表达“一起”的联想，“诺”承载持续陪伴的品牌含义。这是品牌设计联想与建议读法，不是现成英语词义。
- **品牌语：陪你把知识学会。** 强调 AI 陪伴用户阅读、理解与回顾，将资料转化为自己的知识。
- 用户已确认项目名称，商标及域名可用性尚未核验。

### 1.2 一句话定位

Conuo（可诺）是一个以个人资料库为基础的 AI 陪伴学习工作台，让用户在不同设备上收集和阅读资料，在原文旁提问，并将分散内容整理成有出处、可编辑、可持续更新的知识体系。

### 1.3 核心价值

| 用户困扰 | 产品提供的能力 | 用户应获得的结果 |
|---|---|---|
| 资料散落在文件夹、网页收藏和聊天里 | 统一资料库、学习空间、跨端收集 | 有明确的资料入口，知道内容放在哪里 |
| 保存很多资料，但不知道如何开始 | 主题概览、阅读线索、学习目标 | 能选出下一步要读的资料或要解决的问题 |
| 阅读时需要反复复制到其他 AI 工具 | 原文伴读、选段提问、可回跳引用 | 能在保留上下文的情况下理解难点 |
| 多篇资料重复、术语不一致或观点冲突 | 概念关联、跨资料知识页、差异说明 | 看见资料之间的联系和不同适用条件 |
| 更换设备或隔几天后难以接续 | 同步进度、未解决问题、学习记录 | 快速恢复上次学习的上下文 |
| 看完摘要却无法独立解释 | 自我解释、小练习、针对性回顾 | 留下可观察的理解证据，而非仅有阅读次数 |

### 1.4 产品结构

产品围绕三种对象组织：

1. **资料：** 原始文件、网页快照、用户创建的笔记和摘录，是可追溯的来源。
2. **知识：** AI 或用户从资料中整理出的主题页、概念解释、关联及分歧。
3. **学习：** 用户的问题、自己的解释、练习作答与回顾记录。

资料与 AI 整理内容分别保存。已读状态、知识整理状态和掌握状态彼此独立。

当前实施范围是 Web 首版及其后续功能完善。手机和平板浏览器的响应式访问属于同一 Web 产品；独立客户端的开发、打包、系统集成与真机验收留到后续平台扩展阶段。

网页端在各设备上可访问，只能证明基础可用性；**不能据此宣称 Android、iPhone、iPad、Windows 或 macOS 独立客户端已经交付。**

### 2.4 初期不纳入范围

- 手机、iPad、Windows 和 macOS 独立客户端及其前置原型、签名、打包、系统分享、原生手写与客户端离线包。
- 多人实时协作、企业组织和复杂角色管理。
- 完整通用浏览器能力，例如插件市场、密码管理、任意站点自动化。
- 自动抓取整个网站或账号内全部页面。
- 完整视频语义理解、无限时长录音转写、复杂工程文件解析。
- 类似专业排版工具的文档编辑器，以及替代完整办公套件。
- 强制依赖复杂知识图谱可视化的主界面。
- 本地模型管理、模型训练，以及云端 AI 离线运行。
- 社区公开内容、知识市场、积分排行和社交关系。

这些项不影响未来扩展；如要提前引入，应单独评估对核心学习流程的成本。

## 3. 用户与核心任务

### 3.1 优先用户

**主要用户：自学者。** 拥有若干 PDF、网页和笔记，希望系统学习某个主题，每周在多个设备上阅读；当前常在文件夹、浏览器和 AI 聊天工具之间切换。

**次要用户：课程学习者和知识工作者。** 前者依赖课件与复习，后者需要比较资料并形成有依据的结论。首版不预设考试题库、机构教学或专业研究数据库。

### 3.2 核心任务（JTBD）

| 编号 | 情境与任务 | 完成标志 |
|---|---|---|
| JT-01 | 我开始学习一个主题，希望把现有资料集中起来 | 创建空间，导入至少一份可阅读、可提问的资料 |
| JT-02 | 我读到不理解的段落，希望获得与上下文一致的解释 | 获得解释并能跳回被引用的原文位置 |
| JT-03 | 我发现多篇资料讲同一主题，希望整理异同 | 形成带多来源引用、可编辑的知识页 |
| JT-04 | 我换设备继续学习，希望找回上次的位置和疑问 | 看到同步位置、相关对话和未解决问题 |
| JT-05 | 我想确认是否理解，希望得到适量练习与反馈 | 提交回答，看到依据与具体不足，自主决定是否复习 |

### 3.3 代表性使用故事

林同学建立“机器学习入门”空间，上传一份教材和课程文档，保存两篇网页。AI 根据可解析内容建议主题目录。她在 iPad 上阅读某一段，询问“这里为什么需要求导”，得到带页码引用的解释。晚上在电脑上，她把自己的理解与 AI 的解释整理成知识页，并留下“不同学习率如何影响结果”的问题。几天后手机打开同一空间，展示上次问题和一题可选练习。

故事中的资料数量和学科仅用于原型与验收示例，不代表用户已确定目标学科。首版的 iPad、电脑和手机访问均指浏览器 Web 会话；练习属于后续学习增强，独立客户端另行扩展。

## 4. 产品目标与效果指标

### 4.1 目标

1. 用户能够独立完成“导入—阅读—提问—保存理解”的首个流程。
2. AI 对资料内容的关键判断有可验证出处，证据不足时清楚说明。
3. 自动整理减少人工归类负担，同时保留用户的内容控制权。
4. 用户跨设备继续学习时，不丢失已经确认同步的资料和学习记录。
5. 回顾功能能帮助用户定位理解不足，并能回到相关原文。

### 4.2 候选指标及解释

| 指标 | 计算口径 | 用途 |
|---|---|---|
| 首次有效学习完成率 | 首次进入后 24 小时内，导入成功、打开资料、完成一次有引用问答并保存笔记/知识页的用户数 ÷ 同期完成注册且非测试用户数 | 判断首用流程是否成立；24 小时为候选窗口 |
| 每周有效学习用户 | 一周内在至少一个空间发生阅读，以及提问后保存、本人笔记编辑或练习提交之一的去重用户数 | 候选主指标；不把纯后台生成算成学习 |
| 引用支持率 | 人工评估中被引用原文确实支持的关键断言数 ÷ 抽检的有引用关键断言数 | 判断回答可信度 |
| 知识建议保留率 | 接受后 7 天内未撤销的知识建议数 ÷ 已接受建议数 | 观察建议质量；不能单独证明学习效果 |
| 跨端接续成功率 | 目标端获取指定同步版本并恢复对应学习位置的次数 ÷ 有效接续尝试次数 | 判断同步体验 |
| 延迟理解表现 | 用户对同一知识目标的首次与后续等价题作答表现 | 验证学习价值；样本不足时仅展示观察 |

首轮用户验证后再确定增长、留存和学习效果目标。聊天次数、生成字数、上传数量只作辅助指标。

## 5. 信息架构与界面原则

### 5.1 一级导航

```text
Conuo
├── 首页：继续学习、最近资料、待解决问题
├── 收件箱：待归类的导入资料与处理状态
├── 学习空间
│   ├── 概览：学习目标、主题与继续入口
│   ├── 资料：文档、网页、笔记
│   ├── 知识：主题页、概念与来源
│   ├── 问答：空间内对话及未解决问题
│   └── 回顾：练习与个人理解记录
├── 空间内搜索：M1 增加显式启用的全库搜索
└── 设置：账号、存储、AI 数据范围、同步、导出
```

### 5.2 阅读工作台

以下首版布局均通过响应式 Web 实现，按浏览器视口验证；原生分屏、手写和系统集成在后续平台扩展时另行评估。

- 桌面宽屏：左侧资料/章节目录，中间原文，右侧按需展开 AI 与笔记。
- iPad：以原文为主体，可切换分屏或浮层；手写能力在后续客户端阶段提供。
- 手机：单列阅读，选段后的 AI 对话以抽屉或独立页面显示，关闭后恢复原位置。
- 窄屏 Web：提供与手机相同的基础阅读流程，桌面快捷键不作为唯一入口。

### 5.3 必须清晰可见的状态

每份资料应显示“已保存”“处理中”“可用于 AI”或具体失败原因。文件云端存在、解析完成、进入检索索引是三个独立事实。

AI 对话应显示来源范围及是否包含联网补充；知识页应标识 AI 草稿、用户编辑和引用状态；同步状态应区分已在设备保存、正在同步、云端已确认和同步异常。

### 5.4 空白、错误与恢复

- 空空间提供文件导入、粘贴链接和创建笔记三个明确入口。
- 空知识库说明需要至少一份可用资料，并可主动生成主题建议。
- 上传、解析、索引错误就地提供原因与下一步，不以通用“未知错误”替代可识别原因。
- AI 超时保留问题、选段与范围，用户可重试；不得显示伪造的完成状态。
- 跨端异常应提供同步详情和保留本地副本的入口。

## 6. 核心使用流程

### 6.1 首次使用

注册或登录 → 创建学习空间（名称必填，目标可跳过）→ 上传文件/导入链接 → 显示处理状态 → 打开首份可用资料 → 提出问题 → 点击引用核对 → 保存笔记或知识页。

可提供明确标注的示例资料，但不得把示例混进用户自己的空间。首次引导不强迫用户填写学习画像或接受 AI 推测的目标。

### 6.2 网页进入知识库

粘贴网址或从其他应用分享 → 打开原页或导入预览 → 用户选择保存正文/选段 → 生成带来源信息的快照 → 解析与索引 → 建议标签及关联主题 → 阅读提问或整理到知识页。

无法提取时保存标题与链接并说明“正文未导入”，允许用户自行粘贴正文、上传文件或稍后重试。

### 6.3 自动知识整理

资料完成索引 → 基于新增或变化内容生成标签、主题和关系建议 → 形成 AI 知识草稿或既有页面更新建议 → 用户预览新增/修改内容及来源 → 接受、编辑、忽略或撤销 → 新版本可被引用。

标签可按用户设置自动应用。覆盖已有人工内容、合并页面、移动资料和删除内容均不默认执行。

### 6.4 跨设备接续

设备 A 保存阅读位置、批注和问题 → 获得云端确认 → 设备 B 打开同一空间 → 拉取新版本 → 展示继续入口 → 恢复资料位置与关联上下文。

若 A 离线，A 显示待同步；B 不应被误导为已经获得 A 的最新进度。

### 6.5 学习回顾

用户标记概念或问题 → 选择生成少量练习 → 自主回答 → AI 给出带出处的反馈 → 用户修正理解或标记仍有疑问 → 回到相关原文 → 按用户设置进入后续回顾。

练习、通知和学习建议均可关闭，不阻碍资料库与问答的基础使用。

## 7. 功能需求

**优先级与分期：** P0 表示所属阶段不可缺少，P1 表示重要增强，P2 表示后续探索。M0 为首版 Web，M1 为 Web 功能完善，M2 为学习增强；“后续平台扩展”单独排期，在 Web 功能基本稳定后启动。后续阶段的 P0 不构成首版要求。以下编号继续用于追踪，详见第 15 节。

| Markdown / TXT | 正文、标题、代码块；Markdown 外部资源不默认抓取 | 后续支持明确授权的关联附件导入 | 编码异常可重选编码或保留原文件 |

**导入需求：**

| 编号 | 需求 / 分期 | 业务规则与验收要点 |
|---|---|---|
| IMP-01 | 单个与批量导入 · P0/M0 | 支持文件选择、桌面浏览器拖拽、粘贴链接；可选择目标空间。原生系统分享入口留到后续平台扩展。每项独立进度，某项失败不阻塞其他项。 |
| IMP-02 | 可恢复处理任务 · P0/M0 | 上传、解析、索引、知识整理分别记录状态；网络中断可重试，重试使用原任务身份，避免重复创建资料。解析失败不删除已上传原文。 |
| IMP-03 | 重复与同名处理 · P0/M0 | 内容指纹相同提示复用已有资料或保留副本；同名不同内容不覆盖。替换资料需明确发起并形成新版本。 |
| IMP-04 | 部分成功 · P0/M0 | 展示可解析页数/章节与失败范围。AI 仅引用可用区域，问答显示覆盖不完整；“无答案”与“相关部分未解析”不能混淆。 |
| IMP-05 | 取消、超额与清理 · P0/M0 | 上传前预校验，提交时再次校验；支持逐项取消。云端已保存后取消后续 AI 处理，默认保留原文件；彻底取消导入的影响单独说明。 |

**处理状态模型：**

```text
主流程：待上传 → 上传中 → 已保存 → 解析中 → 建立索引 → AI 可用
失败分支：上传失败 / 解析失败 / 索引失败 / 超限 / 不支持 / 等待用户处理
部分完成：原文件已保存 + 部分内容可阅读或可用于 AI
整理状态：未整理 / 建议生成中 / 有待查看建议 / 已整理 / 整理失败
```

原文件保存状态、内容处理状态和整理状态分别记录，避免用一个“完成”覆盖不同事实。加密文件不收集或保存文档密码；提示用户自行提供可解析副本。M0 扫描 PDF 可保存，但需明确其文本无法提取。

非 AI 的文本解析与普通关键词索引按资料处理设置执行；需要模型参与的索引、摘要或其他生成任务，须先满足用户已启用 AI 及资料允许用于 AI 的条件。仅上传存储文件不自动视为同意所有 AI 处理。

### 7.7 AI 问答与问题记录

| ASK-03 | 跨资料比较 · P0/M0 | 可比较观点、方法、定义和例子，分别显示来源及适用条件。无法解释分歧时保留分歧。 |
| ASK-04 | 对话持续与重试 · P0/M0 | 对话记录按空间保存；支持停止生成、重试和重新开始。重试形成可识别的回答版本；草稿问题不会因错误消失。 |

| ASK-06 | 联网补充 · P1/M2 | 单独开关，默认关闭；联网前明确提示可能发送搜索词。外部材料与个人资料分别标注，不自动入库。M0/M1 不依赖该能力满足问答验收。 |

用户在对话中缩小资料范围后，先前范围内的历史内容不能成为隐藏证据。系统应重新建立受当前范围约束的上下文，或提示新建对话；具体实现由技术验证确定，结果必须满足范围隔离验收。

|---|---|---|
| DAT-01 | 完整导出 · P0/M0 | 导出原文件、网页快照、用户笔记/知识页 Markdown、对话与批注 JSON，以及来源映射清单。长任务可查询进度；部分失败逐项说明。 |
| DAT-02 | 回收站与恢复 · P0/M0 | 删除资料立即退出搜索和新 AI 请求；恢复后保留原 ID、关联和版本，必要时重新索引。普通删除不自动删除用户已经保存的笔记和历史回答，须说明并标记失效引用。 |
| DAT-03 | 彻底删除与账号注销 · P0/M0 | 提供具体影响预览与确认，区分原资料、派生解析、历史版本和用户另行保存的内容。账号注销停止后台任务并清除账号数据；备份清理规则见第 11 节。 |

## 8. AI 知识整理与问答规则

### 8.1 证据优先级

原始资料中的明确表述、用户笔记、AI 生成的知识页属于不同证据类型。回答界面须能识别各类来源。

- AI 草稿默认不入索引，避免未经核对的生成内容循环强化。
- 用户接受的知识页可入索引，但关键事实应回溯其原始来源；仅有 AI 推断时明确标注。
- 用户笔记可以表达个人理解或假设，不自动转化为外部事实。
- 用户接受 AI 整理结果表示认可保存，不等于系统已证明内容正确。

### 8.2 知识页建议结构

```text
主题标题
简明解释
关键概念与前置知识
来自资料的主要结论
例子及适用条件
不同资料的分歧 / 尚无依据的缺口
我的理解与批注
相关问题
引用来源、版本与更新时间
```

资料不足的字段可省略或显示缺口，不为凑齐模板而生成内容。

### 8.3 引用定位

| 资料类型 | 最低定位信息 | 失效处理 |
|---|---|---|
| PDF | 资料 ID、版本 ID、物理页序号、文本片段；有印刷页码时另外显示 | 找不到精确选段时仍打开原版本对应页，并提示定位降级 |
| 网页快照 | 快照 ID、段落锚点、原 URL、采集时间 | 原站消失不影响已保存快照；快照被删除后停止提供原文访问 |
| DOCX / Markdown / TXT | 资料版本、标题路径、段落/文本锚点 | 阅读版变化后仍优先定位旧版本；不能伪造原文件页码 |
| 笔记 / 知识页 | 对象 ID、版本、正文块位置、内容类型 | 被编辑后保留历史引用状态；引用旧版本需可识别 |
| 图片 OCR / 手写 / 音频 | OCR 在 M1 使用页/图片区域；手写在后续平台扩展保留笔迹关联；音频在 M2 探索时间戳 | 识别不确定或缺失时显式提示，不能输出虚构锚点 |

引用有效不等于引用支持结论，两者需要分开评估。

笔记或知识页的被引用历史版本到期后，保留引用元数据并标记“历史版本已到期，无法查看当时原文”。可另行打开当前版本，但不得把当前版本冒充当时的引用版本。原文件版本与网页快照按第 11.3 节另行保留；“引用旧版本”“来源已删除”“历史版本已到期”使用不同状态。

### 8.4 更新规则

1. 整理任务绑定输入资料的确定版本和目标页基础版本。
2. 用户在任务运行期间编辑目标页时，不直接应用旧建议；展示需重新生成或手动合并。
3. 资料新增生成补充建议；资料冲突生成并列观点；资料删除使相关引用失效。
4. 同一建议重复接受不重复插入内容；用户拒绝的相同建议不在无新依据时反复出现。
5. 撤回某次 AI 更新形成恢复版本，不删除此后用户独立编辑的内容；存在后续编辑时提供差异与选择。

### 8.5 错误与证据不足

- **检索成功但无证据：** 说明当前范围未找到依据，并建议补充资料或由用户扩大范围。
- **解析覆盖不全：** 显示缺失范围，不能得出“整本书从未提及”的结论。
- **服务失败或超时：** 显示系统错误与重试入口，不伪装成内容不存在。
- **多来源冲突：** 分别引用、指出条件，不按文件数量投票决定真伪。
- **开放推理：** 能基于已有材料提出解释，但必须标注推断及可验证的前提。

### 8.6 数据范围与不可信内容

模型只能获得本次授权范围中的必要内容。资料正文、网页与附件属于待分析内容，其中要求泄露资料、扩大权限、改变系统规则或执行外部操作的文本不应作为指令执行。

基础问答和整理任务不具有删除原文件、发送消息、操作网站账号或发布内容的权限。删除或禁用资料后，运行中的请求应在输出交付前重新检查可用性，必要时终止或重新生成。

## 10. 云同步、离线与冲突处理

### 10.1 同步范围

首版的跨设备接续与并发冲突通过不同设备浏览器或两个隔离的 Web 会话验证。本文的“两端”在 M0 指 Web 会话，不要求提前开发独立客户端。

同步：原始资料及版本、网页快照、空间关联、标签、笔记、批注、已保存知识页、问题、对话、阅读位置和后续练习记录。

不同步为知识内容：设备浏览会话、第三方网站 Cookie/密码、临时上传碎片、设备窗口布局。离线下载清单和缓存大小属于设备级设置；AI 资料可用开关属于账号数据设置。

### 10.2 同步状态与可靠性

对象状态为：本地待同步 → 同步中 → 云端已确认；异常分支为失败、认证失效、超额或冲突。必须记录服务端版本、客户端变更身份及删除标记。

网络恢复重放操作要保持幂等。应用不得依赖设备时钟顺序覆盖内容；显示时间可本地化，但冲突判定使用版本关系。后台受系统限制时，在下一次前台打开后继续同步并说明待处理状态。

### 10.3 冲突策略

| 对象 / 冲突 | 期望处理 |
|---|---|
| 两端编辑同一段笔记 | 保留双方版本，标记冲突，用户选择或手动合并 |
| 两端添加不同批注 | 根据独立批注 ID 合并，不相互覆盖 |
| AI 更新与人工编辑并发 | 优先保护人工内容，AI 建议重新校验基础版本 |
| 删除与离线编辑并发 | 删除标记阻止旧客户端自动复活资料；离线新增文字保存为可恢复草稿，并由用户选择恢复或另存 |
| 两端改变阅读位置 | 保留各设备最近位置，默认展示最新确认的阅读活动并允许选择 |
| 标签添加与删除并发 | 使用可解释的操作合并，无法确定时保留冲突信息；用户固定字段优先于 AI 自动建议 |

### 10.4 离线能力边界

M0 保护浏览器中已保存的编辑草稿，但不承诺完整离线工作流；M1 继续完善 Web 功能。后续平台扩展再评估显式离线资料与已保存内容的下载，完整后才能显示“离线可用”。以下完整离线包规则仅适用于启用该能力后的平台。

离线时允许阅读、批注、编辑可用笔记和保存待发送问题；云端 AI 不能生成新回答。联网后，待发送问题由用户再次发起，避免网络恢复时意外触发大量 AI 请求和费用。

资料在设备离线期间被其他端删除，离线设备可能暂时仍保有本地副本；恢复连接后应执行删除同步。远程操作无法保证立即清除未联网设备的内容，应在设备管理说明中明确。

## 11. 数据模型与数据生命周期

### 11.1 关键数据对象

以下为产品级模型，用于明确所有权和关联，不锁定数据库结构。

| 对象 | 关键属性 | 关系与约束 |
|---|---|---|
| User | 账号 ID、偏好、数据处理设置、状态 | 所有私有对象均有账号归属 |
| LearningSpace | 名称、目标、归档状态 | 通过关联表连接资料与知识页 |
| Source / SourceVersion | 类型、原文件、内容指纹、版本、来源信息、删除状态、AI 可用开关 | 一个资料有多个版本；空间关联不复制原文件 |
| WebSnapshot | 原 URL、最终 URL、采集时间、正文、资源清单、提取范围 | 属于确定资料版本；与浏览器会话隔离 |
| ImportJob | 请求身份、阶段、进度、失败原因、重试次数、输入版本 | 不能将完成的旧任务误应用到新版本 |
| ParsedBlock | 文本、原文位置、页/章节、解析覆盖信息 | 必须回溯到 SourceVersion；删除来源后退出检索 |
| Annotation | 选段、批注、原文锚点、创建/修改版本 | 不依赖文件名作为唯一定位 |
| Note / NoteVersion | 正文、作者类型、版本、同步状态 | 用户笔记与 AI 草稿可区分 |
| KnowledgePage / Revision | 主题、正文、来源、接受状态、基础版本 | 待接受草稿不默认用于新回答 |
| ConceptRelation | 两端对象、关系类型、来源/建议标记 | 用户可以修改和删除 |
| Conversation / Message | 空间、问题、实际检索范围、回答版本、状态 | 保存引用及当时的数据版本，不只存最终文本 |
| Citation | 来源 ID、版本、位置、引用类型、可用状态 | 同一资料改名或移出空间不使 ID 改变 |
| LearningQuestion | 问题、关联原文/对话、解决状态 | 状态由用户控制 |
| ReviewItem / Attempt | 题目、来源、作答、反馈、时间、用户自评 | M2 引入；题目修改不改写历史作答 |
| SyncChange / Tombstone | 对象、基础版本、变更身份、删除记录 | 防止离线旧数据复活已删除对象 |
| UsageLedger | 存储、处理用量、请求身份、错误状态 | 幂等记账，能区分成功处理与失败 |

### 11.2 生命周期与删除语义

| 操作 | 原资料 | 解析与检索 | 用户笔记 / 知识页 / 历史回答 |
|---|---|---|---|
| 清除本机缓存 | 云端保留 | 云端保留 | 云端保留，未同步草稿先处理 |
| 移出学习空间 | 资料库保留，其他关联不变 | 该空间的检索范围排除它 | 本空间保留内容，但引用是否可打开按账号权限与资料状态判断 |
| 禁用资料的 AI 使用 | 云端保留、仍可阅读 | 新请求立即排除，取消相关待执行 AI 任务 | 历史生成文本保留；新请求也不能通过旧对话/派生内容间接使用被禁用原文 |
| 资料进入回收站 | 在候选保留期内可恢复 | 新搜索/AI 请求立即逻辑排除；后台清理活动索引 | 已另存的文字保留，引用标记“来源已删除”；不提供原文打开 |
| 从回收站恢复 | 恢复资料 ID 及关联 | 重新确认解析/索引可用性 | 引用可恢复时更新状态，否则提示需要重建 |
| 彻底删除资料 | 删除原文件、所有相关原始版本和快照 | 清理解析、向量、摘要等系统派生物 | 默认保留用户独立保存的文字与历史回答，但明确列出；提供选择清理关联内容的入口 |
| 删除学习空间 | 删除空间与空间级设置 | 删除该空间范围关联 | 明确列出专属内容；全局资料默认保留，可另行选择删除 |
| 注销账号 | 删除账号全部资料 | 停止任务并清除索引及处理副本 | 删除账号全部内容，进入备份到期清理流程 |

“从所有历史文字中抹除同一事实”不作为可保证能力：用户可能复制、重写或导出了内容。系统应准确展示可追踪的关联对象，并允许用户选择一并删除，不能宣称已消除所有相似表述。

删除或禁用资料的 AI 使用后，新 AI 请求应排除以该资料为依据的可追踪原文块、摘要、知识页片段及对话上下文。无法可靠按片段分离时，保守排除整个关联对象；独立保存的内容仍可供用户阅读。此约束依赖已记录的来源关系，不承诺识别外部复制或重新创作的所有相似文字。进行中的任务也须检查删除与可用状态，不能重新发布已失效内容。

### 11.3 候选保留策略

以下为待成本、地区及产品政策评审的默认草案，实施前需定案并在产品中告知：

- 回收站保留 **30 天**；保留期间占用原文件存储配额。
- 未完成上传的临时碎片保留 **24 小时**，到期可清理；重新上传使用明确新任务。
- 笔记与知识页可恢复版本保留 **30 天**，不承诺无限历史。
- 原文件各版本与网页快照默认保留至用户删除对应版本或资料，全部计入原始资料配额；达到配额时停止新增或由用户明确清理，不静默删掉被引用的旧版本。新问答默认使用当前有效版本，引用旧版本需明确选择或由历史记录访问。
- 确认彻底删除后，活动原文件、解析、索引和处理缓存在 **24 小时**内完成物理清理；在此之前已通过访问控制退出在线使用。
- 备份保留窗口候选为 **30 天**。删除数据在备份到期后移除；恢复备份时必须重放删除记录，避免已删除资料再次上线。
- 用户已主动导出的文件和长期离线设备副本不受服务端删除直接控制。

保留期不能只存在于 PRD：需进入设置、删除确认说明及运维验收。最终期限若变化，应同步修改本文与测试用例。

### 11.4 原文与第三方 AI 处理

建议采用传输加密、服务端存储加密、访问控制与最小必要内容发送。云端 AI 处理通常需要访问本次相关内容，因此不能默认宣称“服务方完全无法读取”或“端到端零知识”。

在首次启用 AI 与设置页说明处理目的、处理方类别、可用资料范围和关闭方式；供应商名称、处理地区、保存期限及训练使用条款在选型后据真实合同填写。未核验前不做“不训练”“零留存”等承诺。

默认私有，不提供无鉴权的资料访问。日志中不默认记录完整正文、模型输入输出、站点会话或凭据；错误排查优先使用任务 ID 与脱敏元数据。

## 12. 非功能需求与候选目标

### 12.1 可测性能目标

下表用于初始技术验证，最终须在明确设备、网络、部署区域与负载下测试。测试基线建议为：单账号 1,000 份已索引资料，总可检索文本 500 万中文字符量级，服务端 20 个并发活跃会话；中英文混合样本独立记录。基线数值不代表已经测得的容量。

| 编号 | 候选目标 | 测量方式与边界 |
|---|---|---|
| NFR-01 | 资料列表首次可交互 P95 ≤ 3 秒 | 指定测试设备与稳定网络；不把原文件全部下载计入 |
| NFR-02 | 关键词检索 P95 ≤ 2 秒 | 已索引资料、定义的测试负载；冷启动另外记录 |
| NFR-03 | 文本型文档索引完成 P95 ≤ 120 秒 | 从上传确认开始，50 页以内且不超过 10 MB 的测试文本 PDF；OCR 与复杂文件分开评估 |
| NFR-04 | AI 首个可见输出 P95 ≤ 8 秒 | 指定模型与问题长度，计入排队；完整回答时间另记录。超时阈值和重试策略需技术评审 |
| NFR-05 | 普通对象跨端可见 P95 ≤ 5 秒 | 双端前台在线且已完成服务端保存；不包括大文件上传和系统限制的后台执行 |
| NFR-06 | 用户编辑自动保存防抖候选 1 秒 | 最后输入后尝试保存；失败显示状态，必须能区分本地草稿与云端保存 |

### 12.2 可靠性与可恢复性

- 同一请求重试不重复创建资料、不重复接受知识更新、不重复扣减用户额度。
- 后台任务有运行、失败、取消、重试与终态，重启后可恢复可重试任务。
- 删除、权限变更和 AI 禁用应在检索与回答交付路径生效，不能只靠定时重建索引。
- 备份恢复必须演练；候选目标为已云端确认的元数据 **RPO ≤ 24 小时、RTO ≤ 24 小时**。该目标意味着灾难场景可能损失最近一天数据，是否需要更强保障须在公开上线前决策。
- 已有资料在 AI 服务不可用时仍可阅读、编辑和导出。文件服务与模型服务的可用性分别监控。
- 未制定正式 SLA；内部测试和试用阶段不得用目标值宣传已兑现的服务等级。

### 12.3 AI 质量门槛

建议在冻结的人工标注集上评估，首轮至少 **120 道问题**，覆盖单文档可答、跨文档综合、无答案、来源冲突、局部解析失败、范围切换、已删除资料和恶意指令等场景。样本在调试集和保留验收集之间分开。

| 编号 | 候选放行条件 |
|---|---|
| AIQ-01 | 测试集中输出的引用目标 100% 指向存在且当时授权可用的对象；正文定位可降级，但须明确提示 |
| AIQ-02 | 人工抽检的关键断言引用支持率 ≥ 90%；样本数、评审分歧和错误类型随结果一并记录 |
| AIQ-03 | 在标注为无依据的问题中，明确说明证据不足的比例 ≥ 90% |
| AIQ-04 | 跨账号、范围越界、已删除或 AI 禁用来源的隔离验收用例须全部通过，即零次未经授权的检索、引用或内容泄露；任一隔离失败阻止放行 |
| AIQ-05 | 测试中无未经用户操作覆盖笔记、删除资料、执行网页指令的行为 |

这些门槛是初始建议，不代表能保证所有真实问题都正确。发布报告必须给出真实样本、分母和失败案例，不能只展示单次演示。

### 12.4 易用性与可访问性

- 中文界面与中英文资料；日期按设备时区显示，存储使用统一时间基准。
- 主要流程可用键盘完成，焦点可见；触屏操作不依赖悬停。
- 正文支持可读字号、缩放、深浅色模式；信息不只依赖颜色表达。
- 控件有可访问名称；重要状态对屏幕阅读器可读；最终标准等级在专项评估后声明。
- 长任务不阻塞继续阅读；导入、同步和生成进度可回到任务详情查看。

### 12.5 安全验证范围

所有权校验、下载鉴权、上传类型与内容校验、文档解析隔离、网页阅读版脚本清除、访问地址限制、模型范围约束均需测试。服务器导入网址应防止访问本机、内网、云实例元数据及经跳转绕过限制的地址。

未经用户选择的其他页面与文件不进入 AI 上下文。错误报告不得包含用户的站点 Cookie、登录令牌或无关资料。支持地区、用户年龄与相关数据政策由上线前评审决定，本文不作任何合规认证声明。

## 13. 额度、设置与运营边界

### 13.1 配额设计

建议分开管理云存储、单文件大小、导入并发/批量数、解析用量、AI 生成用量及本机缓存，不以一个模糊的“积分”遮盖所有限制。

| 配额项 | 内部试用候选配置 | 计量规则 |
|---|---|---|
| 单账号原始资料存储 | 5 GB | 原文件、网页资源、其保留的各版本及回收站原文计入；明确展示组成 |
| 单个文件 | 50 MB | 上传前和提交时校验；不同解析器可有更小的处理上限 |
| 单批文件数量 | 20 个 | 分项展示结果，超过时分批导入 |
| 索引/知识生成任务 | 并发数由部署容量验证后确定 | 排队可见；暂停后台生成不影响阅读 |
| OCR / 音频处理 | 启用时按页/分钟单独配置 | 处理前给范围和预计计量，不承诺无限处理 |
| AI 生成 | 暂不定套餐次数 | 可见剩余用量、重置规则及失败是否计费；供应商消耗与用户扣减分开记录 |
| 后续平台离线包缓存 | 启用该能力后由设备容量和用户设置决定 | 首版不提供完整离线包；清理缓存不影响账号云端额度 |

平台内部解析、向量及系统版本备份不重复显示为用户原文件大小，但必须纳入服务成本核算并设置合理保留策略。达到额度后允许读取、导出和清理现有资料，不丢弃正在编辑的文字。

### 13.2 设置项

- 账号与设备：登录方式、会话、退出、账号删除。
- 资料与存储：配额组成、回收站、导出、默认导入空间。
- AI：资料级可用开关、自动归类/整理开关、默认问答范围、处理方说明。
- 阅读与同步：首版提供显示偏好与同步详情；离线包下载与管理入口在对应平台启用该能力后提供。
- M2 学习：练习偏好、回顾频率、通知开关。

### 13.3 商业化与运营

当前未确定商业化方案，不在本轮创建支付、订阅或付费云资源。后续可以比较按订阅分配存储与 AI 额度、单独扩容等方案，但需先测得每活跃用户的存储、解析、检索与模型成本。

运营侧至少需要查看服务健康、队列积压、任务错误和汇总用量。默认不提供可随意浏览用户原文的后台；确需处理用户授权的支持请求时，应有受限权限与访问记录。

## 14. 分析事件与评估方法

### 14.1 最小事件集合

| 事件 | 必要字段 | 注意事项 |
|---|---|---|
| space_created | 匿名化用户 ID、时间、端类型 | 不记录学习目标正文 |
| import_started / import_ready / import_failed | 任务 ID、类型、大小区间、阶段、耗时、错误码 | 不记录文件名、完整路径或网页敏感参数 |
| reader_opened / reading_resumed | 资料匿名 ID、端、入口、是否接续成功 | 默认不记录读到的正文 |
| question_submitted / answer_completed / answer_failed | 范围类型、请求 ID、耗时、引用数量、状态 | 默认不记录问题与回答全文 |
| citation_opened | 引用 ID、是否定位成功、是否降级 | 与“引用支持结论”人工指标分开 |
| knowledge_suggested / accepted / rejected / reverted | 建议 ID、变更类型、资料数量 | 不采集知识页正文 |
| note_saved / sync_confirmed / sync_conflict | 对象类型、版本、端、耗时 | 不采集笔记内容 |

M2 再增加练习提交、反馈异议与回顾完成事件。事件重试需去重；指标文档应排除内部测试账号和自动任务。

### 14.2 首轮用户验证

建议邀请 5—8 名符合主要用户画像的试用者，使用自己的非敏感资料或明确授权的样本完成首个流程；观察能否找到入口、理解状态、核对引用和继续旧问题。人数为可行性访谈建议，不作统计效果证明。

分别记录任务完成情况、卡点和用户复述。把“资料已上传但不知道还在解析”“引用跳转不到所需位置”等具体问题转成设计改动。学习效果需更长周期与相匹配的评价设计，不能仅由满意度或留存推断。

### 15.1 MVP 定义

本方案的 MVP 对应 M0，即**首版 Web：用一组文档与网页，在同一处完成阅读、基于出处的问答、知识整理与学习接续。** 它是当前明确的首版交付范围，按已确定的 Web 功能与质量门槛验收。

“功能开发差不多”建议以核心流程可稳定使用、主要交互和数据结构趋于稳定、阻塞问题已处理、有实际试用反馈为判断依据。届时再决定平台顺序和迁移方式，不要求全部探索功能完成，也不将原生客户端提前作为 Web 发布条件。

### 15.2 依赖顺序

账号与对象权限 → 资料保存及版本 → 解析与原文定位 → Web 阅读/检索 → 问答引用 → 知识页与增量建议 → Web 功能完善。学习增强可在 Web 上继续迭代；其他平台在核心功能基本稳定后另行启动。

服务端数据版本、删除语义和引用锚点在 Web 阶段确定，以支持浏览器会话间的保存与接续。保持 HTTP 接口和模块边界清晰即可，首版不为尚未启动的平台预建空壳工程或复杂兼容层。

### 15.3 发布前必须具备的材料

- 已批准的版本需求清单、支持平台/格式清单及明确的已知限制。
- 关键流程原型、空白/加载/失败/冲突状态设计。
- 技术决策记录，包含数据与模型处理方、权限、保留策略、配额和恢复方案。
- 人工标注 AI 评估结果、功能验收结果、Web 浏览器兼容性与多会话接续结果；后续客户端在各自发布时补充设备验收。
- 真实部署环境中的删除、备份恢复、任务重试与版本回退演练记录。

## 17. 技术设计约束与验证任务

### 17.1 已确认技术路线与逻辑架构

用户已接受以下 Web 基础技术栈，并指定 Supabase 数据库和 Vercel 部署。选型与模块边界详见 [TECH_STACK.md](TECH_STACK.md)；对象存储、登录和模型服务仍待选择，后台队列的 Vercel 适配须通过 Web 阶段原型。移动与桌面原生组件的验证留到相应平台启动后。

| 范围 | 已确认的技术选择 |
|---|---|
| Web 前端 | React + Tailwind CSS + TypeScript，在 Next.js 工程内实现 |
| 后续 Windows / macOS 参考 | 此前 Electron + React 路线保留，平台启动时复核；首版不开发 |
| 后续手机 / iPad 参考 | 此前 React Native + Expo 路线保留，平台启动时复核；首版不开发 |
| Web 编辑与 PDF 阅读 | Tiptap + PDF.js；批注和引用定位由项目实现 |
| 业务后端 | Next.js + TypeScript，Node.js Route Handlers；提供统一 HTTP API |
| Web / 业务 API 部署 | Vercel |
| 业务数据 / 向量索引 | Supabase 托管 PostgreSQL + pgvector |
| 原文件与快照 | 对象存储，服务商待定 |
| 后台任务 | 保留 Python + Celery；建议采用 Vercel Queues 与 Python Functions，POC-05 验证后锁定；Redis 为常驻处理层备选 |

```text
首版 Web（浏览器访问）
        ↓ 统一账号与对象权限
Vercel 上的 Next.js 资料与学习服务 ─── 同步与版本服务
        ↓
原文件与快照存储 ─── Supabase 中的元数据、笔记与关联
        ↓
Supabase 任务/outbox → 有界 Python 派发 → Vercel Queues
                                                 ↓
                                 Python Celery 分阶段处理 → 暂存结果
                                                 ↓
                                  Next.js 校验并发布关键词/语义索引
                                                ↓
                                         AI 问答与整理
                                                ↓
                                  引用、知识版本、用量与评估
```

图示是建议的逻辑职责划分：React 前端和 Next.js TypeScript 业务 API 由同一个 Next.js 工程提供并部署到 Vercel；Python 派发与处理通过独立函数执行，Vercel Queues 接入须通过 POC-05。Supabase 承担 PostgreSQL + pgvector；各语言共用版本化数据契约和单一迁移来源，不共享运行时业务对象。Supabase Auth、Storage、Realtime 尚未确认，服务地区、套餐、模型商仍待选择。

### 17.2 技术选型原则

- 首版按清晰模块组织 React / Tailwind CSS 界面，通过 HTTP API 接入 Next.js 业务层；后续平台可复用数据、接口及合适的组件，也可重新实现界面。Server Actions 仅作为 Web 交互的可选实现，权限、版本和额度判定以 Next.js 业务层为准。
- 在已选框架上先验证 Web 的 PDF 文本定位、网页提取和中文输入；移动编辑器、阅读器、笔迹及原生样式在相应平台启动后验证。
- 原文件、业务数据与检索索引职责分离；索引可重建，不作为用户资料唯一副本。
- 文件解析、OCR、索引与耗时知识整理由 Python + Celery 执行；Next.js 在 Supabase 同事务创建任务及 outbox，再由有界 Python 派发函数通过 Celery 原生客户端投递。Vercel Queues 接入为首选待验证方案，不从 TypeScript 手工拼装 Celery 消息；原 Redis 常驻方案作为验证未通过时的备选。
- Python 暂存解析与生成结果，由受限的 Next.js 结果提交接口重查版本、删除、取消及按任务类别适用的 AI 许可后发布，普通关键词索引不因关闭 AI 被禁用。知识草稿的发布与用户接受正文修改分开处理。
- 交互问答走 Vercel 上 Next.js Node.js Route Handler 的流式链路，首版验证实际网络至 Web 浏览器的首段输出、断流、鉴权和取消行为；后台工作按可恢复阶段拆分，须满足实际函数时长、内存及依赖包限制。
- 大文件通过受限凭证直传对象存储，Next.js 负责授权与上传后校验；不依赖函数请求体承载整份大资料。
- Supabase 连接池、数据库角色、暴露的 schema 与 RLS 策略按技术方案落实；前端不持有数据库密码或服务密钥，也不绕过 Next.js 业务规则直接改写资料和任务。
- Supabase、对象存储和客户端框架不自动提供产品所需的云同步；版本、冲突副本、操作重放、删除标记和本地缓存隔离需独立实现。
- 模型供应商可替换，但每次替换需要重跑核心评估集，不仅比较演示回答。
- 客户端不内置服务端模型密钥；不把服务器权限交给网页内容或文档文字。

## 18. 风险与应对

| 风险 | 用户影响 | 应对与发现信号 |
|---|---|---|
| 范围覆盖笔记、浏览器、AI、学习及多端，工作量膨胀 | 首版长期无法使用 | 按 M0/M1/M2 设置门槛，每次新增功能说明挤占范围 |
| 资料解析质量差 | AI 漏读、错引、误解表格 | 支持清单和覆盖状态可见；用真实代表样本验证 |
| 自动整理把推断固化成事实 | 知识库越用越不可靠 | 草稿隔离、原始引用、增量审核、质量评估与撤回 |
| 用户笔记被 AI 或同步覆盖 | 数据损失与信任受损 | 版本前提、冲突保留、编辑恢复作为 P0 |
| 站点登录、动态内容或嵌入限制 | 内置浏览体验不一致 | 三态拆分、站点清单、外部打开与手动导入替代 |
| 删除/禁用后索引或对话仍使用资料 | 用户数据控制失效 | 在线权限过滤、生成前后校验、来源追踪、专门测试 |
| 云端模型费用高且后台整理不可控 | 产品成本失控或用户意外耗额 | 增量任务、去重、批量、可取消、用量可见与额度控制 |
| 用户只收藏而不学习 | 资料增长但学习价值不足 | 首页接续入口、问题记录，验证用户是否再次使用知识页 |
| 学习反馈误判 | 用户形成错误理解 | 参考要点与出处、允许异议、避免绝对掌握标签 |
| 名称与现有用途混淆 | 对外传播或注册受影响 | 保留初筛记录，对外发布前进一步核验；内部标识可重命名 |

## 20. 术语、参考资料与变更记录

### 20.1 术语

| 术语 | 本文定义 |
|---|---|
| 资料库 | 保存原文件、网页、笔记及其组织关系的集合 |
| 学习空间 | 围绕一个目标或主题组织资料、知识与学习记录的容器 |

| AI 草稿 | 尚未被用户接受的生成内容，不默认成为检索证据 |

| 引用支持率 | 人工核对中，引用原文确实支持关联断言的比例 |
| 网页快照 | 用户明确保存的某次网页正文/资源副本，带 URL 与采集时间 |
| 幂等 | 同一逻辑操作被重试时，不产生重复资料、重复更新或重复扣减 |
| 删除标记 | 在物理清理前记录对象已删除，并阻止旧数据自动恢复 |
| RPO / RTO | 灾难恢复中允许的数据丢失时间窗口 / 服务恢复时间目标 |
