# Conuo Web 界面规范

更新日期：2026-09-21。记录已落地的工作台样式及本轮增量，供后续功能沿用；历史验证日期在各节保留。

2026-09-21 平台入口更新：本文仍是 Web 与首批 Electron 宿主的视觉基线；原生端页面、导航、窗口和系统交互分别以 [桌面端 PRD](DESKTOP_PRD.md)、[iOS PRD](IOS_PRD.md)、[iPadOS PRD](IPADOS_PRD.md) 为准。移动原生界面共享品牌与业务含义，不直接照搬浏览器断点；旧页面生成提示词不再作为当前设计入口，其他原型与品牌资源保留。

## 设计方向

参考 Notion 的导航与内容组织方式、飞书的资料管理入口，保留清晰的信息层级和稳定的页面骨架。按用户最新反馈，Conuo 使用更有色彩的学习工作台：紫色续读、蓝色资料、暖杏色问题与薄荷绿笔记，配合丰富的竖向知识库封面；正文与编辑区保持清晰。参考入口为 [Notion 侧栏说明](https://www.notion.com/en-gb/help/navigate-with-the-sidebar) 与 [飞书云盘说明](https://www.feishu.cn/hc/zh-CN/articles/778513900437-%E5%88%9B%E5%BB%BA%E6%96%87%E4%BB%B6%E5%A4%B9)。以下尺寸与颜色是 Conuo 的实现约定，不是上述产品的官方设计参数。

## 基础规范

| 项目       | 当前约定                                                                |
| ---------- | ----------------------------------------------------------------------- |

| 字体       | 操作系统无衬线字体栈，中英文沿用同一体系                                |
| 层级       | 页面标题约 26px、分组标题 15px、内容标题／正文 13–14px、辅助信息约 12px |

统一变量位于 `apps/web/src/app/styles/tokens.css`。阅读器仍有专用布局；不为统一工作台而取消它的双栏、工具栏或引用定位规则。图标中的文件类型缩写、数量徽标可小于正文尺寸，但不能用 8–10px 承载主要资料信息。

## 内容配色

桌面宿主使用 40px 一体标题栏，底色与 Conuo 辅助面一致，均为 `#f7f7f8`。Windows 原生窗口按钮区域同步此色；侧边栏开关、前进后退、文件、编辑、视图、帮助及下载入口处于同一行，空白区域可拖动。最左侧 Logo 替换为侧栏图标，“文件”菜单保留；展开状态和“显示/隐藏侧边栏”提示随操作更新。品牌仍在业务侧栏及连接页显示。macOS 保留系统菜单和原生交通灯。业务页面继续复用 Web 布局；系统窗口交互须在对应平台单独验收。

| 用途                       | 强调色                               | 浅底色    |
| -------------------------- | ------------------------------------ | --------- |
| 续读、主要操作与新建知识库 | 紫色 `#6353c7`（主要按钮沿用品牌色） | `#eee9fc` |
| 最近资料、知识页、文档导入 | 蓝色 `#396bb8`                       | `#eaf2ff` |
| 笔记、网页／纯文本图标     | 薄荷绿 `#287b69`                     | `#e9f6ef` |
| 问题、问答图标             | 暖杏色 `#996127`                     | `#fff4e3` |
| PDF 文件图标               | 玫瑰色 `#b04f63`                     | `#fdeff2` |

使用成组的 `--accent-*-soft`、`--accent-*-border` 和前景色。续读卡片可以使用浅紫至浅蓝的柔和渐变，问题／笔记面板由浅色标题区过渡到白色正文。彩色背景上的日期等小字使用较深的次文字色。颜色辅助识别内容类别，名称和图标始终保留；成功、警告和错误仍使用独立状态色。

知识库封面有紫、蓝、绿、桃、黄、薰衣草六组配色，按持久 ID 稳定选择，改变排序不会换色。深紫封面配浅色文字，其他封面配深色文字；用户自选颜色保留 20% 浅色混合，并使用独立深色前景以保持对比度。归档封面保持灰色，悬停不恢复成活动库颜色。默认六组封面及收件箱的标题／辅助文字对比度按色值计算均不低于 4.5:1，此项不代表全站无障碍认证。

## 页面模式

- **学习概览：** 当前续读与次要最近资料并列；次要资料用紧凑行显示名称和阅读位置。下方以两栏展示待解决问题和最近笔记，窄屏顺序排列。不填充虚构数据、装饰图表或没有动作的入口。
- **资料库：** 三个快捷入口使用绿、蓝、紫图标，保留竖向彩色知识库封面。标题与底色成组匹配，资料数／日期明确；归档和待审核状态按正常文档流排列，避免互相覆盖。
- **资料列表：** 搜索与筛选处于同一操作区，表头、状态与更新时间保持稳定列关系；手机保留可读字号及收藏／管理的 44px 操作区域。
- **笔记／知识页：** 统一卡片内距和标题、摘要、元信息层次；状态通过文字与适当颜色表达。搜索和筛选在窄屏换行，不挤压标题。
- **问答：** 连续分隔列表，行级操作弱于页面主操作。保留真实不可用提示，移除日常页面上与当前任务无关的实现说明。
- **账号与设置：** 左下角账号与顶栏头像共用入口，侧栏不再单列设置。五组内容保留原有分组标签、卡片与行间距；账号、普通操作与危险操作保持明确区别。

## 导航与反馈

全站统一浅紫选中态。长知识库名称保持单行省略并提供完整可访问名称；平板紧凑导航同时显示颜色点与名称首字，减少只有相同色点时的歧义。没有置顶资料时隐藏空分组。顶栏账号仅显示头像，完整账号信息保留在侧栏与账号面板中。

常态云端保存反馈采用低干扰显示；错误、冲突、待处理任务仍可辨认。键盘焦点边框保留，移动端 toast 位于固定导航上方。全局导航与库内导航遵守 [路由约定](NAVIGATION.md)，本次视觉调整不修改数据流与路由含义。

## 验证与后续维护

已验证正常桌面 1203×912、平板 834×1194、手机 390×844 与 360×800。390px 首页滚到底时最后面板底部约 768px，底栏顶部 791px；360px 资料行收藏／管理均为 44×44px；平板侧栏 68px、知识库入口 44px。均未观察到页面横向溢出。

P37 色彩增量复核了桌面首页、资料库、笔记和知识页，以及 390×844 手机首页、底部面板与资料库；两列彩色封面、长标题和固定底栏保持正常，页面没有横向溢出。P36 的布局验证保留为历史记录。

每次新增页面应优先使用现有变量和组件，并检查空状态、长标题、键盘焦点、窄屏及真实数据。此轮不是完整无障碍认证，也不是原生手机／iPad 客户端验收。测试与运行状态见 [开发状态](IMPLEMENTATION_STATUS.md) 和 [视觉验收记录](../design-qa.md)。

## 全端体验优化记录（2026-09-21）

本节记录本地 Goal 优化，不替代上述历史验收或对应平台真机验证。逐项问题、页面覆盖与最终检查以 [UI／UX 优化台账](UX_OPTIMIZATION_LOG.md) 为准。

- **移动学习概览：** 以添加网页、写笔记、继续学习、知识库及紧凑最近资料组织页面。继续学习与最近资料避免重复展示同一资料；知识库颜色按 ID 稳定选择，保留名称和资料数量。减少首屏大块装饰，让收集与接续学习先出现。
- **移动收集表单：** 网址和标题使用显式标签；手机采用底部弹层，长正文预览在表单内滚动，保存及未知结果核对入口独立保留。关闭时保护当前草稿，不把仅保留在内存的内容描述为云端保存。
- **阅读与问答上下文：** 详情返回保留原资料库范围、查询与会话位置，全局导航清除旧知识库范围。版本或权限变化必须使旧回答和引用失效；同账号仍可见资料的未发送文字可恢复，但需说明范围变化并等待用户再次发送。资料删除与账号退出不复活旧内容。
- **Web 续读摘要：** Markdown／网页正文使用已有可见文本投影生成摘要，不把标题、链接等标记直接展示。普通 `#`、`C#` 和纯文本符号保留；摘要只是展示，不改写原文和引用身份。
- **Web 手机问答：** 面板接近阅读区全高，上方保留 12px 间隔；不再以约 64% 高度和固定最小高度挤压回答。标题、范围和输入区缩减间距，长范围说明可以滚动；许可提示与引用不隐藏。关闭、发送操作为 44px，输入字体 16px，保留底部安全区。390×844 与 320×700 已实际核对，不能据浏览器截图宣称原生键盘行为通过。
- **桌面宿主：** 保留浅灰一体顶部栏、最左侧侧栏开关及“文件”等菜单。下载进度更新沿用稳定的操作节点，避免键盘焦点丢失；失败反馈可见。连接与下载页沿用 Conuo 的颜色、边框及内容层级。
- **说明文案：** 日常页面使用“保持页面打开”等与操作有关的说明；存储容量区明确区分导入上限与云服务总容量，移除无助于决策的服务商及部署术语。

上述移动布局来自正式 React Native 组件的浏览器预览；Web 和桌面页面使用独立内存／桥接夹具。Apple 真机、安全区与软件键盘、系统分屏、Pencil、原生菜单和系统文件对话框仍需对应平台证据。本节起点尚未完成的压力场景和认证恢复，进展补充如下；当前仍是本地工作，未提交、推送或部署。

### 后续增量：输入、阅读与异常状态

- **表单保留与状态文案：** 手机导入／笔记弹层采用可滚动正文与独立操作区。正常提交显示“正在保存”，只有读回确认才显示“正在核对”；初次保存中不提前宣称结果未知。同账号更换目标库、切换 Web 导入标签不应销毁尚未提交输入，关闭与 Escape 先确认。未确认保存时不开放重复提交或能绕过核对的“打开已有资料”。
- **阅读接续：** 资料列表按页面、知识库和查询分别保留位置；进入详情前捕获当前位置，返回后等待真实布局再恢复，不让初始零位置覆盖记录。用户主动滚动后，以用户操作为准。原文字号变化按段落保留位置；阅读和回答的滚动位置独立，关闭问答面板不能归零回答位置。以上均为当前账号内存会话，不表示进度已经云同步。
- **Markdown 与宽表格：** Markdown 资料正文和 AI 回答共用结构化文本呈现，保留标题、列表、强调和代码层次；非 Markdown 原文仍按原文呈现。表格在自身容器横向滚动，出现溢出时提示左右滑动，不能挤成每行几个字或把整个页面撑宽。字号调整不改原文、chunk、版本或引用定位。原始 HTML 不执行，外部图片不加载。
- **Web 搜索展示：** 摘要显示用户可读文字；用于定位的原文、资料身份和匹配位置保持原值。修饰摘要不应改变搜索范围、筛选或详情返回路径。
- **Web 登录入口：** 登录、注册和找回密码共用单层卡片，标题与当前操作一致；独立登录页不显示无有效去向的关闭按钮，也不重复内层标题。邮箱／密码保留显式标签；字段字号 16px、主要与次要操作最小高度 44px。实际请求失败仍留在表单，不以模式切换产生成功提示。
- **Web 冲突处理：** 双方笔记先展示经白名单清洗的可读富文本，不把 HTML 源码作为默认正文。手动合并复用正式编辑器；打开而未编辑时仍保留原始候选，切换选择或保存失败保留手动输入。离开已编辑的合并草稿前提供继续编辑与明确放弃的确认。提交时锁定选择和编辑；页面修改、云端候选、保存未知和已确认成功必须使用不同文案。
- **认证中断后的输入：** 恢复提示只说明存在本次会话的输入，不提前展示正文。仅同账号重新验证、会话封锁解除、工作区访问门禁通过且用户选择恢复后，才展示本人文字和链接。未获回答的问题明确标识，不冒充未发送或已经完成；任何恢复均不自动提交或重新发问。主动退出、423 封锁、确认切换账号清除临时输入。网络暂时不可用不得被误标成账号切换；网页预览和 AI 授权需要重新确认。

本轮证据包括移动长列表返回（截图 `62` 及实际往返记录）、宽表格（`64–68`）、Markdown 阅读与字号接续（`78/81/82`）、空库到新建示例笔记（`83–85`）；Web 导入保护（`74–77`）、保存异常（`89/91/92`）、登录／注册／找回表单（`95–98`）、冲突富文本前后（`90/99`）和手动合并失败／离开确认（`100/101`）。移动恢复提示 `86–88` 只证明隔离提示／失败态的布局，不证明最新认证集成或真实登录链路。最终重新导出后的复验仍由 [UI／UX 优化台账](UX_OPTIMIZATION_LOG.md) 记录，不能以这些局部截图宣称全部页面、云端或原生平台通过。

### 收尾规范补充

独立失效链接和重设密码页面同样使用至少44px的返回操作；密码字段16px，避免窄屏输入过小。键盘可见焦点采用品牌色2px描边，不能用颜色替代按钮名称。笔记列表可访问名称使用类型、标题和状态，避免读出整篇摘要。手机冲突编辑器允许工具栏换行，以真实可用宽度布局，不通过裁切隐藏内容。

最终本地交互证据已补充到优化台账：新资料的完整学习链路 `114–117`、恢复失败与隔离 `110`、合并草稿保护 `101/102`、笔记弹层键盘焦点 `118`、独立认证页 `121/122`。界面与原生/云端能力的验证层级保持分开。

减少动态效果偏好启用时，目录定位直接到达目标，相关弹层取消过渡；关闭后仍保留阅读位置并返回入口焦点。已用正式组件接模拟偏好在390px核对实际样式和滚动结果，截图`123/124`；此项不代表原生系统设置已验证。

共用Web弹窗用独立的标题ID提供可访问名称，关闭前执行原生dialog清理，并在必要时恢复仍有效的入口。嵌套确认返回父弹窗，全部关闭返回页面入口；不抢走已明确移到其他位置的焦点。移动浏览器的七个既有弹层同样提供与标题一致的名称；安装版原生RN不转发这一Modal属性，原生屏幕阅读器须单独验收。

## 公开主页（2026-09-24）

未登录访问 `/` 时显示公开主页（`apps/web/src/components/landing/`），主页只保留“开始使用”一个入口，打开账号弹窗（默认登录表单，可切换注册与找回密码）；已登录用户仍直接进入工作台，且不会下载主页的 three.js、GSAP、Lenis 与字体。带工作台哈希（如 `#library`、`#source/…`）的深链接会跳过主页介绍，直接弹出中文登录框。认证判定仍只由 `WebCloudEntry` 完成，主页只负责展示。

- **视觉：** 由暗到亮。首屏标题为“每个答案，都有出处。”，背景为深靛色（`#07061a`）与 WebGL 粒子：散落的“资料页”汇聚成 Logo，鼠标经过处一小片粒子浮起变亮、Logo 随鼠标轻微倾斜（不推开粒子），向下滚动时展开为知识网络；工作流章节背景经品牌紫、薰衣草过渡到 `#f7f7f8`，文字颜色在两者之间切换，不经过灰色低对比区间；功能、原则、多端与常见问题为亮色；结尾与页脚回到暗色。
- **字体：** 拉丁字母与数字使用随仓库提供的 Geist / Geist Mono（SIL OFL 1.1，见 `landing/fonts/OFL-Geist.txt`，`preload: false`），中文继续使用系统字体栈。
- **文案：** 中英双语，结构由 `copy.test.ts` 校验一致。不写价格、虚构用户数或评价；Web 之外的客户端标为“开发中/规划中”；演示资料与回答均标注为示例。
- **动效与无障碍：** 系统开启“减少动态效果”时关闭平滑滚动、粒子形变与固定滚动叙事，改为静态 Logo 和纵向步骤；WebGL 不可用时显示静态图标。装饰性画面对读屏隐藏，演示回答完成后通过 `aria-live` 播报全文。
