# 工作区导出格式

本机原件读取先验证当前账号与确切版本，并使用字节写入时的可信归属。云端 `blobKey` 声明不能获得另一账号缓存；旧无归属裸 Blob 保留但不自动读取，仍可尝试有效云端原件并按版本报告缺失。迁移和恢复边界见[本机原件归属](LOCAL_ORIGINALS.md)。

导出为 ZIP，可选择整个工作区或指定知识库。`workspace.json` 保留本次范围的业务快照：整个工作区包含完整工作区，指定知识库包含该库内容及为保留原文依据而纳入的引用资料。`source-mapping.json` 将所含资料及版本对应到原文件、提取文本和元数据。范围内的回收站项目仍包含在备份中，以 `deletedAt` 标识。本机审核草稿单独保存在浏览器中，不属于工作区业务快照，导出边界见下文。

## 导出范围与确认

设置中的“导出备份”先打开确认面板，默认选择整个工作区。具体知识库的资料页和知识页顶栏也提供“导出此知识库”，在同一面板中预选该库；已归档知识库仍可选择。仅打开面板、切换范围或刷新预览不会读取原件或下载 ZIP。预览分别列出资料、资料版本、普通笔记、知识页、对话和批注数量，并说明整理记录、知识关系、可恢复草稿及回收站项目；用户点击“下载 ZIP”后才开始生成。

指定知识库的内容按以下规则确定：

| 内容               | 包含边界                                                                                                                                                                                                                               |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 知识库与成员资料   | 只包含所选知识库的元数据，以及 `spaceIds` 包含该库的资料，含回收站资料。包内成员资料的 `spaceIds` 归一为 `[所选知识库 ID]`，不附带其他知识库的成员关系。                                                                               |
| 笔记、知识页和对话 | 包含当前属于所选库的记录，含待审核、回收站和所选笔记的全部已保存历史。笔记历史中的 `spaceId` 仍是当时的记录，不因此附带该历史知识库或改变当前归属；包内可能没有可导航的对应知识库。                                                    |
| 整理和关系记录     | 包含请求范围属于所选库的整理任务，以及自身 `spaceId` 属于所选库的知识关系，保留其结果、审核和冻结端点。仅有关系端点指向所选笔记，不会把其他库的整条关系拉入。                                                                          |
| 额外引用资料       | 从所含笔记当前／历史引用、手工摘录身份、对话范围与消息、回答重试版本锁、个人笔记依据、整理结果和冻结关系快照中追踪资料身份。存在的额外资料会包含当前完整正文、**全部保留历史版本**及各版原件，不只包含被引的片段或旧版。               |
| 批注与恢复草稿     | 所有纳入资料的全部批注、可恢复草稿及已解决草稿记录一同保留，含外部资料和历史版的记录。位置批注的 `textAnchor` 保留准确原文范围，不给普通资料引用新增位置字段。关联文件导入任务也保留；非所选库的任务空间归一为收件箱。                 |
| 其他库的笔记与快照 | 不因引用就附带其他库的当前笔记、全部笔记历史、对话或知识库正文。已纳入的关系端点、整理审核记录和对话个人笔记依据仍可能内嵌回答当时的标题、历史正文或摘录；这些快照属于本次备份内容，预览会提示，不能据此承诺完全没有其他库的历史文字。 |

额外引用资料在包内的 `spaceIds` 为 `[]`，不会自动加入所选库。将 ZIP 恢复为新增副本后，它们进入收件箱；原本已删除的资料仍在回收站。恢复只新增包内包含的知识库和业务对象，不找回未导出的其他库当前内容。

根目录新增 `export-scope.json`，整个工作区和指定库导出均写入此文件。它是范围说明清单，包含 `schemaVersion: 1`、`scope`、`spaceName`、`allRetainedVersions: true`、`counts`、`memberSourceIds`、`additionalSources`、`missingReferences`、`knownMissingOriginals` 及警示信息。`additionalSources` 列出额外资料的身份、标题、删除状态、当前／历史版本和纳入原因；`counts.notes` 包含知识页，确认面板将普通笔记与 `counts.knowledgePages` 分开显示。清单用于说明范围，不替代 `workspace.json`、版本映射及恢复时的完整性校验。

引用的资料、版本、片段缺失或原话不能在准确版本核验时，保留原标识与原话并列入 `missingReferences`；不可建立的正文／元数据路径为 `null`，不从当前版或相似文字补造依据。`knownMissingOriginals` 只反映快照中已经标记缺失的原件。预览不读取原件字节，数量和清单不保证这些字节最终可取得；生成阶段仍逐版本读取并报告问题，见下文“文件原件与跨格式版本”。

确认面板保存不可变的已审阅快照。下载前再次计算**所选导出范围**的指纹：范围内数据、引用资料或所选知识库改变时，必须“刷新导出范围”后重新确认；知识库消失时停止，不退回整个工作区。范围外且没有被纳入的无关编辑不使预览失效。生成开始后继续使用已审阅副本，同账号、同会话和缓存上下文中的后续编辑不会替换正在导出的快照。

客户端 API 使用 `WorkspaceExportScope`：`{ kind: "workspace" }` 或 `{ kind: "space", spaceId }`。`exportWorkspace(已审阅的完整工作区, sourceBlob, { scope, onProgress, assertCanContinue })` 由导出领域层统一裁定范围，不由页面分别裁剪。省略 `scope` 保持整个工作区导出，既有恢复／交接流程中的完整副本备份仍可使用该默认行为。

同一导出操作阻止重复确认。账号、会话 token、本机缓存模式、工作区可读状态或组件生命周期变化会使继续检查失败；每次原件读取、归档构建、进度发布以及最终触发浏览器下载前都检查当前上下文。旧操作的迟到结果、进度和错误不发布到新账号界面，上下文失效不能降级为普通原件缺失后继续下载。读取失败等正常导出错误保留已选范围，供用户核对后重试。

## 学习数据

启用学习数据导出时，ZIP 根目录增加 `learning.json`。该文件与 `workspace.json` 分开，避免把题目、复习状态和作答历史写入 3 MiB 工作区快照；没有学习数据时可以省略该文件。

```json
{
  "schemaVersion": 1,
  "items": [{
    "itemId": "题目 ID",
    "spaceId": "知识库 ID",
    "kind": "recall",
    "prompt": "题干",
    "choices": null,
    "answer": { "text": "参考答案" },
    "explanation": null,
    "citations": [],
    "origin": "user",
    "originRef": null,
    "conceptKey": null,
    "hints": [],
    "status": "active",
    "card": {},
    "dueAt": "2026-09-24T12:00:00.000Z",
    "version": 0,
    "reps": 0,
    "lapses": 0
  }],
  "reviewLogs": [],
  "settings": { "dailyNewLimit": 20, "desiredRetention": 0.9, "paused": false }
}
```

题目保留创建时的规范引用快照、来源标记和复习卡片；`reviewLogs` 保留评分、批改快照和耗时。恢复备份时每个题目与作答记录都分配新的 `itemId`、`logId`，并把引用中的资料与版本身份按新增副本的映射重写；无法映射的引用保留为历史不可用记录，不绑定到当前版本。恢复不会继续排队的 AI 任务或复习任务，学习设置按备份值写入新副本。

## 笔记与知识页

`note-mapping.json` 列出每份笔记或知识页的当前内容、引用和全部已保存历史版本的文件路径。已保存为知识页的待审核草稿与已接受知识页都会导出，分别保留 `kind`、`status` 和删除状态；它们与差异面板中尚未应用的审核勾选和改写不同。

每份笔记目录包含：

| 文件                                                     | 内容                                                                                |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `标题.md`                                                | 可阅读和迁移的 GFM Markdown，包含标题、正文和当前引用来源                           |
| `标题.html`                                              | 经过清理的 HTML 阅读副本，保留常见富文本结构并附引用来源                            |
| `content.original.html.txt` 或 `content.original.md.txt` | 原始编辑器正文的逐字备份；最后的 `.txt` 后缀避免直接打开时执行原始 HTML             |
| `metadata.json`                                          | 完整笔记元数据，包括原始正文、当前引用和已保存版本记录                              |
| `citations.json`                                         | 按顺序编号的当前引用，保留原始 `sourceId`、`versionId`、`chunkId`、页码、章节和原话 |
| `versions/序号-版本ID/`                                  | 每个历史版本的 Markdown、HTML、原始正文、版本元数据，以及有记录时的独立引用文件     |

历史版本目录加上顺序号，即使旧数据包含重复版本 ID，也不会覆盖其他历史正文。历史正文内原有的引用标记保持原样；导出按快照是否实际记录引用区分两种情况：

| 历史快照                    | Markdown / HTML                      | 引用文件与版本映射                                                                                |
| --------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `version.citations` 已记录  | 只附当时的引用来源，不附当前笔记引用 | 独立 `citations.json`；`historicalCitationsAvailable: true`，`citations` 指向该版本目录的引用文件 |
| `version.citations: []`     | 不追加引用来源区                     | 仍有内容为 `[]` 的独立引用文件，`historicalCitationsAvailable: true`，表示当时确实记录为空        |
| 旧快照没有 `citations` 字段 | 保留历史正文，不补造引用来源         | 不生成引用文件；`historicalCitationsAvailable: false`，`citations: null`                          |

新的历史快照还可记录当时的 `status`、`aiGenerated`、`spaceId` 和 `contentRevision`。`metadata.json` 保留原始记录，`note-mapping.json` 的版本项列出这些值；未记录时为 `null`，不会用当前页面的状态补齐。`workspace.json` 保留本次导出范围的业务快照，导出不修改原笔记、引用、历史或 revision。

手工原文摘录创建的知识页会在当前笔记及相应历史版本的元数据中保存可选 `manualExcerptRefs`。每项只包含资料、版本、片段身份和选段指纹，用于在富文本编辑后避免重复追加；它不包含原文、不替代 `citations.json`，也不改变引用可读副本。恢复备份为新增副本时会同引用一起重映射这三类身份。

## 引用与资料版本映射

当前和历史引用只在备份包含**相同资料 ID 和相同版本 ID**时链接到资料元数据。每个 `citations.json` 中的引用保留当时的 `sourceId`、`versionId`、`chunkId`、标题、页码、章节和原话，并增加以下字段：

| 字段                 | 含义                                                                                                                                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `number`             | 当前引用列表中的顺序编号；历史版本从其独立快照重新按顺序编号                                                                                                                                         |
| `sourceAvailability` | `included` 为准确当前版，`historical` 为准确保留旧版，`deleted` 为回收站中可恢复的准确版本；`source_missing`、`version_missing`、`citation_invalid` 分别表示资料缺失、版本未保留或引用无法在该版核验 |
| `sourceMetadata`     | 相同版本资料的元数据路径，相对 ZIP 根目录；资料或版本缺失时为 `null`                                                                                                                                 |
| `metadataPath`       | 相同元数据文件的相对链接，供同目录 Markdown、HTML 和引用文件使用；资料或版本缺失时为 `null`                                                                                                          |

引用另记 `sourceVersionState`（`current`、`historical`、`unavailable`）、`availabilityReason` 和 `deletedAt`；`extractedText` 指向 ZIP 根目录内准确版本正文，`textPath` 是可读文件所在目录的相对正文链接。资料 ID、版本 ID 与片段归属均需匹配；手工摘录继续允许同一版中的选段和空白归一化匹配，不能用当前版补齐旧版摘录。

当前笔记目录链接使用 `../../sources/...`，笔记历史目录使用 `../../../../sources/...`。资料历史引用指向其 `versions/<版本ID>/source.json` 和 `extracted.txt`；准确版本已进入回收站仍可在备份内关联，所有可读引用同时显示删除警示。缺失或无法核验的引用保留完整标识和原话，但元数据、正文链接为空，不把现存的新版本当作历史证据。

## 笔记历史恢复与导出的区别

应用内恢复新历史快照时使用当时的标题、正文、引用、状态和 AI 标记。旧记录没有引用快照时恢复为空引用；知识页若也没有历史状态，恢复为待审核。恢复前保留当前内容，正文 revision 继续增加，并维持当前所属知识库。导出会保留历史 `spaceId` 和 `contentRevision` 供核对，不意味着恢复时会回退这些字段。整个 ZIP 可通过设置中的“恢复备份”导入为新增副本，操作、身份重映射与验证边界见 [备份恢复](BACKUP_RESTORE.md)。

## 未应用的本机审核草稿

知识页更新差异面板中的勾选和未应用改写作为本机审核草稿单独持久化，只有显示“已保存到本机”后，才确认可在同一浏览器、同一账号刷新后恢复；读取中、保存中或失败时不保证恢复最新修改。恢复受账号、知识页、任务、完整建议合同和当前有效性约束。本机审核草稿不云同步、不进入检索或问答，也不写入 ZIP 的 `workspace.json`、笔记阅读副本或其他归档文件，因此恢复 ZIP 不会恢复这些勾选和改写。

整理任务中原始的 AI 更新建议仍按工作区快照导出，本机审核草稿中的用户改写不会替换这些原始建议。应用后已经写入知识页的正文、引用、历史与审核记录按正常规则导出；已保存但仍待审核的知识页也继续包含在 ZIP 中。应用更新本身不会把待审核知识页自动变为已接受。

应用或忽略会清理对应建议的本机草稿，收起记录或任务、页面、依据失效会清理相关草稿；账号切换会清理离开账号的草稿，失败时可在界面重试。账号注销的缓存清理阻止旧标签页重新创建该账号草稿，这些本机生命周期操作不改变 ZIP 格式。完整恢复、清理和容量边界见 [资料整理](ORGANIZATION.md#本机审核草稿)。

## 文件原件与跨格式版本

PDF、DOCX、Markdown、TXT 的文件替换保留同一资料 ID 和每版独立格式、原文件名、原件、正文及片段。ZIP 对本次范围纳入的每份资料遍历当前版和全部保留的历史版本，包括没有引用的旧版；例如当前为 DOCX、历史为 PDF 时，两者分别导出自己的原件字节，不转换为当前格式。应用的文件替换与重复内容确认规则见 [FILE_VERSIONS.md](FILE_VERSIONS.md)。

| 版本   | 归档路径与内容                                                                                                                         |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 当前版 | `sources/<资料ID>/` 下保存 `metadata.json`、`extracted.txt`、`chunks.json`、可取得的原文件与 `original-status.txt`                     |
| 历史版 | `sources/<资料ID>/versions/<版本ID>/` 下保存 `source.json`、`extracted.txt`、`chunks.json`、该版可取得的原文件与 `original-status.txt` |
| 映射   | `source-mapping.json` 当前项及其 `versions` 数组记录确切版本、时间、元数据、原件路径和原件状态                                         |

原文件名会清理路径字符；若与 `metadata.json` 等备份保留文件名冲突，会加 `original-` 前缀。应按映射路径取原件。不同版本的同名文件位于独立目录，不互相覆盖。

导出先读取准确版本的本机原件，必要时通过当前账号的原件读取回调获取该版云端原件。某一版找不到原件、本机读取失败、云端下载失败或原件字节读取失败时，导出仍会继续处理其他版本；根目录 `export-issues.json` 和该版本的 `original-status.txt` 记录逐项原因，`README.txt` 标明备份不完整。本机读取发生异常时，账号和版本身份仍会再次核对，并仅回退到该账号下该版本的云端路径。进度逐版本显示 `sourceId`、`versionId`、当前／历史状态及读取、已包含、缺失或失败结果，之后显示 ZIP 构建阶段。缺失或无效版本不以当前正文、当前原件或相似文字回填。历史版本记录重复、缺失或无法安全解析等结构性错误会整体拒绝，不生成部分 ZIP。

文件历史阅读是只读核对，新 AI 检索仍只使用当前版。应用内可通过独立的恢复／清理影响预览处理保留历史版本，实际状态与边界见 [文件版本](FILE_VERSIONS.md)；导出本身不切换或清理版本。整个工作区或指定知识库 ZIP 均可经 [备份恢复](BACKUP_RESTORE.md) 导入为新增副本。

## 网页阅读快照

新导入网页的 `sources/<资料ID>/web-snapshot.json` 保留 `sourceId`、`versionId`、原始/最终网址、采集时间、采集方式、正文/选段/手动粘贴/仅链接范围及提取说明。`extractedText` 指向同目录的 `extracted.txt`，其中只包含用户实际保存的文字；`resources` 为空数组，未保存原站 HTML、外部图片或登录会话。

`source-mapping.json` 包含可空的 `webSnapshot` 路径和 `versions` 历史列表；后者逐项记录版本、时间、元数据、正文、片段、原件及其缺失说明路径。当前路径保持兼容，所有已保留旧版（包括没有引用的版本）分别位于 `sources/<资料ID>/versions/<版本ID>/`，保存 `source.json`、`extracted.txt`、`chunks.json`、有记录时的 `web-snapshot.json` 以及原件或 `original-status.txt`。旧版不存在元数据或原件时不使用当前版回填；重复或无效的版本记录明确导致导出失败，不静默覆盖文件。

旧资料未记录网页元数据时 `webSnapshot` 为 `null`，不伪造采集时间；仅链接的 `originalStatus` 明确无正文。同一网页资料可刷新与阅读历史；ZIP 恢复保留各版快照与引用，见 [备份恢复](BACKUP_RESTORE.md)。

## 对话与历史引用

`conversations.json` 保留本次范围内的原始对话，`conversation-mapping.json` 列出各会话与消息的可读 Markdown、安全 HTML、原始正文及元数据路径。逐消息目录 `conversations/<会话ID>/messages/<序号-消息ID>/` 始终含 `citations.json`，只保存原始资料引用；如该回答使用个人笔记，目录另含 `note-evidence.json`，其路径也在消息映射的 `noteEvidence` 字段中。双资料对照会话另在 `comparison` 元数据中保存左右资料与各自确切版本，恢复或打开时不把后来的当前版本当作原比较范围。旧问答依据按资料与版本指向对应历史正文，与笔记、关系两侧依据共用上述准确版本规则。

`note-evidence.json` 是个人笔记依据的历史快照，不是 `citations.json` 的替代或附加原文引用。每项保留原始问答 `spaceId`、`sourceId`、`sourceVersionId`、`noteId`、笔记 `revision` / `updatedAt`、块 ID、标题和摘录。该消息的 Markdown 与 HTML 在“我的笔记依据”下单独显示它们，并明确为用户的个人理解，不冒充原始资料。备份恢复会重映射其中的空间、资料、资料版本和笔记身份；资料随后更新、回收或彻底删除时，该快照仍可供历史说明，但不能令已失效资料再次参与新问答。

## 知识关系

`relations.json` 保存本次范围内已建立的关系（含已删除记录），`relation-mapping.json` 列出对应路径。整个工作区导出包含全部已建立关系；指定知识库仅包含关系自身归属该库的记录。未接受的 AI 关系提案仍在所含 `workspace.json` 整理任务中，不伪装成已建立关系。

每条关系位于 `relations/<关系ID>/`，包含安全 Markdown/HTML 阅读副本、`metadata.json` 和按 `from`、`to` 区分的 `citations.json`。两侧 `from/`、`to/` 子目录各保存关系记录时的 `snapshot.json`、Markdown、HTML、原始正文与引用。类型、方向、双方观点、适用条件、说明、AI/人工来源和删除状态均保留。

- `direction: from_before_to` 表示起点为终点的前置知识，其余三类为 `symmetric`；对称关系仍分别记录两侧说法。
- 关系 `availability` 为 `current`、`needs_review` 或 `deleted`。`current` 仅说明基线和原文依据可用，不证明观点成立。AI 来源不会因接受或人工编辑而变成原文事实。
- 端点 `availability` 为 `current`、`changed`、`deleted`、`missing` 或 `not_knowledge`；只有 `current` 才提供 `currentMetadata`。其他情况保留当时快照，不把当前页当作历史页面。
- 引用使用与笔记相同的版本保护和 `sourceAvailability` 规则。关系阅读副本与两侧快照中的引用路径分别指向相应归档目录；缺失或已换版资料不串绑。

## 格式保留范围

HTML 使用语法树解析和转换，Markdown 使用 GFM：标题、段落、粗体、斜体、删除线、嵌套有序／无序列表、起始序号、引用块、链接、行内代码、带语言信息的代码块、表格和普通换行可保留。代码中的反引号、文字中的 Markdown 标点和表格中的竖线由序列化器转义。

GFM 的表格行不能直接包含换行，因此单元格换行使用固定的 `<br>`。合并单元格展开为空白占位；没有表头的表格增加空表头，避免把第一行正文误当作表头。字体、颜色、下划线、上下标、列宽等排版信息不属于 Markdown 的保真范围；原始正文和工作区 JSON 保留这些编辑器数据。复杂嵌套表格会降级为文字。

现有笔记尚未存储独立的正文格式字段。以已知 HTML 元素开始的正文按富文本转换，其余旧笔记按 Markdown 解析。代码围栏中的 HTML 不会触发富文本格式识别；原始内容始终保留，便于精确恢复和以后迁移。

## 阅读副本与原始备份的边界

可读 HTML 和 Markdown 移除脚本、样式、内嵌页面等执行性内容，移除危险链接和事件属性，远程图片替换为替代文字，避免打开笔记自动请求图片。HTML 阅读副本另加限制资源加载的 CSP。引用原话作为文字转义，不作为 HTML 或 Markdown 指令执行。

`workspace.json`、`metadata.json`、`note-evidence.json` 和 `content.original.*.txt` 是数据备份，会保留原始内容，包括阅读副本清理掉的标记。不要将这些原始字段直接注入网页。导出本身不改变笔记、历史版本、引用、个人笔记证据或工作区状态。

转换采用 [rehype-remark](https://github.com/rehypejs/rehype-remark) 的 HTML → Markdown 语法树管线，并在转换前限制允许的元素、属性和 URL。
