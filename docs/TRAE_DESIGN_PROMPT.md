# Conuo｜TraeWork Design 页面设计提示词

提示词版本：1.2 · 2026-09-15。产品与技术基线：[当前 PRD](PRD.md)、[技术方案](TECH_STACK.md)；区域截图交互见[区域视觉学习](REGION_STUDY.md)。

本文件用于生成页面设计与可交互原型。覆盖桌面 Web、手机 iOS / Android、iPad 横屏 / 竖屏 / 窄分屏。**第一版开发仍然只做 Web**；手机和 iPad 首先是响应式 Web 设计，原生系统能力仅作为后续平台参考。

**当前存储决定：Web 必须登录，全部正式资料使用云端。** 浏览器只保留当前会话内存和必要认证 Cookie，刷新获取云端已确认资料；旧副本提供显式导入与备份恢复，不自动覆盖、去重或清空。只有后续 Windows／macOS 桌面版本地与云端共存，尚未开发；首版各视口都不能出现日常本机工作区或持久离线入口。详见 [Web 云端存储](WEB_CLOUD_STORAGE.md)。

## 使用方法

1. 进入 TraeWork 的 **Design** 模式，在输入框的设计风格菜单中选择 **设计系统 → TraeWork**。该操作路径依据[官方 Design 模式说明](https://docs.trae.cn/work_use-the-design-mode)。
2. 复制下方“完整提示词”代码块中的全部文字发送。如果当前环境支持附加文件，同时附上本项目 PRD；没有附件时，提示词本身已包含主要需求。
3. 先检查阅读工作台的代表屏，再沿用同一套组件扩展其他页面。一次生成受限时，按提示词末尾的批次继续，保持同一画布和设计系统。

官方将内置 **TraeWork** 描述为以浅色模式为主、结构清晰、适合平台型产品的设计系统。公开介绍未提供其完整主题参数；下文要求设计工具读取实际主题和组件，**不把自行指定的色值、字体、圆角或间距冒充官方规范**。参见[官方设计系统文档](https://docs.trae.cn/work_design-system)。

下文的页面编号、布局尺寸、示例资料及交互细化是本项目设计建议；商业套餐和配额等尚未确认事项，不因出现在原型中而成为产品承诺。

## 完整提示词

```text
请为 Conuo（中文名：可诺）设计一套可以指导开发的产品页面和可交互原型。使用我在 Design 模式中选择的内置 TraeWork 设计系统，覆盖桌面 Web、手机 iOS、手机 Android，以及 iPad 横屏、竖屏和窄分屏。

一、项目定位与交付边界

产品名：Conuo / 可诺。
品牌语：陪你把知识学会。
面向用户：中国学生、自学者，以及需要持续学习的职场用户。
产品定位：以个人资料库为基础的 AI 陪伴学习工作台。
核心价值：把收集到的文件、网页和笔记组织起来，在阅读时提问，通过可核对的引用理解内容，再把理解保存成自己的知识。

请围绕“收集资料 → 阅读与提问 → 核对原文 → 保存理解 → 下次接着学习”设计。界面以简体中文为主，使用真实、简短的产品文案；Conuo 品牌名保留英文。

开发范围已经确定：第一版只交付响应式 Web，功能和交互基本稳定后，再评估其他客户端。本次要求多设备设计覆盖，不代表同时开发原生应用。
- 桌面 Web：在 Windows、macOS 浏览器中使用同一产品界面，体现键盘快捷键等必要差异。
- 手机：提供适合 iOS Safari 和 Android Chrome 的响应式页面，补充系统习惯适配说明。
- iPad：提供浏览器中的横屏、竖屏和窄分屏布局。
- 原生分享扩展、真正的内置浏览器、Apple Pencil 手写等放入独立的“后续原生平台参考”画布分组；本地与云端共存和完整离线资料包只放在“后续桌面参考”分组。均不放进首版页面，也不生成安装或发布流程。

本轮产物是页面设计与交互原型。技术交接面向 React + Tailwind CSS + TypeScript、Next.js + TypeScript；已选 Supabase 数据库、Auth 与 Storage，部署 Vercel。不要在产品界面展示这些技术名，也不要因本次设计任务连接后端、创建云资源或执行部署。区域截图要求服务端配置的模型支持图像输入，原型中的模拟回答不代表真实模型已联调。

二、严格使用 TraeWork 设计系统

请先读取当前所选 TraeWork 系统实际可用的主题、组件、图标与说明，再设计页面。
1. 复用其颜色语义、字体层级、间距、圆角、边框、阴影、按钮、输入框、标签、导航、弹层和状态组件；在交付说明中列出实际使用的组件与 token 映射。
2. 以系统的浅色模式为主，保持清晰的页面结构、适度的信息密度、安静的阅读背景和明确的主要操作。
3. 使用 Conuo 的品牌名与内容；TraeWork 只作为设计系统，不把它的产品名称、Logo 或演示业务内容搬进 Conuo。
4. 品牌强调色从所选系统的真实主题中取值，用于主要按钮、选中项和关键焦点。状态色遵循系统语义，同时配合文字或图标说明。
5. 系统已有组件优先组合复用。确需新增的组件标注为“Conuo 扩展组件”，沿用系统主题，不把自定义值称为官方值。
6. 若工具无法读取该系统，明确列出缺失的主题或组件信息，将相应设计标为临时方案；不要声称已严格还原，也不要悄悄换成 TraeCode 或其他设计系统。

视觉方向：简洁、清楚、可信、有陪伴感。主要视觉重量留给资料、阅读正文和用户正在解决的问题。首页采用学习接续布局，避免营销首屏、大面积装饰渐变、无依据的数据图表和过多卡片。AI 陪伴感通过理解上下文、保留问题、支持继续学习表达，不需要在每条消息旁放机器人吉祥物。

阅读正文可先以 16–18 px、舒适行距和适中的行宽进行试排，再映射到实际主题；这是项目建议，不是对 TraeWork 官方字体参数的声明。大段正文、代码、公式和表格要有足够空间；长表格局部横向滚动，不让整个页面溢出。

三、功能范围与内容规则

所有首版画板是必须登录的云端工作台，包括手机和 iPad 浏览器。日常资料、笔记、历史、对话与阅读位置只有在云端确认后才算保存。浏览器可以保留当前页面输入和临时阅读内容，但刷新、关闭或退出后不承诺恢复；断网不能切换成本机工作区。后续桌面的本地数据库、文件缓存与云端共存只放在独立的“后续桌面参考”分组，不画成已可用功能。

首版必须设计：
- 必须登录的邮箱账号流程、注册／密码恢复、创建学习空间与空间切换；未登录不能进入日常资料库。
- 文件选择、桌面拖拽导入、公开文章链接导入、收件箱、标签与资料管理。
- 文本 PDF、DOCX、Markdown、TXT 和公开网页正文的阅读；PDF 保留页面阅读，其他格式可以使用规范化阅读版。
- 文本高亮、批注、继续阅读、当前空间搜索、AI 检索与带引用问答。
- PDF 当前页固定区域框选、截图预览，以及直接基于截图的“解读区域 / 针对区域提问 / 生成练习”。
- 自动摘要、标签和主题建议；用户选择资料后生成知识页草稿；由用户触发知识页增量更新建议。
- 基础笔记、对话记录、待解决问题、云端保存状态、同步冲突处理、导出、回收站和删除影响预览。

处理边界必须在设计中成立：
- 文件上传保存、文本识别整理、建立检索、可用于 AI 是不同阶段，不把“上传成功”直接显示成“AI 已读完”。界面可用更易懂的“正在提取文本”“正在准备检索”等文案。
- 扫描 PDF 在首版可保存和预览。没有可提取文本时，清楚提示“正文暂不可检索，可框选区域问 AI”；用户可以明确发送当前页截图进行区域学习，但不能把它描述成整份资料已读完或已建立全文索引。不出现首版可用的 OCR 按钮。
- 区域学习流程固定为“框选 → 截图预览 → 选择学习方式 → 明确发送 → 查看结果”，不加入先识别文字才能继续的步骤。文字转写仅作为模型可选结果；公式、图表或无文字区域也能直接解读、提问与出题。
- PNG / JPG OCR、PPTX、EPUB、后台持续知识页整理和全库搜索属于后续 Web 完善；完整练习作答、回顾、关系图、音频和联网补充属于更后续阶段。区域生成的一次性练习不等于完整练习系统，首版主导航不预留一排不可用按钮。
- 自动分析只在用户启用 AI、资料允许 AI 使用、开启自动整理且额度允许时运行。关闭这些能力不影响已保存原文的阅读与可用文本的关键词搜索。
- AI 建议可以接受、编辑、忽略和撤回；用户固定的名称与标签不能被自动覆盖。
- 跨资料知识页先生成草稿，未接受的草稿不作为新问答证据。增量建议只应用用户选择的部分，保留用户原文和旧版本。
- AI 默认使用明确显示的资料范围，不暗中扩展到所有空间或联网。区分来源事实、用户理解和 AI 推断。
- 当前 Web 使用邮箱与密码登录，提供注册和忘记密码；必须先登录，再进入个人云端资料库。没有“本机工作区”“匿名使用”“离线模式”入口，不加入未确认的第三方登录品牌。
- 不设计已售卖的会员套餐、价格、无限额度或学习效果承诺。用量可用明确标记的演示值或占位配置展示。

四、信息架构与导航

桌面 Web：
- 左侧主导航：Conuo 品牌、首页、收件箱、学习空间列表、新建空间；底部头像与设置。
- 进入空间后，在内容区提供“概览 / 资料 / 知识 / 问答”切换，避免同时堆叠多层常驻侧栏。
- 顶部显示当前位置与当前学习空间；搜索在空间上下文中使用，明确标注“搜索当前空间”。
- 阅读页面进入专注工作台，导航可以收起，主要空间用于原文与 AI 对话。

手机 iOS / Android：
- 应用内底部导航：首页、资料、知识、问答。
- 顶部提供当前空间切换；收件箱从资料页进入；设置从头像进入。
- 阅读模式收起全局底部导航，使用精简阅读工具栏与“问 AI”入口，避免与系统栏、浏览器栏、输入框叠在一起。
- 搜索和批量选择进入独立任务状态；次要操作放入菜单或底部操作面板，主要动作始终可找到。

iPad：
- 保留同一信息架构，按可用窗口宽度决定侧栏、列表、正文和 AI 面板的组合。
- 横屏阅读优先原文与 AI 并排，主导航可收起。竖屏优先正文，AI 可切换面板。窄分屏使用单栏导航与返回路径。
- 空间、选中文档、阅读位置、问题草稿和对话上下文在布局变化时连续保留。

五、画板与响应式要求

以下是逻辑画板 / CSS 布局测试尺寸，不是硬件规格，也不是 TraeWork 官方断点：
- Web 主画板：1440 × 1024；紧凑桌面验证：1280 × 800。
- 手机 iOS 主画板：390 × 844；补充 360 px 窄屏验证。
- 手机 Android 主画板：412 × 915。
- iPad 竖屏：834 × 1194；横屏：1194 × 834；补充约 600 px 宽的窄窗口验证。

布局建议：宽屏可显示导航、主要内容、辅助面板；中等宽度收起次要导航并在需要时打开辅助面板；窄屏以单任务单栏为主。可从 1280 px、768 px 两个项目断点开始验证，再根据内容修正，不按设备名称硬编码布局。

建议桌面导航约 220–240 px，AI 面板约 340–400 px，可拖拽调整并设置合理最小宽度；都以阅读区域实际可用为前提。iPad 横屏不强行塞入“主导航 + 章节目录 + PDF + AI”四栏。手机上的文档表格改成信息分层的列表项，不能整体缩小桌面表格。

覆盖固定 / 流动宽度、滚动容器、吸顶工具栏、软键盘出现、浏览器可视区域变化、超长文件名和空状态。触控目标以至少约 44 CSS px 为项目设计目标，并提供适当间距；不要将这个值描述为所有系统统一的官方规范。

六、页面设计清单

P00｜登录、恢复与首次创建空间
目标：让用户尽快开始一次有资料依据的学习。
- 简洁品牌区、邮箱／密码登录、注册和忘记密码，分别设计认证错误、会话失效与重新登录。主说明“登录后，在不同设备继续学习你的云端资料”；主按钮“登录”。
- 登录后创建学习空间：名称必填，学习目标可跳过。
- 下一步明确给出“上传文件”“导入链接”“创建笔记”。示例资料作为独立的“体验示例空间”，不混入用户私人资料。
- 重新登录或刷新后只恢复云端已确认资料与位置。当前页面未发送输入、临时审核勾选和未确认编辑只在同页内存保留，不能承诺刷新或关闭后恢复。首次读取失败展示连接失败页与“重新连接”，不能伪装成空资料库。
- 桌面内容宽度克制；手机表单适应键盘；iPad 使用阅读舒适的居中区域。
- 登录成功后的云端首次读取失败单独设计：“暂时无法连接云端资料库。你的云端资料未被修改，请重新连接。”按钮“重新连接”和账号管理入口；不展示“开始本地使用”，也不把失败画成“你还没有资料”。

P01｜首页 / 继续学习
目标：让用户知道从哪里继续，而不是浏览一屏统计数字。
- 首要模块“继续学习”：展示最近资料、所属空间、上次阅读位置、最近留下的问题；主要按钮“继续阅读”。
- 次要模块：最近学习空间、最近资料、待解决问题；入口“新建空间”“导入资料”。
- 用平实文案表达接续，例如“上次读到第 12 页”“继续讨论学习率”。不推断用户情绪，也不声称已经掌握知识。
- 无学习记录时，展示一个清晰的开始入口和三种导入 / 创建方式。
- 手机纵向排列，首屏突出一项继续任务；iPad 可用主次两区，避免填充无意义卡片。

P02｜学习空间概览、资料库与收件箱
目标：找到资料，了解处理状态，完成归类。
- 空间概览包含名称、可编辑目标、最近资料与待处理建议，支持重命名和归档。
- 资料区提供列表 / 合适的网格视图、类型与标签筛选、排序、搜索入口、导入按钮。
- 列表展示文件名、类型、标签、阅读状态、AI 可用状态、更新时间；大小、来源和更多时间信息可收进详情。
- 收件箱展示尚未关联空间的资料，支持批量关联空间、添加标签和移入回收站。
- 单份资料可关联多个空间；“移出当前空间”和“移入回收站”是不同动作，分别说明影响。
- 批量操作明确显示已选数量和逐项失败结果。长文件名可展开查看完整名称。
- 手机使用文件行与选择模式，不复制拥挤表头；iPad 中等宽度可用列表与详情二栏。

P03｜上传文件、导入链接与处理任务
目标：每项资料是否保存、是否可读、是否可提问都能看清。
- 文件导入：选择目标空间、文件选择 / 桌面拖拽区、支持格式提示、单项校验、提交与取消。
- 链接导入：输入 URL → 获取预览 → 展示标题、最终来源地址与采集时间 → 选择保存可提取正文 / 选段或仅收藏链接。
- “打开原站”在 Web 中打开浏览器页面；不承诺在应用内嵌入所有网站，不将已打开页面自动收集到知识库。
- 批量进度逐项展示：等待上传、正在上传、原文件已保存、正在提取文本、正在准备检索、可用于 AI、部分可用、失败。
- 处理失败仍能查看已经保存的原文件；重试与取消按项操作。一项失败不挡住其他成功项。
- 相同内容：显示已有资料并选择复用或保留副本。同名不同内容：独立保留，不静默覆盖；替换版本是明确的独立操作。
- 网页只保存链接、正文提取不完整、登录后文章无法获取时，说明限制并给出可行下一步，不伪装成全文导入成功。
- 上传额度不足时保留现有资料与阅读、导出入口，不把界面变成付费墙。
- 手机用系统文件选择器与单栏任务列表；不要画自制系统文件选择器冒充操作系统界面。

P04｜阅读与 AI 问答工作台：最重要的代表页面
目标：阅读原文和理解问题可以自然往返。
- 顶栏：返回资料、文件名、所属空间、保存状态、搜索文内、更多操作。
- 阅读区：PDF 页码和缩放 / 其他格式的章节与字号、正文、清楚的文本选择、高亮与批注定位。
- 选段浮动工具：高亮、记笔记、问 AI；选段提问前展示选中的文本与“选段及所属文档上下文”范围说明。
- PDF 工具栏提供“框选区域”，只能选择当前显示的物理页；进入框选后暂停普通文字选择，支持正向 / 反向拖动、取消和重新框选。范围随页面缩放保持一致，不能跨页或截取系统其他应用。
- 确认区域后展示真实截图预览、文件名和物理页码，再选择“解读区域”“针对区域提问”或“生成练习”；提问方式提供问题输入框，问题为空时不能发送。
- 拖动和预览不自动调用 AI。发送前明确说明只临时上传当前截图，截图默认不保存到资料库；模型未就绪、AI 关闭、资料不允许 AI、原件不可用时显示具体原因和可行下一步。
- 区域结果显示当次页码和框选范围，并提供重新框选与复制结果。出题结果先展示题目，由用户逐题展开答案和解析；可选文字转写收在折叠区，不占据解读的主要位置。结果绑定发送时的资料和版本，不替代普通原文引用，也不宣称看过区域外内容。
- AI 区：对话标题、来源范围选择、消息正文、引用、输入框、停止 / 重试、保存到笔记或知识页。
- 范围选项：当前选段及文档上下文、当前文档、选定资料、当前空间。默认与入口上下文一致；范围变化后不把旧范围内容当成隐藏证据。
- 回答以解释问题为主，来源事实有可点击的文件名与页码 / 章节；推断单独说明。证据不足时直接说明缺口。
- 点击引用展示原文片段并定位到对应版本的原文，高亮匹配位置；关闭引用后恢复阅读位置、对话滚动和未发送问题。
- 支持把问题保存为“待解决”；是否已解决由用户标记，不因生成回答而自动完成。
- 桌面：原文与 AI 并排，AI 可收起；目录与主导航按需打开。
- 手机：默认单栏阅读，“问 AI”先打开易于发现的面板，持续对话和键盘输入时可进入全高对话；引用打开原文预览 / 定位页，并提供“返回刚才的回答”。
- iPad：横屏原文与 AI 双栏，竖屏可切换或展开辅助面板，窄分屏单栏。布局变化保持选段和输入内容。
- 区域学习适配：桌面使用截图预览与学习结果并排的弹层；手机使用全高单栏，预览、方式选择、问题与结果纵向排列，发送和关闭入口可达；iPad 横屏可并排，竖屏 / 窄分屏按宽度重组。触控框选要与页面滚动区分，先进入明确的框选模式。

P05｜空间内搜索与检索结果
目标：快速找到依据，并清楚地区分找到的内容与 AI 生成内容。
- 搜索框明确显示当前空间；支持标题、标签、正文、笔记和知识页检索。
- 提供类型、标签、时间筛选，结果含文件名、匹配片段、页码 / 章节和来源类型。
- 自然语言检索返回资料结果；“根据这些资料提问”作为显式动作，AI 回答与结果列表在视觉上分开。
- 资料关闭 AI 时，可用的普通关键词结果仍可查看；需要 AI 的动作说明不可用原因。
- 区分无匹配、相关资料尚未处理、服务错误。无匹配给出改词或调整筛选建议，首版不自动搜索所有空间。
- 桌面可打开侧边片段预览；手机逐项展开或进入详情，返回时保留查询、筛选和滚动位置。

P06｜知识库列表与主题知识页
目标：看懂资料整理出了什么，并能回到依据。
- 列表按主题组织，展示标题、简短摘要、关联资料数量、更新时间、已保存 / AI 草稿状态；支持筛选与搜索。
- 主操作“从资料生成知识页”：先选择资料，展示范围，再生成可审核草稿。
- 主题页结构：概念说明、关键要点、例子、前置知识、关联概念、不同观点、来源清单。内容短时自然合并，不强制填满所有区块。
- 来源引用可回到原文；用户笔记、已接受的 AI 内容和未接受草稿可辨认，接受保存不等于系统已证明内容正确。
- 对有冲突的资料并列呈现观点与各自适用条件，不强行合并成一个结论。
- 主操作编辑 / 保存，次要操作查看来源、关联资料、版本历史。
- 使用清楚的列表与内容页，首版不以大规模关系图作为入口。
- 手机保持单栏可读；iPad 根据宽度显示知识列表与正文，或正文与来源面板。

P07｜AI 归类建议与知识更新审核
目标：减少整理负担，让用户能够决定每一次修改。
- 分两类任务：资料摘要 / 标签 / 主题建议，知识页内容草稿 / 增量更新建议。
- 资料建议显示建议内容、依据及受影响资料。用户固定标签展示“已固定”，AI 不覆盖它。
- 支持接受、编辑后接受、忽略、撤回最近一次批量操作；批量结果显示实际成功 / 失败项。
- 知识页增量展示“当前内容 / 建议内容 / 来源依据”，可逐段选择接受；手机用可切换的上下结构，避免把两列缩成难读小字。
- 如果生成建议后用户改过正文，显示“原文已更新，请重新生成或合并”，保留人工内容，不直接覆盖。
- 未接受草稿在列表有清楚标识，不显示成正式知识事实，不参与后续问答。
- 自动整理关闭或额度不足时说明本次未生成原因，并保留手动管理入口。

P08｜笔记编辑与摘录保存
目标：让用户把自己的理解留在资料上下文里。
- 支持标题、段落、列表、链接、代码块、基础表格；不扩展成完整办公套件。
- 摘录 / AI 回答保存到新笔记或既有知识页时，保留原始来源、位置、版本与 AI 生成标记。
- 用户可以编辑保存的副本，不因此改写原对话。
- 保存状态与版本历史可见；断网或冲突时保留当前页面输入，提供云端重试与导出。明确“修改暂存在当前页面，尚未保存到云端；请勿刷新或关闭”，没有本地持久保存承诺。
- 桌面工具栏简洁；手机提供适合键盘上方的常用格式工具与可展开菜单；iPad 支持触控与键盘操作。

P09｜空间问答历史与待解决问题
目标：延续之前的学习过程。
- 显示当前空间内的对话列表、标题、最后讨论时间、关联资料，以及“全部 / 待解决 / 已解决”筛选。
- 待解决问题展示问题文字、来源片段与最近讨论，支持继续讨论、打开原文和由用户标记解决。
- 打开历史回答仍显示当时的资料范围与来源状态；继续提问时检查当前有效资料范围。
- 来源失效的历史回答可以保留，但失效引用必须可见，不能作为仍然可用的原文入口。
- 桌面可用列表与对话二栏；手机先列表再详情，并保留返回上下文；iPad 宽度允许时同时展示。

P10｜设置、云端保存、导出与回收站
目标：用户能控制资料的处理方式，并找回自己的内容。
- 设置按账号、AI 与资料处理、云端资料与存储、阅读与保存状态分组。日常存储只显示当前账号云端，不提供本机空间切换、离线编辑、缓存资料库或保留本地草稿退出。
- AI 首次启用说明处理范围；资料级 AI 开关和自动整理开关可找到。关闭 AI 后原文仍可阅读，已有文字可在权限范围内关键词搜索。
- 存储展示组成与占用；示例值只作为演示，不承诺固定免费容量、保留天数或商业套餐。
- 同步详情展示对象、状态、失败原因与重试入口；发生笔记冲突时支持查看双方版本、选择保留或合并。
- 导出可选择空间与内容，展示原文件、网页快照、笔记 / 知识页、对话 / 批注和来源清单，提供进度、完成与部分失败状态。
- 回收站展示删除资料、恢复入口及永久删除操作。普通删除与彻底删除的影响分别说明；用户保存的笔记不会悄悄连带消失。
- 删除空间与注销账号先给具体影响预览，确认动作使用明确文案。退出前若有未确认修改，只提供完成云端保存或导出备份后再退出；未完成时明确原因，不提供保留本地草稿退出。切换账号不得展示前一账号的临时内容。
- 这些功能可以作为 P10 下的子页 / 弹层，不要求塞进同一屏。
- 旧版本副本只作为迁移卡片：“发现旧版本保存在此浏览器的资料”。提供“查看并导入旧资料”和“导出旧副本”，不要求退出当前账号再进入本机日常工作区。代表场景为旧副本有 7 份资料、1 篇笔记，当前账号已有云端资料。
- 迁移预览明确显示当前目标账号、资料／笔记／历史数量、可恢复和缺失原件：“将这些旧资料恢复为当前账号中的新增副本，现有资料和旧副本都会保留；不会自动去重。”主按钮“确认导入为新增副本”，取消不会写入云端。新增资料默认不授权 AI，缺失原件须明确接受限制。
- 迁移中展示“正在上传原件并保存到云端”；云端确认后显示“旧资料已加入当前账号”。失败说明“云端尚未确认导入，旧副本仍保留，请重新连接后核对”，保留同一确认计划重试，不显示本机保存成功或自动删除旧副本。

P11｜资料详情、标签与已识别内容
目标：让用户理解某份资料为何可检索、可用于哪些问题，并能纠正归类。
- 详情展示文件名、类型、来源地址 / 原文件、导入时间、资料版本、关联空间、标签、AI 可用状态与可识别范围。
- 标签区区分手动标签、已固定标签、AI 建议，支持修改和撤销。
- “查看已识别内容”以标题、正文片段、页码 / 章节和对应标签呈现，展示检索能够使用的原文范围；点击片段回到原文。
- 部分解析只成功的页 / 章节清楚可见，失败区域也可找到。界面不展示 chunk ID、embedding、向量维度或内部任务日志。
- 更正标签、AI 使用开关和重试处理分别操作。重试不会凭空更换原始资料版本。
- 桌面可用详情侧栏与完整详情页；手机为独立详情页；iPad 可在列表旁展开。

七、各系统适配细节

A. Windows / macOS 桌面浏览器
- 保持同一 Web 导航与组件，提供 hover、focus、pressed、disabled 状态，所有主要任务有键盘路径。
- 搜索等快捷键按系统显示 Ctrl 或 ⌘；若与浏览器冲突，采用不冲突的方案并在交接中注明。
- 支持桌面拖拽导入，但文件选择按钮始终存在。
- PDF / 正文和 AI 区分别滚动，边界清楚；拖动分栏时不挤压到不可用宽度。
- 弹层关闭后焦点返回触发控件；阅读位置不因打开侧栏或切换页签而丢失。

B. iOS 手机浏览器
- 内容、应用工具栏与键盘避开安全区域及浏览器动态栏，使用实际可视区域适配。
- 返回入口明确，系统返回手势不承担唯一导航职责；底部操作面板关闭后回到原任务。
- 文本选择、长按与应用高亮工具不互相抢占；保持系统文本选择可用。
- 原型重点展示阅读 → 问 AI → 弹出键盘 → 点击引用 → 返回对话的连续过程。
- 首版“上传文件”调用系统文件选择；系统分享扩展和原生通知留在后续原生参考分组，本地资料与离线下载管理只在后续桌面参考中设计。

C. Android 手机浏览器
- 复用相同的 Conuo / TraeWork 视觉系统，针对系统返回、文件选择、键盘和底部手势区域给出适配说明。
- 返回顺序优先退出当前临时状态，如键盘 / 操作面板 / 搜索模式，再回上一产品页面；不要让一次返回误退出整个学习过程。
- 操作不依赖 hover；长按批量选择同时提供显式菜单入口。
- 单独提供导入、阅读对话、引用返回、键盘展开等差异画板；其余页面注明与手机共享组件和响应式规则，避免另造一套无关视觉风格。

D. iPad 浏览器
- 横屏重点：原文和 AI 对话并排，辅助导航可收起；可拖拽但有最小宽度限制。
- 竖屏重点：以阅读正文为主，目录、来源和 AI 采用可切换区域或面板，避免四栏压缩。
- 窄分屏重点：根据实际容器宽度退为单栏，所有主要任务仍可完成，不要求先退出分屏。
- 兼容触摸、指针与外接键盘；所有指针快捷行为都有触控等价操作。
- 横竖屏或窗口宽度变化后，保留阅读页码、选段、批注、对话滚动与未发送内容。
- Apple Pencil 手写仅在“后续原生平台参考”说明如何与原文关联，不把 OCR 成功当成笔迹保存成功，也不把它加入首版验收。

以上系统差异写在画布注释和交接说明中。用户界面只呈现自然的产品操作，不出现“这里兼容 iOS”“后端使用 Supabase”等实现说明。

八、必须展示的状态与恢复路径

请建立可复用状态组件，并将以下状态挂到相应页面，而不是只输出顺利完成的静态页面：
S01 空空间 / 空资料库：上传文件、导入链接、创建笔记三个入口。
S02 页面与内容加载：骨架屏或明确等待状态，不用虚假正文和假进度。
S03 同批资料状态不同：已保存、处理中、可用于 AI、失败可以同时出现。
S04 部分解析成功：展示可用范围，问答说明覆盖不完整。
S05 扫描 PDF 无文本 / 格式不支持 / 损坏文件：保留可保存的原文件，分别给出下一步。无文本扫描 PDF 可使用区域视觉学习；不可读取的原页不能生成截图。
S06 重复内容和同名不同内容：复用、保留副本、明确替换有不同结果。
S07 AI 正在生成 / 用户停止：保留已生成部分并标明已停止，输入与原问题可恢复。
S08 AI 超时 / 检索失败：区分原因，重试保留问题与实际范围。
S09 资料证据不足与相关部分未解析：不同说明，不用同一句“没有答案”掩盖差异。
S10 引用可精确定位 / 只能定位到页或章节 / 旧版本 / 已删除 / 版本不可用：分别展示，不让旧引用跳到新版不同内容。
S11 AI 标签建议 / 手动固定字段 / 接受与撤回：状态与操作反馈明确。
S12 AI 草稿 / 增量建议 / 正文已变化：支持选择接受、编辑或重新生成。
S13 当前页面暂存 / 正在保存 / 云端已确认 / 保存失败：服务确认前不能显示已保存；当前页面暂存不能叫“已保存在此设备”，刷新或关闭可能丢失未确认修改。
S14 两个浏览器会话修改同一笔记：保留双方内容，差异查看与合并路径可操作。
S15 AI 关闭 / 额度不足：阅读、可用文字关键词搜索、导出仍可进入。
S16 手机软键盘展开 / iPad 窄分屏：发送、返回、关闭和正文访问不被遮挡，草稿不丢失。
S17 导出部分失败 / 移入回收站 / 恢复 / 永久删除：展示对象、结果和真实影响。
S18 未登录 / 会话失效 / 无权限或资料不存在：未登录展示登录页；认证失效暂停私有访问并重新登录，不泄露其他账号内容。
S19 区域视觉学习：框选中、截图编码中、预览、模型状态检查、未就绪、发送中、失败、解读 / 问答 / 练习结果分别设计；无文字转写仍可显示有效结果。切换账号、资料或版本以及失去 AI 权限时丢弃旧截图，旧请求不能发布到新上下文。
S20 云端首次读取失败 / 保存中断：首次读取失败阻止编辑并提供“重新连接”；保存中断保留当前页面输入与导出入口，说明尚未云端确认，不提供本地降级。
S21 旧副本迁移：发现、只读预览、取消、缺失原件确认、上传与保存、云端确认、失败与同计划重试分别设计；保留旧副本与账号原内容，不自动去重。

状态文案示例：
- “原文件已保存，正在提取文本。”
- “已识别 42 / 48 页。部分内容暂时无法用于回答。”
- “这份 PDF 暂未识别到可用文本，你仍可查看原文件。”
- “当前资料中没有找到足够依据。”
- “相关章节尚未解析完成，暂时无法核对这个问题。”
- “这条引用来自旧版本。” / “来源资料已删除。”
- “正在保存到云端…” / “修改暂存在当前页面，尚未保存到云端，请勿刷新或关闭” / “已保存到云端”。

这些示例只在对应模拟状态成立时使用。原型可以切换场景，但不能将所有失败状态叠在一个正常页面上。

九、统一示例内容

十一、交互原型与验收

至少连通以下流程，并确保返回路径、所选空间、阅读位置和输入草稿保留：
F01 登录 → 创建空间 → 上传文本 PDF → 分项处理完成 → 阅读 → 选段提问 → 点击引用 → 保存到笔记。
F02 导入网页 → 查看提取预览 → 保存正文或仅收藏链接 → 查看详情与已识别内容。
F03 收件箱多选 → 关联空间 → 审核标签建议 → 接受 → 撤回；固定标签保持不变。
F04 选定资料 → 生成知识页草稿 → 查看依据 → 编辑或接受部分内容 → 打开已保存知识页。
F05 新资料加入 → 手动生成增量建议 → 查看差异 → 仅接受所选段落；原文已更新时进入合并 / 重生成路径。
F06 首页继续阅读 → 打开待解决问题 → 继续讨论 → 用户标记已解决。
F07 手机阅读 → 打开 AI → 键盘输入 → 查看引用原文 → 返回回答；iPad 横屏切竖屏 / 窄分屏后继续同一任务。
F08 保存异常或冲突 → 查看详情 → 保留 / 合并版本 → 云端确认；删除资料后历史引用显示失效。
F09 打开扫描 PDF → 进入框选模式 → 选择当前页固定区域 → 确认截图预览 → 分别解读、针对区域提问或生成练习 → 展开答案 / 复制结果。覆盖手机触控与 iPad 横竖屏，发送前取消不产生模型请求。
F10 未登录打开 Web → 登录 → 云端读取失败 → 重新连接 → 读取真实资料库；保存中断时显示当前页暂存与重试／导出，刷新只恢复云端已确认内容。
F11 当前账号已有资料 → 查看旧副本 7 份资料／1 篇笔记 → 核对新增副本预览 → 确认上传与保存 → 云端确认后查看新增资料；无需退出账号，失败不自动清空任何副本。
```
