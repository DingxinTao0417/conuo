# Markdown 选段与原文映射

更新日期：2026-09-14。本文记录 P20 的 Web 阅读器原文映射，并补充 P21 的批注位置合同。Markdown 排版后的文字与保留原文分别处理，选段不会通过删除格式符号后猜测来源。P20 已完成的检查按当时范围保留；P21 的验证仍在收尾，见[批注原文位置](ANNOTATION_POSITIONS.md)和[开发状态](IMPLEMENTATION_STATUS.md)。本功能不扩大云端或模型验收结论。

## 显示文字与原始依据

例如原文 `学习 **梯度下降** 的步骤。` 显示为“学习 梯度下降 的步骤。”。用户跨粗体选中整句后，阅读器同时保留：

- `rawQuote`：从确切 `Source.text` 取出的连续原文，包含选区内的 Markdown 语法。
- `visibleQuote`：用户实际选中的显示文字，用于预览和复制。
- 原文范围及当前 source/version；可证明索引覆盖时，另保留对应的 chunk 标识。P21 的新批注另以 `textAnchor` 持久保存已证明的 UTF-16 原文范围；它不改变引用的 chunk 合同。

原文范围只取所选首尾可见字符在源文件中的连续区间，不人为补齐格式。例如从粗体内部开始选择，原话可以是 `度下降** 的步骤。`；它仍是准确的原文子串。显示预览基于完整来源 AST 中的对应范围生成，不能把这段不完整语法重新解析后产生的文字当作来源。选段问答预览在显示文字与原文不同的情况下提供“查看原文格式”。

| 操作       | 保存或发送的依据                                                                      | 显示方式及限制                                                         |
| ---------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 复制       | 不修改资料或引用；写入剪贴板的是显示文字                                              | 保留用户看到的文字，不复制隐藏的格式标记                               |
| 选段问答   | `selection` 使用连续原话，以选段问答 scope 连同确切 source/version 发送               | 预览显示可见文字；沿用当前问答的权限、版本和解析状态检查               |
| 高亮／批注 | `Annotation.quote` 保存原话，绑定 source/version；新批注以 `textAnchor` 保存准确范围  | 编辑与已保存预览显示可见文字；定位核验锚点原话与当前 DOM，不猜重复位置 |
| 存笔记     | 正文包含原话；引用逐项使用对应片段的完整 `chunk.text`，保留 source/version/chunk 身份 | 选区覆盖多个可证明的片段时可保留多个完整引用；没有可证明引用时拒绝保存 |
| 存知识页   | 手工摘录使用原话，能定位单块时提供准确 `anchorChunkId`，领域层再次核验                | 沿用单块锚定合同；跨片段选区需缩小，不通过拼接引用绕过校验             |

引用中的 `quote` 始终是对应的完整原文块，而不是以显示文字或任意选段替换 `chunk.text`。例如第二处相同句子位于另一章节时，当前 DOM 定位可将笔记引用和知识摘录锚定到第二个真实片段；引用可继续按保存版本核验，不引用第一处的相似文字。

## 如何证明选区属于原文

`lib/markdown-excerpt.ts` 使用与阅读器相同的 Markdown/GFM 解析规则，将可见文字投影到原文 UTF-16 范围。格式标记和链接目标不贡献显示文字；转义、实体、行内代码、代码块、段落及列表等按解析节点核对，无法确认的内容成为不能跨越的屏障。实体对应的原文范围是原子的，不能只选择一个解码实体的一部分就猜测原文切点。

`components/markdown-selection.tsx` 给生产 Markdown 正文块附加 AST 原文范围；Reader 的 Markdown 正文容器另有 `0..source.text.length` 范围及 source/version 标识。因此同一正文内跨两个段落的原生 `Range` 可使用整个正文容器作为定位范围，不必截断到第一段。读取选区前核对正文身份、选区首尾是否都在该范围内，以及保留 DOM 文字和来源投影是否一致；图片占位、按钮与隐藏界面文字不被当作原文。确认后，用选区前的 DOM 文字长度定位当前块中的准确可见偏移，再映射回连续原文。

有准确 DOM 范围和偏移时，重复句子可按用户当前选择的位置定位；提供的偏移不一致时直接拒绝，不回退到全文第一处匹配。没有可信位置的直接映射请求遇到重复文字也会拒绝。索引片段必须属于当前 source/version；完整、有序覆盖可证明重复块的实际位置，部分或旧缓存只接受能独立证明位置的唯一原文块。

跨段、跨片段问答与标注可使用已证明属于该正文的连续原话，不受知识页单块合同限制。如果选区中有未索引的非空白正文，映射可以保留准确原话，但不会伪造一组片段来宣称完整证据覆盖；存笔记与知识页仍分别检查其所需引用。阅读器选段及原文长度上限沿用 6000 字符，超限提示缩小范围，不静默截断 Markdown 原话。

## 保守拒绝与批注位置兼容

资料标题、问答输出或正文外的选区、不同 source/version 的 DOM、范围或偏移不合法、DOM 与来源投影不同、图片／HTML／未知节点屏障、无法原子映射的实体及无法可靠核对的语法都会被拒绝或提示缩小选区。知识摘录还会拒绝跨块、失效锚点或没有可证明片段的选段。此实现不声称所有 Markdown 扩展、自定义排版或图片文字都可映射。

**P20 当时的局限：已保存批注只有原话和版本，没有持久 offset。** 当时的首次匹配使重复批注的高亮和“定位”可能落到第一处，准确识别新选段或第二个 chunk 不能证明保存后的批注也已消歧。

P21 为新批注加入 `textAnchor`，按准确原文切片与可证明的 DOM 范围定位第二处重复文字；点击使用独立批注 focus，不为 `Citation` 添加位置字段。旧无锚点批注保持可读，只在对应原文范围中的原话唯一时兼容定位，重复或不能核对时提示位置不足，不猜第一处。`markdownQuoteText` 的首次匹配仅提供显示候选，不能用它证明批注位置。范围、UTF-16 边界、历史版本与恢复规则见[批注原文位置](ANNOTATION_POSITIONS.md)。
