# 文件替换与版本记录

Conuo 的 Web 阅读器已支持将 PDF、DOCX、Markdown（`.md` / `.markdown`）或 TXT 文件明确替换为同一资料的新版本，四类格式之间可以互换。网页资料使用独立的[预览与刷新流程](WEB_IMPORT.md)，不通过文件替换改成网页。

## 操作流程

1. 打开资料的当前版本，点击“替换文件”，选择一个文件。此时只在浏览器中解析和计算 SHA-256，不保存原件，也不改变现有资料。
2. 核对新文件名、格式、大小、解析状态、正文片段，以及 PDF 的解析页数。资料名称、标签、所属知识库、收藏状态和 AI 权限保持不变，新版本的原文件名改为所选文件名。
3. 点击“保存为新版本”。应用确认原件字节与预览一致，并保存原件后，再核验账号、资料、预期版本、归属与工作区容量，归档原来的当前内容并发布新版本。
4. 在“资料版本记录”查看各版日期、文件名与格式，打开确切历史版本或返回当前版。留意工作台的本机保存与云端同步状态；确认换版不等于云端同步完成。
5. 需要回到旧内容时，在历史版本旁选择“恢复为当前”。确认界面会列出版本时间、标识和内容范围；确认后直接提升这个确切版本，并把操作前的当前版归档。其他历史不变，不需要重新上传或解析已经保留的原件。
6. 登录并等待同步完成后，可在历史版本旁选择“清理此版本”。系统先展示服务端计算的影响，再要求输入“清理”确认；它绝不适用于当前版本。

选择与当前版本 SHA-256 相同的文件通常会被拒绝，不创建重复版本；可取消、选择另一个文件或查看历史。若当前版已明确标为 `originalMissing: true`，允许重新选择同哈希原文件，校验后保存成新版本，以补回可用原件。旧版仍保留缺失标记，不宣称原来的历史原件已找回。若内容与某个保留的历史版本相同，用户需明确勾选恢复确认，才会将这份重新选择并解析的文件保存为一个新的当前版本。此操作不会删除中间版本，也不是直接回退版本指针。

直接恢复与重新选择原件是两种不同操作。直接恢复沿用历史版原有的 `versionId`、片段和原件位置，刚才的当前版以自身身份进入历史；恢复前后版本总数不增长，往返恢复也不会产生重复身份。资料名称、标签、知识库归属、收藏和 AI 权限继续使用操作时的当前值，阅读页码与滚动位置会重置。若当前版或目标旧版仍在解析、资料已进入回收站、目标记录缺失，或当前版本已被另一会话改变，整个操作会拒绝且不修改工作区。

### 单独清理历史版本

“清理此版本”由云端事务执行：确认指纹必须匹配当前工作区 revision 和服务器重新计算的影响。事务从资料版本记录、规范化版本/片段/向量任务中移除目标版本，并只为已经不被其他版本引用的 canonical Storage 路径写入既有 cleanup outbox。本机原件也只会在新快照已持久化、且所有本机工作区都不再引用该键后删除。

当前版、其他历史版、资料名称、标签、知识库归属和 AI 权限保持不变。没有文字备注的高亮、已结束的导入/整理记录及 AI 生成的知识关系会随目标版本清理；带文字的批注、手工知识关系、排队或运行中的导入/整理任务是 blocker，必须先由用户处理。笔记和对话继续保留原文与版本绑定的引用；被清理版本会显示为不可用，绝不会用当前版本替代旧依据。

解析仅部分成功或没有正文时，原件仍可作为新版本保留，但必须先确认已了解新问答的覆盖限制。`partial` 表示文字或结构解析存在真实缺口，部分解析只提供已提取内容，不保证未可靠解析的结构关系；无正文的新版本不能为新问答提供正文依据。扫描 PDF 当前没有 OCR。DOCX 保留提取原文，并解析段落、标题和基础表格；合并、嵌套、不规则或空单元格、超长完整行，以及结构与原文位置无法可靠对应时，保留文字并明确说明表格行列关系暂不保证。解析或提交失败可重新选择文件或重试；不会自动用失败预览覆盖当前资料。

取消、关闭面板、选择另一文件，或切换账号、目标资料、版本、名称及知识库归属后，迟到的解析结果会被丢弃。已提交的保存由协调器再次检查当前上下文；不能把旧账号或陈旧版本的候选写入新的上下文。

## 版本、引用与阅读

- 资料 `id` 保持不变；新内容使用新的 `versionId` 与片段标识，旧内容保存在 `Source.versions`，最近归档的版本在前。每版保留自己的格式、原文件名、文字、片段、采集范围、解析状态、真实缺页范围、时间和原件位置。
- 历史阅读根据该版自身格式选择阅读方式。例如当前版已改为 DOCX，旧 PDF 仍打开其 PDF 原件；不会使用当前版文件代替旧原件。
- 旧问答、笔记和标注的引用继续绑定准确的资料、版本与片段。双资料对照会话还保留左右两份资料的准确版本；比较请求把这两条资料版本身份一并发送，服务端只在云端当前版本、权限和可检索状态全部匹配时继续。再次打开时只有这两版仍可读取才进入对照，不跳到新版相似正文。版本不存在或引用无法核对时明确提示；永久删除任一侧后保留只读历史身份，但不能重新打开或继续提问。历史内容沿用当前资料的账号、归属及删除状态，不形成权限副本。
- 历史页面只读，禁止发起新 AI 问题、新增标注和回写当前版阅读进度；可以查看已有问答、定位旧引用、下载该版原件和另存独立摘录笔记。
- 新问答、摘要、知识整理与更新建议只使用当前资料版本。替换文件不自动改写已有问答、笔记或知识页。
- 选段、当前资料、“此资料 + 我的笔记”和显式指定资料问答都会把发送时的准确资料版本写入请求与回答尝试。重试只重放原版本范围；资料换版或旧尝试缺少版本锁时，用户需重新确认问题与范围，系统不会静默改用后来版本。

### DOCX 表格切块与旧版边界

新导入或替换文件预览中的基础矩形表格，在结构与原文顺序准确对应后，按完整行形成最多 1200 个字符的连续原文块，以 JavaScript 字符串长度计。长表按行分组；多段单元格保留真实段落分隔。每块带章节、表格序号、实际行范围、列数及有界的首行各列文字；首行元数据不是推断的表头，不把其他行或首行文字拼接进引用。例如“学习率／0.001”可以留在同一个检索证据中，而非拆成互不关联的名称和值。支持范围及降级行为见[搜索与语义索引](SEARCH_INDEXING.md)。

保存为新版本后，新片段使用新版本身份；旧版本原文、片段标识、定位与原件继续保留，已有引用仍指向原来的准确依据。打开旧版、从备份恢复、重建向量索引或直接“恢复为当前”不会重新解析或静默升级旧片段，也不会以新规则生成的相似片段替换旧引用。

当前“重新解析／重新处理”仅允许失败或已取消、原件可用且仍对应当前资料版本的导入任务，沿用该任务的 source/version 身份。已完成的旧任务没有通用重解析入口，资料为 `partial` 也不自动变为可重试任务。若已完成资料需采用新的表格规则，可明确重新导入为独立资料，或选择实际字节发生变化的文件保存为新版本；当前同 SHA-256 原件通常会被换版拒绝，不能把同一文件重新选择一遍当作重新切块操作。`originalMissing` 补回原件与明确重新选择历史内容的例外仍遵循前述确认流程。

## 保存与上传边界

`prepareFile` 只产生内存候选和待使用的原件标识。用户确认后，`WorkspaceCoordinator.replaceFile` 校验实际文件的大小、类型与 SHA-256，以 IndexedDB 的不可覆盖写入保存原件，再回读核验。最后复核预期版本并一次性替换工作区中的资料状态；超过容量、身份变化或原件未确认保存时不发布新版本。

这里的版本发布保护不是原件、工作区持久化与云端保存的跨服务事务。原件回读后会再次检查账号及其他标签页的新提交；只有替换元数据和当前同步信息已经写入 IndexedDB，保存 Promise 才会成功，界面才显示已创建新版本。这个成功只代表本机已持久化，不代表云端已经确认。

若本机工作区写入失败，保存 Promise 会拒绝，页面保留已经采用的替换元数据及原件，并显示可重试或导出的保存错误；不会显示成功后让用户误以为可以安全关闭页面。发布前失败时，只尝试清理本次创建且确认没有被引用的暂存原件；无法证明可安全删除的原件会保留并提示。

账号上传队列遍历每份资料的当前版本和所有保留历史版本，为尚无 `storagePath` 的原件逐个上传。上传完成后按准确的版本与原件身份回填路径；上传期间当前版变成历史版，也不会将结果绑到另一份内容。队列保存确认路径后重新遍历最新版本链，再提交云端工作区。Storage 对象不可覆盖；真实 Supabase、跨设备并发、断网恢复及真实模型服务仍未完成联调。

从 ZIP 恢复时，缺失原件的当前或历史版本保存 `originalMissing: true`，同时移除不可用的 `blobKey` 和 `storagePath`；已有文字和引用仍可保留，这些明确缺失的版本不会阻塞其他完整原件上传。阅读器和再次导出继续标明缺失。普通文件仍带原件句柄却无法读取、身份不符或上传失败时，保存队列会报错，不把异常当作允许缺失。新增副本恢复的完整流程见[备份恢复](BACKUP_RESTORE.md)。

## 导出与限制

ZIP 导出包含当前与全部保留历史版本，包括没有被引用的版本。每版独立保存元数据、解析文字、片段和可取得的原件；不同格式保留各自文件名与字节。原件不可取得时写缺失说明，云端下载异常会明确终止导出，不用当前版补齐旧版。具体路径与引用字段见[导出格式](EXPORT_FORMAT.md)。

| 限制         | 当前行为                                                                                                                                                                                                                                                         |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件大小     | 浏览器导入及替换单文件最多 30 MiB；不是云端底层桶容量                                                                                                                                                                                                            |
| 批量导入     | 每批最多 20 个文件、合计 150 MiB；选择或拖放时逐项显示拒绝原因，接受的文件顺序保存                                                                                                                                                                               |
| 本机原件额度 | 当前版、保留历史版和回收站中仍有原件的资料共用 512 MiB；界面先预检格式、单文件和批量条件，空间不足时在计算哈希后判断是否可关联已有原件，当前页面实际保存前再严格核对。跨标签页或独立工作区实例的并发额度与合并仍待验证。这是浏览器端保护，不代表未来云端套餐容量 |
| 版本数量     | 每份资料最多 200 个历史版本，另有当前版本；达到上限拒绝新增，不自动删旧版                                                                                                                                                                                        |
| 工作区大小   | 当前和历史的正文、片段、笔记、对话及整理结果等共用 3 MiB 快照上限；原件字节单独存储                                                                                                                                                                              |
| 处理方式     | 仍由浏览器执行解析，没有持久后台解析或 OCR                                                                                                                                                                                                                       |
| 清理与恢复   | ZIP 可恢复为新增副本；历史版可在确认后直接恢复为当前版，或经服务端影响预览、输入“清理”确认后单独清理。账号注销会清理同账号当前与恢复副本及其独占原件缓存；Storage/Auth/Cron 与浏览器矩阵仍待联调。                                                               |

3 MiB 的本地预检查按紧凑 JSON 的 UTF-8 字节计算；数据库按 JSONB 文本大小校验，实际大小可能更高。应以工作台最终保存状态确认持久化结果。容量、同步和真实环境边界见[云端配置](CLOUD_SETUP.md)与[开发状态](IMPLEMENTATION_STATUS.md)。

DOCX 表格变更已通过 6 个定向测试文件、149 项本地回归，以及 TypeScript、定向 ESLint 和格式检查。新增内存 DOCX 样本使用真实 Mammoth 浏览器解析器，验证基础行列、多段单元格、长表容量与降级说明，并核对解析、检索、模型上下文及换版后的引用身份；149 项包含相关既有测试，不代表 149 次 DOCX 解析。测试没有调用真实生成模型或写入真实 Supabase，不构成模型回答质量、跨设备同步或云端验收。
