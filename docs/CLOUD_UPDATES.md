# Conuo 前台云端更新

更新日期：2026-09-20。本文记录已实现的 Web 前台版本检查与安全采用流程。本轮复用现有工作区 revision、会话内存适配器和冲突处理协议，没有新增 Realtime 订阅。独立 staging 已完成同一主机 Chrome／Edge 的真实页面同步矩阵；两台物理设备与 PRD NFR-05 仍待完整验收。

## 检查时机与接口

登录账号的工作区就绪后，页面可见且浏览器未报告离线时立即检查。每次检查结束后等待 **4 秒**再检查一次，同一会话最多一个检查在途；这不是固定每 4 秒发起请求，也不保证更新在 4 秒内显示。恢复可见、重新聚焦、回到在线或 `pageshow` 时可立即检查；隐藏、离线、`pagehide` 和卸载会停止计时并取消在途检查。浏览器的在线标志不证明服务器一定可达。

单次检查设 **12 秒取消预算**，超时显示可重试的检查错误。取消信号贯穿版本检查与完整快照读取；已经开始的本机持久化不能由网络取消信号撤销，因此 12 秒不是本机写入的硬期限。迟到结果仍需通过当前会话和编辑边界复核。

| 接口                             | 内容与语义                                                                                                                      |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/workspace/revision` | 只读取已认证账号的 revision，不返回正文，不创建工作区。`revision: 0` 仅表示没有工作区记录，不代表已经保存到云端或确认账号已注销 |
| `GET /api/v1/workspace`          | 在需要载入已发现的新版本时读取完整快照；校验工作区 schema 和原件归属。无记录返回 `data: null, revision: 0`                      |

两个 GET 均复核 Cookie 会话、`X-Conuo-User` 与账号注销访问栅栏，只查询该账号的记录，并使用 RLS、动态响应和 `private, no-store` 缓存策略。客户端拒绝无效 revision、格式不兼容或其他账号原件身份；载入时还要求完整快照至少达到已发现的新 revision，不以旧快照或空工作区替换当前内容。

## 自动采用与显式复核

轻量检查发现更高 revision 后，先保留更新提示。只有本机与最后确认的云端快照一致、没有待保存修改、冲突或进行中的操作时，才自动读取完整快照。同步、导入、整理、问答、文件替换、备份恢复、删除、跨标签页更新和待保存阅读位置等会阻止采用；发现版本不等于已经载入。

完整读取前记录工作区内容、云端基线、本机 revision 和保存队列，读取后再次核对。候选先以当前本机 revision 执行 IndexedDB **CAS**（比较版本后保存）；只有保存成功、会话及输入边界仍有效时，才更新界面、云端基线和采用序号。干净快照的采用不会再上传一遍相同数据。本机保存失败时保留当前页面内容和更新提示，显示检查错误，不把未采用候选显示为成功。

有未同步修改时，自动检查只提示更新。用户点击“检查并载入更新”后重新读取并使用既有共同基线复核：可确认互不冲突的对象修改或阅读进度沿用已有安全重基规则；重基结果先在本机耐久保存，仍有本机修改时继续按既有 revision 协议上传。同一内容冲突或缺少可信共同基线时，保留本机副本和云端恢复候选，进入已有冲突处理，不通过“载入”直接覆盖。仍有操作在途时，显式载入也会提示等待。

## 输入、阅读位置与身份保护

普通编辑输入在候选 CAS 期间继续可用。读取途中出现新输入时丢弃迟到候选；候选已经写入本机但输入边界随后变化时，不发布候选，而是按保存栅栏耐久写回最新本机输入及其原云端基线。后续输入的保存排在修复之后，不能被旧编辑快照或旧基线覆盖。修复失败保留内存输入，并明确提示本机尚未保存、需要重试或导出。

Reader 会把尚未落入工作区的暂存滚动位置报告为 pending，单资料和对照两侧分别隔离；任一 pending 会阻止自动及显式采用。保存、清除或对应 Reader 卸载后才解除该保护。只有本机 CAS 成功且候选被实际采用时，`cloudAdoptionSequence` 才递增；Workspace 将此信号传给仍挂载的 Reader，重放对应资料版本的 PDF 页码或文字滚动位置，避免每次普通进度保存都跳动。失败、迟到、取消或冲突候选不触发该序号。

账号切换、退出和账号注销会取消旧会话检查；采用和修复再次核对 token、活动会话及删除状态。账号注销的本机清理会等待已开始的写入，并阻止后续修复重建已丢弃的工作区。其他标签页的新本机 revision 会阻止采用；CAS 冲突时回读最新本机 revision，提示处理该标签页更新，不覆盖它已经保存的数据。上述保护不构成原件、浏览器缓存与云端之间的跨服务事务。

## 验证与验收边界

本地自动测试覆盖前台串行轮询、暂停与取消、轻量接口账号范围、响应校验、干净采用、脏数据显式复核、安全重基、输入在读取/CAS/修复期间变化、Reader pending、跨账号及本机 CAS 冲突、账号清理和错误提示。测试使用受控网络与本机存储；最终测试及构建结果以[开发状态](IMPLEMENTATION_STATUS.md)的统一记录为准。这里不将本地测试写成真实 Supabase 或双设备验收。

2026-09-20 在已部署 staging 上使用同一主机的独立 Chrome／Edge 进程完成真实页面验收：相同 revision 同时保存得到 200／409；断网编辑在当前页面保留，重连后保存并刷新恢复；服务端已提交但响应被截断时通过权威回读确认，没有重复提交；旧端离线改名不能推翻另一端的资料删除；笔记同时编辑可手工合并并保留双方历史。另用自编长 TXT 让两个进程同时移动阅读位置，失败端进入专用选择流程，选择后云端保存成功，落选位置可从“已保留阅读位置”切换，原当前位置仍保留。这些结果证明部署实例和真实浏览器流程，但同主机网络、时钟和系统生命周期不能替代两台物理设备。

PRD **NFR-05：普通对象跨端可见 P95 ≤ 5 秒**的前提是双端前台在线且已经完成服务端保存，不包括大文件上传或受系统限制的后台执行。4 秒间隔还叠加请求、校验、本机保存与渲染时间；当前没有真实 P95 数据，不能据此宣称满足 5 秒要求。

真实双设备验收至少需覆盖以下矩阵，并记录服务端保存确认到另一端实际采用的时间、数据及阅读位置：

| 场景                       | 需要核对的结果                                                                                            |
| -------------------------- | --------------------------------------------------------------------------------------------------------- |
| 同账号、双端前台在线       | 普通对象与 PDF/文字阅读位置可见；干净端自动采用，往返修改及 P95 样本覆盖真实网络和设备                    |
| 接收端编辑或任务在途       | 提示更新并保留输入；独立对象安全重基，同一对象进入冲突；覆盖读取、CAS、修复期间继续输入及对照两侧 pending |
| 隐藏、离线、重新连接       | 暂停及恢复符合实际浏览器生命周期，超时或网络失败不伪装为保存/载入成功                                     |
| 两标签页与两设备同时保存   | 真实 IndexedDB CAS、云端 revision 冲突与读取后再次变更均保留准确副本                                      |
| 切账号、注销或删除期间迟到 | 不混入其他账号、不重建已清理工作区；服务端注销访问栅栏与本机清理失败状态准确                              |
| 原件与历史、容量和格式异常 | 不混绑原件或历史身份；兼容性及容量失败保留本机内容，确认大文件上传不被误计为普通对象同步时间              |

当前没有后台持续同步或推送订阅；前台仍通过有界轮询检查云端 revision。同主机 Chrome／Edge 矩阵已完成云端写入，完整物理设备矩阵、真实网络切换及 P95 样本仍属后续范围。
